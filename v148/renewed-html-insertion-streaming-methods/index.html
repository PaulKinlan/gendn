v148 · html / dom · developer trial (shipped in Chrome 157)

Renewed HTML insertion & streaming methods

A coherent set of new DOM methods for inserting HTML into an existing document, introduced in developer trial in Chrome 148 and enabled by default in Chrome 157 (with a revised method surface). Adds positional HTML insertion methods replacing insertAdjacentHTML, plus streaming HTML methods for progressive server-sent markup.

Limited availability — graduated and shipped enabled by default in Chrome 157 and Edge 157 with a revised API surface; Firefox and Safari have not shipped

  • Chrome · 148 trial; 157 shipped (2026-11-03)
  • Edge · 157 shipped (2026-11-05)
  • Firefox · Not supported (Positive #1370)
  • Safari · Not supported (No signal #629)

For the settled Chrome 157 shipping reference, see /v157/renewed-html-insertion-streaming-methods/.

Shipped in Chrome 157 (formerly developer trial in Chrome 148)

This API was in developer trial behind a flag in Chrome 148 and shipped enabled by default in Chrome 157 on desktop, Android, and WebView (ChromeStatus 5054329641893888; blink-dev Intent to Ship). Enabling chrome://flags/#enable-experimental-web-platform-features is only needed before Chrome 157. Note: the shipped Chrome 157 API surface changed from the Chrome 148 trial method names documented below — positional methods shipped as appendHTML, prependHTML, beforeHTML, afterHTML, and replaceWithHTML (plus *Unsafe variants), and streaming methods shipped as streamHTML, streamAppendHTML, streamPrependHTML, streamBeforeHTML, streamAfterHTML, and streamReplaceWithHTML (plus *Unsafe variants) returning a WritableStream rather than taking a ReadableStream argument, alongside runScripts in SetHTMLUnsafeOptions and Trusted Types createParserOptions (WICG explainer §Resulting API; Chromium element.idl; MDN BCD api/Element.json). Read the full shipped Chrome 157 reference at Chrome 157: Renewed HTML insertion&streaming methods.

why it exists

insertAdjacentHTML was designed in the IE era and has a string-enum position argument ("beforebegin", "afterend", etc.) that is error-prone and verbose. innerHTML replaces content but doesn’t provide relative insertion. Neither accepts streams. This feature replaces both with ergonomic methods that follow the naming of the existing Element manipulation API and adds streaming variants for progressive server-rendered HTML.

Source: chromestatus summary; WICG explainer.

positional insertion methods

These Chrome 148 trial methods mirror the existing Node manipulation API but accept HTML strings instead of Node objects. Each parses the string in the context of the element’s owner document (for the settled Chrome 157 names appendHTML/prependHTML/beforeHTML/afterHTML/replaceWithHTML and *Unsafe variants, see /v157/renewed-html-insertion-streaming-methods/).

Historical Chrome 148 trial positional HTML insertion method names and legacy equivalents
Method (v148 trial)Behavior and legacy equivalent
el.setHTMLBefore(html)Inserts parsed HTML immediately before el in its parent. Replaces insertAdjacentHTML("beforebegin", html).
el.setHTMLAfter(html)Inserts parsed HTML immediately after el. Replaces insertAdjacentHTML("afterend", html).
el.setHTMLFirst(html)Inserts parsed HTML as the first child. Replaces insertAdjacentHTML("afterbegin", html).
el.setHTMLLast(html)Inserts parsed HTML as the last child. Replaces insertAdjacentHTML("beforeend", html).
el.setHTMLReplacing(html)Replaces el itself with parsed HTML nodes. Replaces outerHTML = html.
Source: WICG explainer §Resulting API; WHATWG HTML issue #11669. Names paraphrased for the v148 trial; see the shipped Chrome 157 API at /v157/renewed-html-insertion-streaming-methods/.

streaming methods

Streaming variants in the Chrome 148 trial accepted a ReadableStream of HTML chunks and parsed them progressively into the document, enabling low-latency rendering of server-streamed responses without JavaScript orchestration beyond kicking off the stream. In Chrome 157, the shipped streaming API settled on returning a WritableStream (streamHTML, streamAppendHTML, streamPrependHTML, streamBeforeHTML, streamAfterHTML, streamReplaceWithHTML and *Unsafe variants; see /v157/renewed-html-insertion-streaming-methods/).

Historical Chrome 148 trial streaming HTML insertion method names (superseded by Chrome 157 WritableStream API)
Method (v148 trial)Behavior and contract note
el.streamHTMLBefore(stream)Streams HTML before el. The return contract was unsettled in the explainer (promise vs WritableStream) — Chrome 157 settled on returning a WritableStream.
el.streamHTMLAfter(stream)Streams HTML after el.
el.streamHTMLFirst(stream)Streams HTML as first children.
el.streamHTMLLast(stream)Streams HTML as last children.
el.streamHTMLReplacing(stream)Streams HTML to replace el itself.

Error paths: the explainer does not yet define when or how these methods raise errors — its security-and-privacy questionnaire answers “It will.” One open question is whether positional insertion on an element with no parent should throw a hierarchy exception or fail silently the way before()/after() do. Until error behaviour is specified, verify it in the browser before shipping (or consult the shipped Chrome 157 error contract).

Source: WICG explainer §Resulting API; WHATWG HTML issue #11669, May 2026.

example

Historical Chrome 148 trial examples for positional HTML insertion and streaming server-sent HTML chunks into an element (for runnable Chrome 157 shipping examples using appendHTML() and streamAppendHTML(), see /v157/renewed-html-insertion-streaming-methods/#examples):

// Old
container.insertAdjacentHTML("beforeend", "<li>New item</li>");

// New (v148 trial naming)
container.setHTMLLast("<li>New item</li>");

Stream a fetch response into the page

const res = await fetch("/partial/comments");
const stream = res.body.pipeThrough(new TextDecoderStream());

// Stream comment HTML into #comments-container without JS parsing.
// Bare call: the return contract was unsettled (promise vs WritableStream) in the v148
// trial - do not rely on awaiting it; see /v157/renewed-html-insertion-streaming-methods/
// for the shipped Chrome 157 WritableStream contract.
document.getElementById("comments-container").streamHTMLLast(stream);

The full positional and streaming set

// Positional variants (string HTML, v148 trial naming)
item.setHTMLBefore('<li>before</li>');
item.setHTMLAfter('<li>after</li>');
list.setHTMLFirst('<li>first</li>');
item.setHTMLReplacing('<section>replaced</section>');

// Streaming variants accepted a ReadableStream of HTML chunks in the v148 trial.
// Their return contract was unsettled in the explainer (promise vs WritableStream),
// so the calls are shown bare - see Chrome 157 for the shipped WritableStream API.
item.streamHTMLBefore(beforeStream);
item.streamHTMLAfter(afterStream);
list.streamHTMLFirst(firstStream);
item.streamHTMLReplacing(replaceStream);
