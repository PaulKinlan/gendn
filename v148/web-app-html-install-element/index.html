Web app HTML install element

A new <install> HTML element — introduced in origin trial in Chrome 148–153 and shipped enabled by default on desktop in Chrome 158 — that lets a page declaratively offer PWA installation for the current origin or a different one without orchestrating the beforeinstallprompt ceremony in JavaScript. The button’s label and appearance are browser-controlled, so the click carries a genuine user-intent signal.

Limited availability — Desktop Chromium only (Chrome 158 / Edge 158; Firefox no signal, Safari opposed); not yet documented on MDN (checked 2026-11-27)

  • Chrome · 148–153 OT; 158 default (desktop)
  • Edge · 148–153 OT; 158 default (desktop)
  • Firefox · Not supported (No signal #1179)
  • Safari · Not supported (Oppose #463)

For the updated shipped Chrome 158 surface, see the Chrome 158 HTML install element reference.

Shipped on desktop in Chrome 158 (formerly origin trial in Chrome 148–153)

The <install> element was in origin trial on desktop from Chrome 148 through 153 (and testable locally via about://flags/#web-app-install-element) and shipped enabled by default on desktop in Chrome 158 (ChromeStatus 5152834368700416; blink-dev Intent to Ship). ChromeStatus records no Android or WebView milestone for this feature. The origin trial token and flag steps below are only needed before Chrome 158. Note: the shipped Chrome 158 API surface changed from the Chrome 148 origin-trial surface documented below — installurl was replaced by manifest, validation uses isValid, invalidReason, and validationstatuschange (replacing validity and validationstatuschanged), and promptaction/promptdismiss were removed in favor of installresult in the specification (WICG Install Element spec; Chromium html_install_element.idl). See the current Chrome 158 HTML install element reference for the shipped contract.

why it exists

The existing beforeinstallprompt pattern requires JavaScript to intercept and store an event, then replay it on a button click — around 20+ lines of boilerplate. Worse, it only works for the same origin. App stores and catalog pages that want to offer cross-origin installs had no standard mechanism at all. The <install> element provides a single declarative element: the browser renders it as an install button, trusts the click, and handles the installation flow natively. Cross-origin installs are supported via the installurl attribute in the Chrome 148 origin trial (renamed to manifest in Chrome 158), enabling catalog pages to offer many apps each with its own install button.

Source: Chrome for Developers blog — Install web apps with the new HTML install element; WICG install-element explainer.

shape of the API

In the Chrome 148–153 origin trial, the <install> element is declared in HTML with optional installurl and manifestid attributes (see the Chrome 158 migration table for the shipped manifest / installresult surface):

<install installurl="https://app.example/" manifestid="https://app.example/id"></install>

Attributes

Chrome 148 origin-trial HTML attributes on the <install> element
AttributeRequiredDescription
installurl No (required for cross-origin) URL of the web app to install. For same-origin apps whose manifest has an id field, you can omit this — the browser infers the target from the current page’s manifest.
manifestid No Computed manifest ID string. Use this when the target app’s manifest does not have an explicit id field, so the browser can uniquely identify the app to install.

Events

Chrome 148 origin-trial DOM events dispatched on <install>
EventFires when
promptactionThe user accepted the installation prompt — the app was installed (or is being installed).
promptdismissThe user dismissed the installation prompt without installing.
validationstatuschangedThe element’s validation status changed — e.g. the target URL resolved (or failed to resolve) to an installable manifest.
Source: WICG Install Element specification; Chrome for Developers guide; Chromium issue 454827186.

recipes

Declarative install button syntax example (Chrome 148 origin-trial shape):

<install installurl="https://awesome-app.example/"></install>

Same-origin install button

If your page is served from the same origin as the PWA manifest and the manifest has an id field, a bare element is sufficient:

<install></install>

Cross-origin install button (app catalog)

<!-- Catalog page at catalog.example.com offering another app -->
<install installurl="https://awesome-app.example/"></install>

<!-- App without a manifest id field — provide the computed id -->
<install
  installurl="https://awesome-app.example/"
  manifestid="https://awesome-app.example/?source=pwa"
></install>

Reacting to install outcome

const installBtn = document.querySelector('install');

installBtn.addEventListener('promptaction', () => {
  console.log('App installed!');
  installBtn.hidden = true; // hide after successful install
});

installBtn.addEventListener('promptdismiss', () => {
  console.log('User dismissed the install prompt.');
});

installBtn.addEventListener('validationstatuschanged', (e) => {
  // e.g. target manifest failed to load
  if (!installBtn.validity?.valid) {
    console.warn('Install element validation error');
  }
});

Enabling the origin trial

<!-- Add your origin trial token in the <head> -->
<meta http-equiv="origin-trial" content="YOUR_TOKEN_HERE">

Obtain a token at developer.chrome.com/origintrials — search for “Web app HTML install element”.
