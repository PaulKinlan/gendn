Web Authentication Immediate UI mode

A new uiMode: "immediate" option for navigator.credentials.get() that shows a sign-in dialog instantly when the user clicks a button — if the browser has a passkey or saved password for the site. If no credential exists, the call rejects with NotAllowedError rather than showing an empty or confusing UI.

Limited availability — Chromium-only (Chrome 148); Safari negative, Firefox no signal; not yet documented on MDN (checked 2026-11-27)

  • Chrome · 148 (Finch: WebAuthenticationImmediateGet)
  • Edge · Planned / Chromium-aligned
  • Firefox · No signal (#1239)
  • Safari · Negative (#504)

While the parent webauthn web-feature is Baseline Widely available, immediate UI mode (uiMode: "immediate" and immediateGet) is Chromium-only (ChromeStatus API 5164322780872704 lists milestone 148 on desktop, Android, and WebView with summary status still Proposed). Live MDN check on 2026-11-27: MDN CredentialsContainer.get() (HTTP 200) and MDN PublicKeyCredential.getClientCapabilities() (HTTP 200) do not yet document uiMode: "immediate" or immediateGet, and MDN BCD carries no subfeature entry for it yet.

why it exists

The existing mediation: "conditional" flow shows passkey suggestions in the browser’s native autofill UI — good for sign-in forms with a username field. But some flows (single-button sign-in, checkout, re-authentication) have no username field; they just need an immediate credential picker. uiMode: "immediate" triggers that picker directly on a user gesture, succeeds only when a credential exists, and fails fast when none does — so the site can fall back to a registration flow without showing a confusing empty dialog.

Source: ChromeStatus feature motivation; WebAuthn immediate mediation explainer; W3C WebAuthn issue #2228.

shape of the API

A single new option on the existing navigator.credentials.get() call (defined on CredentialRequestOptions in Credential Management Level 1):

Immediate UI mode option on CredentialRequestOptions for navigator.credentials.get()
OptionTypeDescription
uiMode "default" | "immediate" "immediate" — show the credential picker immediately on a user gesture. Rejects with NotAllowedError if no credential is available (or TypeError if the credential type does not support immediate mediation). "default" (or omitted) preserves existing behaviour.

Capability detection

Before using immediate mode, check that the browser supports it:

const caps = await PublicKeyCredential.getClientCapabilities();
if (caps.immediateGet) {
  // Safe to use uiMode: 'immediate'
}
Source: W3C Credential Management Level 1; W3C Web Authentication Level 3; WebAuthn PR #2291; Chromium issue 408002783.

example

Immediate UI mode credential request invocation:

const cred = await navigator.credentials.get({ uiMode: 'immediate' });

One-click sign-in with passkey

signInBtn.addEventListener('click', async () => {
  const caps = await PublicKeyCredential.getClientCapabilities();
  if (!caps?.immediateGet) {
    // Fall back to conditional UI or form-based flow
    return startConditionalUI();
  }

  try {
    const credential = await navigator.credentials.get({
      uiMode: 'immediate',
      publicKey: {
        challenge: await fetchChallengeFromServer(),
        rpId: location.hostname,
        userVerification: 'required'
      }
    });
    // credential is a PublicKeyCredential; send to server to verify
    await verifyOnServer(credential);
  } catch (err) {
    if (err.name === 'NotAllowedError') {
      // No passkey available — offer registration
      startRegistrationFlow();
    } else {
      throw err;
    }
  }
});

Password credential support

const credential = await navigator.credentials.get({
  uiMode: 'immediate',
  password: true  // also accept saved passwords
});
