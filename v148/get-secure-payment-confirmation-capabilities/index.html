Get Secure Payment Confirmation Capabilities

Chrome 148 adds a static PaymentRequest.getSecurePaymentConfirmationCapabilities() method that returns a record of Boolean flags indicating which Secure Payment Confirmation (SPC) capabilities the current browser supports — such as hardware-backed browser-bound keys (browserBoundKeyHardware).

Limited availability — Chromium-only (Chrome 148 / Edge 148 on macOS, Windows, and Android); MDN now publishes full canonical documentation (checked 2026-11-27)

why it exists

Secure Payment Confirmation (SPC) lets merchants authenticate users via WebAuthn during a payment flow. SPC supports advanced features like browser-bound keys (hardware-backed credentials tied to the device). Before Chrome 148, there was no way for a site to programmatically check whether the browser and OS combination supported a particular SPC capability — a merchant might attempt to use browser-bound keys on a platform that doesn't support them and receive an opaque error. getSecurePaymentConfirmationCapabilities() provides a capability-detection step so merchants can branch their payment flow appropriately.

Source: blink-dev Intent to Ship: Get Secure Payment Confirmation Capabilities; W3C SPC specification §capabilities, April 2026.

shape of the API

Static method on PaymentRequest (secure contexts only, taking no arguments) returning a Promise that resolves to a SecurePaymentConfirmationCapabilities record (record<DOMString, boolean>) with keys sorted in ascending lexicographical order:

// Static method signature
const caps = await PaymentRequest.getSecurePaymentConfirmationCapabilities();

The resolved object maps capability identifiers from the SecurePaymentConfirmationCapability enum to Booleans (true if currently supported, false otherwise). The currently defined key in W3C SPC §4.7 and Chromium is browserBoundKeyHardware, indicating whether hardware-backed browser-bound keys are supported on the device.

The returned promise rejects with a NotAllowedError DOMException if the payment Permissions Policy is disabled in the current document, or NotSupportedError if Secure Payment Confirmation capabilities are disabled (Chromium payment_request.cc). The method is only available on platforms that support Secure Payment Confirmation: Android, macOS, and Windows. On other platforms (Linux, ChromeOS), the method is not present.

Source: blink-dev Intent to Ship; W3C Secure Payment Confirmation §4.7; Chromium payment_request.cc; Intent to Prototype (re-verified 2026-11-27).

examples

Feature-detect the method and check for hardware-backed browser-bound key support (browserBoundKeyHardware) before initiating payment:

if ('getSecurePaymentConfirmationCapabilities' in PaymentRequest) {
  const caps = await PaymentRequest.getSecurePaymentConfirmationCapabilities();
  if (caps.browserBoundKeyHardware) {
    // Browser supports hardware-backed browser-bound keys in SPC
    initiateSecurePaymentWithBoundKeys();
  } else {
    // Fall back to standard SPC or non-SPC payment flow
    initiateStandardPayment();
  }
}
Source: W3C SPC §4.7; MDN: PaymentRequest.getSecurePaymentConfirmationCapabilities().
