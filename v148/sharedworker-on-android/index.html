Chrome 148 on Android was the last core browser to ship shared workers, which is what made the feature Baseline. Status from webstatus.dev shared-workers (baseline.status: newly, low_date: 2026-05-05; queried 2026-11-15). See the full table.

SharedWorker — long available on desktop — now ships on Android in Chrome 148. Shared workers allow multiple browsing contexts (tabs, iframes, workers) in the same origin to share a single background worker instance and communicate through its port interface. Ships in Chrome 148 on Android and WebView.

this API is documented on MDN

Constructor shape (unchanged by this release; Chrome 148 enables it on Android and WebView):

const worker = new SharedWorker("/workers/shared.js", { name: "shared-1" });
worker.port.start();
worker.port.postMessage("ping");
worker.port.addEventListener("message", (e) => console.log(e.data));
Source: HTML spec §Shared workers (SharedWorker(url, options), options.name, port), May 2026.

Formal syntax (Web IDL)

Verbatim from the HTML Standard. Chrome 148 does not change this interface; it turns it on for Android and WebView.

[Exposed=Window]
interface SharedWorker : EventTarget {
  constructor((TrustedScriptURL or USVString) scriptURL, optional (DOMString or SharedWorkerOptions) options = {});

  readonly attribute MessagePort port;
};
SharedWorker includes AbstractWorker;

dictionary SharedWorkerOptions : WorkerOptions {
  boolean extendedLifetime = false;
};

Passing a string as options is shorthand for { name: string }. WorkerOptions adds name (default ""), type ("classic" or "module") and credentials; AbstractWorker adds the onerror handler. extendedLifetime is a separate Chrome 148 feature, documented at Extended lifetime shared workers. Per-option support on Android is in the compatibility table.

Source: HTML Standard §10.2.6.4 Shared workers and the SharedWorker interface and §Dedicated workers (WorkerOptions), fetched 2026-11-15. SharedWorker — Web APIs | MDN Web Docs

MDN's SharedWorker page covers the full API. Chrome 148 browser-compat data for Android will be reflected once MDN is updated.

why it was disabled on Android

SharedWorkers were removed from Android in Chrome 40 (around 2015) due to memory and stability concerns on mobile hardware of that era. As Android devices have improved significantly, the Chromium team re-evaluated and ran an origin trial (Chrome 145–147) to validate stability before shipping to all Android users in Chrome 148.

Source: blink-dev Intent to Ship (Chrome 148); Intent to Experiment.

basic usage

// main.js (multiple tabs can connect to the same worker)
const worker = new SharedWorker('/shared-worker.js');
worker.port.start();

worker.port.addEventListener('message', (e) => {
  console.log('From shared worker:', e.data);
});

worker.port.postMessage({ type: 'hello', from: location.href });

// shared-worker.js
const ports = new Set();

self.addEventListener('connect', (e) => {
  const port = e.ports[0];
  ports.add(port);
  port.start();

  port.addEventListener('message', (e) => {
    // Broadcast to all connected tabs
    for (const p of ports) {
      p.postMessage({ echo: e.data });
    }
  });
});
