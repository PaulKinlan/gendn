Permissions Policy: focus-without-user-activation

Chrome 151 introduces a focus-without-user-activation Permissions Policy feature that lets embedders control whether embedded iframes can programmatically move focus without a prior user activation. When denied, calls to element.focus(), autofocus, dialog.showModal(), and popover focusing are blocked unless the user has interacted first.

Limited availability — Chromium-only; Firefox has no signal and Safari has signaled support without shipping

  • Chrome · 151 (filed here; ChromeStatus & BCD track ship at 158)
  • Edge · Mirrors Chromium
  • Firefox · Not supported (No signal)
  • Safari · Not supported (Support signal)

No dedicated web-features entry exists on webstatus.dev for focus-without-user-activation (the parent permissions-policy feature is Limited availability; checked 2026-11-27). BCD http/headers/Permissions-Policy.json records Chrome 158 (mirroring Edge, Chrome Android, and WebView) with a note that Chromium’s default allowlist is * rather than the spec’s 'self' (Chromium bug 587978069), and Firefox/Safari false. MDN has no reference page or entry for focus-without-user-activation yet (live MDN checked 2026-11-27: /Permissions-Policy/focus-without-user-activation returns HTTP 404 and the Permissions-Policy header page omits the directive).

why it exists

Embedded third-party iframes can steal focus from the embedding page by calling element.focus() or triggering an autofocus attribute without any user interaction. This is disruptive in embed-heavy layouts (dashboards, ad slots, widget galleries) where unexpected focus shifts break keyboard navigation and screen-reader context.

The focus-without-user-activation policy gives the embedding page control: when the policy is denied for a frame, all programmatic focus calls inside that frame are silently ignored unless a user gesture has occurred first. User-initiated focus (clicking, tabbing) is never affected — the policy only blocks programmatic focus without a prior activation.

Focus delegation is still supported: a parent frame that currently has focus can transfer it programmatically to a child iframe even if the child has the policy denied.

Source: chromestatus feature summary; W3C Permissions Policy issue #273; focus-without-user-activation explainer.

shape of the API and controlled operations

Per WHATWG HTML PR #10672 and MDN Permissions Policy reference, the feature can be declared via HTTP header or the iframe allow attribute:

Permissions-Policy: focus-without-user-activation=()
Policy token, default allowlist, and delivery mechanisms for focus-without-user-activation
Policy featureDefault allowlistSet via
focus-without-user-activation* in Chromium (allowed everywhere by default; WHATWG HTML specifies 'self' — see Chromium bug 587978069)Permissions-Policy HTTP header or <iframe allow> attribute

Focus calls blocked when denied: element.focus(), autofocus attribute, window.focus(), dialog.showModal(), and popover auto-focusing. Blocked programmatic focus calls fail silently without throwing exceptions, preserving backward compatibility.

Never blocked: user-initiated focus (click, tab key, touch).

Source: WHATWG HTML §focus-without-user-activation-feature; chromestatus.com/feature/5179186249465856; Chromium bug 587978069.

examples

Denying programmatic focus for untrusted subframes while allowing focus delegation:

<!-- Deny programmatic focus for an embedded iframe -->
<iframe
  src="https://widget.example.com"
  allow="focus-without-user-activation 'none'"
></iframe>

<!-- Via HTTP response header (applies to all child frames) -->
<!-- Permissions-Policy: focus-without-user-activation=() -->

<!-- Focus delegation still works: parent transfers focus to iframe -->
<iframe id="child" src="https://widget.example.com"
        allow="focus-without-user-activation 'none'"></iframe>
<script>
  // This works — parent delegates focus to child
  document.getElementById('child').focus();
  // Inside the iframe, element.focus() is then allowed within the child's subtree
</script>
Source: chromestatus feature summary; focus-without-user-activation explainer.
