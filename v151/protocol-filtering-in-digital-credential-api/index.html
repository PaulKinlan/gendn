Protocol filtering in Digital Credential API

Limited availability

  • Chrome · developer trial 151 (behind a flag)
  • Edge · mirror (BCD)
  • Safari · 26 (BCD)
  • Firefox · not supported (BCD)

BCD covers the protocol surface (Chrome 141, Safari 26); the deprecation of unspecified protocols begins as a flag-gated developer trial in Chrome 151 with a removal target of Chrome 160. See the compatibility section for the separated facts.

Digital credential requests must now name their protocol: the protocol member is required, DigitalCredential.userAgentAllowsProtocol() lets a page check support before calling, and support for unspecified presentation and issuance protocols is being phased out — a developer trial in Chrome 151, with removal targeted for Chrome 160.

Developer trial — flag required

This feature is behind a flag in Chrome 151 (milestone listing: developer trial). Enable chrome://flags → Digital Credentials Protocol Filter (DigitalCredentialsProtocolFilter, status experimental) to try it. It is not enabled by default, and the feature detail targets the change for Chrome 160.

Source: chromestatus.com/feature/6492906882990080; Chromium runtime_enabled_features.json5

  • the protocol member and enumerations — required on requests, echoed on the credential, with the current protocol identifiers
Source: Digital Credentials — protocols

What changed and why it matters

Previously a request could leave the protocol unspecified and the browser would pick. That ambiguity is being removed: requests must name a protocol, and support for unspecified protocols is deprecated from Chrome 151 with removal targeted for Chrome 160. The migration is to declare the protocol explicitly and check it first — userAgentAllowsProtocol() returns false for unknown identifiers (it never throws for them), so it doubles as a progressive-enhancement gate as new protocol identifiers appear.

Source: ChromeStatus API feature record; Digital Credentials — protocols

Examples

// Gate on the interface first (undefined → ReferenceError otherwise),
// then on the protocol (unknown identifier → false, never throws):
if (typeof DigitalCredential !== "undefined"
    && DigitalCredential.userAgentAllowsProtocol("openid4vp-v1-signed")) {
  const cred = await navigator.credentials.get({
    digital: {
      requests: [{ protocol: "openid4vp-v1-signed", data: { /* … */ } }],
    },
  });
}
