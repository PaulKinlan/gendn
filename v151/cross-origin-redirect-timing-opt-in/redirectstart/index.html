PerformanceNavigationTiming.redirectStart

The timestamp at which the navigation's first redirect began. It returns 0 whenever the entry's redirect count is 0 — which includes cross-origin chains whose redirects did not all opt the destination origin in via Timing-Allow-Origin.

Syntax

// PerformanceNavigationTiming (normative IDL, Navigation Timing)
readonly attribute DOMHighResTimeStamp redirectStart;

// Read it from the navigation entry:
const t0 = performance.getEntriesByType("navigation")[0].redirectStart;
Source: Navigation Timing — PerformanceNavigationTiming

Inputs

A read-only attribute — no page inputs. Its value follows the entry's redirect count: the getter returns 0 when the redirect count is 0, so everything that gates redirectCount exposure (cross-origin opt-in via Timing-Allow-Origin, the no-referrer exclusion) gates this timestamp identically.

Source: Navigation Timing — redirectStart getter steps; whatwg/html PR #12513

Outputs

A DOMHighResTimeStamp in milliseconds, relative to the time origin. The getter steps: if the entry's redirect count is 0, return 0; otherwise return the stored redirect start time. Navigation Timing notes that unlike PerformanceResourceTiming, the navigation versions of redirectStart/redirectEnd return zero for navigations with (non-exposed) cross-origin redirects.

Source: Navigation Timing — redirectStart getter steps

Errors

No exceptions. As with redirectCount, 0 is ambiguous — it means “no redirects”, or “redirects not exposed” (a withheld cross-origin opt-in, or a no-referrer navigation). Do not subtract 0-valued fields: guard on redirectCount > 0 (or on the timestamp being non-zero) before computing chain duration.

Source: Navigation Timing — PerformanceNavigationTiming; whatwg/html PR #12513

Context

Receiver: the document's PerformanceNavigationTiming entry (the "navigation" entry in the performance timeline), in window contexts.

Availability: the cross-origin exposure is Chrome 151 per the milestone listing; runtime feature NavigationTimingRedirectTimingViaTAO (status stable at trunk). The attribute itself long predates the feature as part of Navigation Timing.

Source: Navigation Timing — PerformanceNavigationTiming; Chromium runtime_enabled_features.json5; chromestatus.com/feature/5078310347472896

Lifecycle

The timestamp is captured by fetch while the redirect chain runs and fixed when the navigation timing entry is created at document commit; it never changes afterwards. It marks the beginning of the chain — pair it with redirectEnd for total redirect time, and with fetchStart for the time from chain end to the final fetch.

Source: WHATWG HTML — navigation timing entry creation; Navigation Timing — PerformanceNavigationTiming

Examples

const [nav] = performance.getEntriesByType("navigation");
if (nav.redirectCount > 0) {
  const chainMs = nav.redirectEnd - nav.redirectStart;
  console.log(`${nav.redirectCount} redirect(s) cost ${chainMs.toFixed(1)} ms`);
  // redirectStart is non-zero here by construction (getter guarantees it).
} else {
  // redirectStart is 0: no redirects, or the chain was not exposed.
}

Security and privacy

The timestamp participates in the same consent boundary as redirectCount: cross-origin chain timing is disclosed only when every redirect operator opted the destination origin in, and never for no-referrer navigations with a non-null client. Timing of redirects can reveal infrastructure details (how many hops, how slow), which is why the default remains zero.
