Deprecate and stop firing events during subframe removal

Stops synchronously firing pagehide, visibilitychange (and prefixed webkitvisibilitychange), and unload inside a nested browsing context (<iframe>, <frame>, <object>, <embed>) when it is removed from the DOM and shares a scripting agent with the removing ancestor document. Aligns Chromium closer to the HTML Standard’s destroy a child navigable steps while eliminating synchronous ancestor DOM re-entrancy during node removal.

Limited availability — Developer trial behind a flag in Chrome 156+ (Finch experiment planned for Chrome 162–170; not yet enabled by default); Firefox and Safari still fire subframe removal events today

  • Chrome · Behind flag in Chrome 156+ (desktop, Android, WebView); Finch experiment / trial scheduled for Chrome 162–170 (not yet shipped enabled by default)
  • Edge · Mirrors Chromium flag (not enabled by default)
  • Firefox · No signal (currently fires subframe detachment events on DOM removal per whatwg/html#10194)
  • Safari · No signal (currently fires subframe detachment events on DOM removal per whatwg/html#10194)

No dedicated web-features entry or BCD sub-feature tracks subframe-removal omission yet (checked 2026-11-27 against webstatus.dev pagehide and BCD api/Window.json). MDN Window: pagehide covers the base event only and does not document Chromium’s same-agent DOM-removal omission. Status is tracked in ChromeStatus 5754395122860032.

Developer trial behind a CLI flag in Chrome 156+ (Finch trial planned for Chrome 162–170; not enabled by default): Launch Chromium with --enable-blink-features=OmitSubframeDetachmentEventsOnRemoval or --enable-features=OmitSubframeDetachmentEventsOnRemoval. Because OmitSubframeDetachmentEventsOnRemoval has status: "test" (not "experimental") in runtime_enabled_features.json5, chrome://flags/#enable-experimental-web-platform-features does not activate it and there is no dedicated chrome://flags toggle. Per ChromeStatus 5754395122860032, a Finch Beta / 1% Stable trial is scheduled for Chrome 162–170 (desktop, Android, Android WebView).

why it exists

When a parent document removes a same-agent <iframe> (or removes an ancestor container via remove(), removeChild(), innerHTML = "", or replaceChildren()), legacy browsers synchronously run the child frame’s pagehide, visibilitychange, and unload handlers mid-removal. Because a same-agent subframe holds direct synchronous access to window.parent and window.top, those handlers can re-enter the removing document’s DOM tree while node removal is half-finished—mutating sibling nodes, re-inserting elements, or triggering crashes and spec bugs. The HTML Standard already omits these events in destroy a child navigable; Chromium’s OmitSubframeDetachmentEventsOnRemoval flag removes synchronous dispatch for same-agent subframes while preserving cross-origin third-party telemetry handlers during the deprecation trial (reducing affected mobile root pages in the October 2026 compat study from ~1.21% to ~0.026%, with zero user-facing regressions).

Source: ChromeStatus 5754395122860032; whatwg/html#10194; compat impact study.

Affected surface

This change introduces no new WebIDL interfaces or methods; it alters the event-dispatch contract of existing DOM removal operations on nested browsing-context owners (<iframe>, <frame>, <object>, <embed>) governed by Blink’s ChildFrameDisconnector::ShouldFireUnloadEvents():

// Triggering ancestor DOM removals (ChildFrameDisconnector::kDisconnectSelf):
//   iframe.remove() | parent.removeChild(el) | parent.replaceChild(n, el)
//   container.innerHTML = "" | container.replaceChildren() | container.textContent = ""
//   range.deleteContents() | range.extractContents() | document.adoptNode(el)
//
// Subframe listeners NO LONGER fired synchronously when InSameAgent(child, removingDoc):
//   childWindow.addEventListener("pagehide", ...)
//   childDocument.addEventListener("visibilitychange", ...)
//   childDocument.addEventListener("webkitvisibilitychange", ...)
//   childWindow.addEventListener("unload", ...)   // (also gated by Permissions-Policy: unload)
//
// Migration replacements (explicit teardown / atomic move):
//   childWindow.postMessage({ type: "teardown" }, targetOrigin)  // before removal
//   newParent.moveBefore(iframe, refNode)                        // preserves navigable
//   new MutationObserver(cb).observe(container, { childList: true })

This reference covers all three parts of the behavioral change: omitted synchronous removal events (pagehide, visibilitychange / webkitvisibilitychange, unload), the InSameAgent scoping boundary (including opaque-origin sandboxes and cross-origin A1 → B → A2 sandwiches), and unaffected lifecycles & migration patterns (moveBefore(), explicit teardown handshake, and MutationObserver).

Source: Blink child_frame_disconnector.cc; WHATWG HTML Standard; compat impact study.

Omitted synchronous removal events (pagehide, visibilitychange, unload)

Inputs (triggers). Any DOM mutation in a removing document that disconnects a frame-owner element (<iframe>, <frame>, <object>, <embed>) or any ancestor containing one—including Element.remove(), Node.removeChild(), Node.replaceChild(), Element.replaceWith(), innerHTML / outerHTML / textContent assignment, replaceChildren(), Range.deleteContents(), Range.extractContents(), or reparenting via appendChild() / insertBefore() (non-atomic moves detach and reload the iframe).

Outputs. When OmitSubframeDetachmentEventsOnRemoval is active and the detaching child document shares an agent with the removing document, ChildFrameDisconnector::ShouldFireUnloadEvents() returns false: none of pagehide, visibilitychange, webkitvisibilitychange, or unload fire inside that subframe during DOM removal. Note that in Chrome 155+, unload is already disabled by default unless opted in via Permissions-Policy: unload, so pagehide and visibilitychange are the primary newly omitted events.

Source: Blink child_frame_disconnector.cc; ChromeStatus 5754395122860032; BCD api/Window.json (unload note).

Same-agent scoping boundary (InSameAgent)

Inputs & classification. While the HTML Standard omits these events for every removed child navigable, Chromium’s flag checks InSameAgent(document, disconnector->Root().GetDocument()) across the active stack of ChildFrameDisconnector instances with disconnect_reason_ == kDisconnectSelf. Using the agent boundary (similar-origin-window-agent) instead of SecurityOrigin::CanAccess() prevents a handler from widening access via document.domain.

Unaffected lifecycles & migration patterns (moveBefore(), explicit teardown, MutationObserver)

Inputs & unaffected paths. The omission applies only to DOM removal (kDisconnectSelf). The following lifecycles are unchanged:

  • Subframe navigation: Navigating a subframe (changing iframe.src or contentWindow.location) still fires pagehide and visibilitychange (and unload if permitted by policy) on the outgoing document.
  • Top-level navigation or tab close: Unloading the top-level document still dispatches lifecycle events down the frame tree normally.
  • Atomic DOM reparenting (moveBefore()): Moving a live <iframe> with parent.moveBefore(iframe, refNode) preserves the child navigable without detaching or unloading it at all.

Outputs (migration). Applications that previously relied on a same-origin iframe’s pagehide or visibilitychange handler to flush drafts, release locks, or report metrics before the host removes the iframe MUST migrate to an explicit parent-initiated teardown call (for example a synchronous helper method on iframe.contentWindow or a postMessage() handshake awaited before calling iframe.remove()), or observe frame removal asynchronously from the host via MutationObserver.

Source: WHATWG HTML Standard; compat impact study; ChromeStatus 5754395122860032.

Edge cases, non-omitted events, and breakage modes

  • Silent missed cleanup (no exception thrown): Removing a same-agent iframe never throws an error when pagehide / visibilitychange / unload is omitted; cleanup logic registered exclusively on those listeners simply does not execute unless migrated to an explicit postMessage() teardown handshake, host MutationObserver, or state-preserving moveBefore() reparenting.
  • Mid-flight Navigation API cancellations: Per the compat study, if an uncommitted navigation is in progress inside the subframe at the exact moment of removal, FrameLoader::StopAllLoaders can still synchronously fire abort and navigateerror on the subframe’s window.navigation.
  • Focus blur / focusout events: Omitting blur on element removal is tracked separately under Chromium’s OmitBlurEventOnElementRemoval runtime flag, not OmitSubframeDetachmentEventsOnRemoval.
  • Future expansion to all subframes: Do not build new dependencies on cross-origin subframe pagehide during DOM removal; Chrome’s trial notes explicitly evaluate expanding omission to all subframes to match the HTML Standard completely.
Source: compat impact study (Not covered); runtime_enabled_features.json5; ChromeStatus 5754395122860032.

Context, exposure, and feature detection

Applies to all HTML documents (HTTP and HTTPS, desktop, Android, and Android WebView) containing nested browsing contexts (<iframe>, <frame>, <object>, <embed>). There is no static JS property to probe whether OmitSubframeDetachmentEventsOnRemoval is active; instead, write teardown code that never depends on synchronous subframe removal events (explicit parent teardown + pagehide only as an idempotent fallback for real navigations/tab closes).

Source: Blink child_frame_disconnector.cc; ChromeStatus 5754395122860032.

Lifecycle and removal ordering

  1. Host DOM mutation begins: Script removes a frame owner or an ancestor subtree (e.g., container.replaceChildren() or iframe.remove()), entering ChildFrameDisconnector with kDisconnectSelf.
  2. Disconnector gate evaluation: For each collected frame owner, Blink calls LocalFrame::DetachImpl(FrameDetachType::kRemove) → ChildFrameDisconnector::ShouldFireUnloadEvents(childDocument).
  3. Event suppression vs dispatch: If OmitSubframeDetachmentEventsOnRemoval is active and InSameAgent() matches any enclosing kDisconnectSelf disconnector root, Blink skips pagehide, visibilitychange / webkitvisibilitychange, and unload completely, finishing DOM removal without re-entering author JS.
  4. Microtask observers run after removal: Parent MutationObserver callbacks run cleanly at the microtask checkpoint after the DOM tree reaches a consistent state.
Source: Blink child_frame_disconnector.cc; Blink local_frame.cc (LocalFrame::DetachImpl).

Examples

Interactive removal event recorder & safe teardown / moveBefore() migration

// Migration Pattern A: Explicit parent-to-child teardown handshake before removing an iframe
// Works identically regardless of whether pagehide / visibilitychange / unload fire on removal.
async function removeSubframeWithTeardown(iframe, targetOrigin, timeoutMs = 500) {
  const childWin = iframe.contentWindow;
  if (childWin) {
    await new Promise((resolve) => {
      const channel = new MessageChannel();
      const timer = setTimeout(resolve, timeoutMs);
      channel.port1.onmessage = () => {
        clearTimeout(timer);
        resolve();
      };
      // Child flushes unsaved draft / releases locks and replies on event.ports[0]
      childWin.postMessage({ type: "explicit-teardown" }, targetOrigin, [channel.port2]);
    });
  }
  iframe.remove();
}

// Migration Pattern B: Reparent a live same-origin iframe without detaching it (moveBefore)
function reparentSubframePreservingState(iframe, destinationContainer, referenceNode = null) {
  if (typeof destinationContainer.moveBefore === "function") {
    // Atomic move: child navigable stays alive (no reload, no detachment)
    destinationContainer.moveBefore(iframe, referenceNode);
  } else {
    // Legacy fallback detaches and reloads the iframe
    destinationContainer.insertBefore(iframe, referenceNode);
  }
}

// Migration Pattern C: Observe removal asynchronously from the host via MutationObserver
function watchSubframeRemoval(container, onRemoved) {
  const observer = new MutationObserver((records) => {
    for (const record of records) {
      for (const node of record.removedNodes) {
        if (node.nodeName === "IFRAME") {
          onRemoved(node);
        }
      }
    }
  });
  observer.observe(container, { childList: true });
  return observer;
}

Security and privacy

  • Eliminates synchronous DOM re-entrancy hazards: Firing author JavaScript from a same-agent subframe while the parent document is mid-way through removing nodes creates classic DOM-tree corruption and use-after-free/invariant bugs inside browser engines (requiring complex re-entrancy guards in Blink’s LocalFrame::DetachImpl). Omitting same-agent removal events closes this entire re-entrancy class.
  • Immutable agent boundary: Checking InSameAgent() (rather than mutable SecurityOrigin::CanAccess()) guarantees that a subframe cannot use document.domain during teardown to gain synchronous access to the removing ancestor’s DOM.
  • Privacy: Removing synchronous events exposes zero new capabilities, storage, or tracking signals; cross-origin telemetry handlers remain unaffected during the initial trial phase.
Source: Blink child_frame_disconnector.cc; whatwg/html#10194; ChromeStatus 5754395122860032.
