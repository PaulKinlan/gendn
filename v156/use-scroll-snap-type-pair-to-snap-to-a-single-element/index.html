Use scroll-snap-type: pair to snap to a single element

Adds the pair axis keyword to CSS scroll-snap-type so a 2D scroll container snaps both its inline and block axes together to a single snap area rather than picking X and Y snap targets independently. Unlike scroll-snap-type: both — which can land on an empty “phantom” intersection formed by Element A’s horizontal alignment and Element B’s vertical alignment — pair treats every dual-axis snap area as an atomic 2D point and ignores single-axis snap areas.

Limited availability — ships enabled by default in Chrome 156 and Edge 156; Firefox and Safari have positive standards positions without shipped implementations yet (base CSS Scroll Snap is Baseline Widely available since 2022-07-15)

why it exists

Two-dimensional scrolling surfaces — such as interactive maps, node graphs, design canvases, seating charts, and staggered galleries — place points of interest across a 2D plane that do not lie on a dense rectangular grid. Under scroll-snap-type: both, the browser evaluates X and Y snap positions independently, so a scroll can snap horizontally to Element A and vertically to Element B, leaving the viewport centered over empty space at (Element A.x, Element B.y). The pair keyword solves this natively by coupling both axes to a single target snap area without JavaScript scroll interception.

Source: scroll-snap-type-pair explainer; w3c/csswg-drafts#9519.

/* Eligible descendant snap area under pair: neither axis may compute to none */

scroll-snap-type: pair axis keyword

Inputs. Accepts pair alone (equivalent to pair proximity), pair proximity, or pair mandatory on a scroll container. As with other scroll-snap modes, proximity snaps only when the scroll landing position is within a UA-defined threshold of a valid 2D snap point, while mandatory always settles on a valid 2D snap point whenever the container is not actively scrolling. Exercise care with pair mandatory when snap areas are larger than the scrollport or widely spaced, so intermediate content remains reachable (per CSS Scroll Snap 1 §4.1.2).

Outputs & both vs. pair comparison. Setting scroll-snap-type: pair mandatory (or pair proximity) serializes with pair in getComputedStyle(el).scrollSnapType and forces the scroll container to align both axes to the same snap area element:

Dual-axis eligibility and coupled 2D target selection

Inputs (scroll-snap-align). Per CSS Scroll Snap 1 §4.1.1 and Chromium’s SnapContainerData::IsSnapAreaValidForAxis(), a descendant snap area is eligible under scroll-snap-type: pair only if neither its block nor its inline value in scroll-snap-align computes to none (for example, scroll-snap-align: center, which sets both axes to center, or scroll-snap-align: start end). Single-axis declarations such as scroll-snap-align: start none or scroll-snap-align: none center are ignored and excluded from the container’s reachable snap extremes.

Outputs & selection algorithm. When choosing a snap destination under SnapAxis::kPair in cc/input/scroll_snap_data.cc:

  1. Single-axis scroll gestures: Candidate search runs along the scrolled axis first; candidates not already aligned on the cross axis are demoted when a cross-axis-aligned candidate exists so scrolling along a row or column avoids unnecessary cross-axis jumps. Once a target area is chosen, the unsearched cross axis is derived directly from that same element’s alignment.
  2. Two-axis pan/fling or programmatic scrollTo(x, y): If independent X and Y searches pick different elements, Chromium reconciles them to a single target element’s 2D coordinate pair (never resting at an empty cross-axis intersection).
  3. scroll-snap-stop: always interaction: A scroll-snap-stop: always element that is not aligned on the cross axis will not preempt a candidate that stays aligned on the cross axis during a single-axis scroll.
Source: CSS Scroll Snap 1 §4.1.1; scroll-snap-type-pair explainer; Chromium cc/input/scroll_snap_data.cc.

Errors, invalid syntax, and progressive-enhancement fallbacks

  • Parse-time rejection: Combining pair with another axis keyword (such as scroll-snap-type: pair x or scroll-snap-type: both pair) or an invalid strictness keyword makes the declaration invalid at parse time; the CSS parser drops the declaration and CSS.supports() returns false.
  • Older browsers (Chrome ≤155, Firefox, Safari): Engines without pair drop scroll-snap-type: pair mandatory. Always declare scroll-snap-type: both mandatory (or both proximity) immediately before the pair declaration, or branch with @supports (scroll-snap-type: pair mandatory).
  • No eligible children: If a scroll-snap-type: pair container contains only elements with single-axis scroll-snap-align (e.g. start none) or none, zero valid snap points exist and the container scrolls freely without snapping.
Source: CSS Scroll Snap 1 §4.1; scroll-snap-type-pair explainer.

Context and exposure

Applies to any CSS scroll container (elements with scrollable overflow via overflow: auto | scroll | hidden, or the document root viewport) in any browsing context. No secure context, permission, or user activation is required. Controlled in Blink by the CSSScrollSnapTypePair runtime feature (status: "stable" in runtime_enabled_features.json5). Detectable in CSS via @supports (scroll-snap-type: pair mandatory) and in JavaScript via CSS.supports("scroll-snap-type", "pair mandatory").

Source: CSS Scroll Snap 1 §4.1; Blink runtime_enabled_features.json5.

Scroll lifecycle, re-snapping, and scroll-snap events

Snapping runs at the completion of user scroll/fling gestures, after programmatic scrollTo() / scrollBy() / scrollIntoView() calls, and during re-snapping after layout changes (CSS Scroll Snap 1 §4.1.3). When a pair container settles on a target, Chromium’s SnapContainerData::IsSnappedToArea() requires the container to be snapped on both axes simultaneously (is_snapped_on_x && is_snapped_on_y) before matching :snapped or firing scrollsnapchange — so event.snapTargetBlock and event.snapTargetInline on scrollsnapchange / scrollsnapchanging identify the same single element (or both null when unsnapped under proximity). Remember that scroll-snap events do not automatically update ARIA state; reflect the active snapped landmark in the accessibility tree (for example, aria-current="location" on linked navigation controls).

Source: CSS Scroll Snap 1 §4.1.3; Chromium cc/input/scroll_snap_data.cc.

Examples

Live demo & progressive-enhancement 2D map canvas

.map-viewport {
  inline-size: 100%;
  block-size: 28rem;
  overflow: auto;
  /* Fallback for engines without pair support */
  scroll-snap-type: both mandatory;
  /* Coupled 2D snapping to a single landmark (Chrome 156+, Edge 156+) */
  scroll-snap-type: pair mandatory;
}

.map-landmark {
  /* Eligible under pair: non-none alignment on both block and inline axes */
  scroll-snap-align: center center;
}

.map-gutter-label {
  /* Ignored under pair because the inline axis is none */
  scroll-snap-align: start none;
}
Source: CSS Scroll Snap 1 §4.1.1; scroll-snap-type-pair explainer.

Feature detection & synchronized scrollsnapchange state

const supportsPairSnap = CSS.supports("scroll-snap-type", "pair mandatory");

function bindSnapIndicator(scroller, navLinks) {
  if (!("onscrollsnapchange" in HTMLElement.prototype)) return { supportsPairSnap };

  scroller.addEventListener("scrollsnapchange", (event) => {
    // Under scroll-snap-type: pair, block and inline targets refer to the same element
    const active = event.snapTargetBlock;
    for (const link of navLinks) {
      if (active && link.getAttribute("href") === `#${active.id}`) {
        link.setAttribute("aria-current", "location");
      } else {
        link.removeAttribute("aria-current");
      }
    }
  });

  return { supportsPairSnap };
}

Security and privacy

scroll-snap-type: pair is a pure CSS scroll-layout keyword operating within the document’s existing scroll snapping model. It introduces no new permissions, storage, network capabilities, cross-origin data exposure, or fingerprinting surface beyond standard CSS feature detection with CSS.supports("scroll-snap-type", "pair mandatory").

Source: ChromeStatus 5124378896498688; CSS Scroll Snap 1 §4.1.1.
