FontFace width attribute and font-width descriptor

Exposes the FontFace.width attribute, the FontFaceDescriptors.width constructor dictionary member, and the CSS @font-face font-width descriptor as exact aliases for FontFace.stretch and font-stretch. Aligns Chromium with CSS Font Loading and CSS Fonts Level 4 so developers can initialize, declare, and inspect font widths using width / font-width interchangeably with legacy stretch / font-stretch.

Limited availability — FontFace.width ships in Chrome 154, Firefox 155, and Safari 18.5, while the broader font-width web-feature (including the CSS font-width property) remains Limited availability

  • Chrome · 154 (desktop, Android, WebView — FontFace.width and @font-face font-width descriptor; CSS font-width property not yet shipped)
  • Edge · 154 (Chromium-based mirror)
  • Firefox · 155 (FontFace.width and CSS font-width property; passes WPT aliasing test)
  • Safari · 18.4 (@font-face font-width) / 18.5 (FontFace.width)

Although MDN documents @font-face/font-width, MDN has no FontFace.width page (HTTP 404, checked 2026-11-27), so gendn provides a complete spec-backed reference covering both the JavaScript and CSS surfaces.

why it exists

CSS Fonts Module Level 4 renamed the legacy font-stretch descriptor and property to font-width (matching the OpenType wdth variation axis and avoiding the misleading implication of synthetic horizontal scaling), and CSS Font Loading correspondingly promoted width on FontFace and FontFaceDescriptors while retaining stretch as a permanent legacy alias. Before Chrome 154, Blink ignored the width member in new FontFace(..., { width }), did not expose FontFace.prototype.width, and rejected font-width inside @font-face rules, failing WPT font-face-width-descriptor-aliasing.html. Exposing both aliases brings Blink’s font-loading surface in line with the specifications, Safari, and Firefox.

Source: ChromeStatus 5145402365050880; CSS Fonts 4 §2.3; CSS Font Loading §2.

Syntax

WebIDL additions on FontFace and FontFaceDescriptors (from CSS Font Loading §2 and Blink’s font_face.idl and font_face_descriptors.idl):

partial interface FontFace {
  [RaisesException=Setter, SetterCallWith=ExecutionContext, ImplementedAs=stretch]
  attribute CSSOMString width;
};

partial dictionary FontFaceDescriptors {
  CSSOMString width;
};

CSS @font-face descriptor grammar (from CSS Fonts Module Level 4 §4.4 font-width descriptor, aliased to font-stretch in at_rule_names.json5):

@font-face {
  font-width: auto | <font-width-absolute>{1,2};
}

<font-width-absolute> =
  normal | ultra-condensed | extra-condensed | condensed | semi-condensed |
  semi-expanded | expanded | extra-expanded | ultra-expanded | <percentage [0,∞]>

This reference covers all three surfaces exposed in Chrome 154: FontFace.width, FontFaceDescriptors.width, and the @font-face font-width descriptor.

Source: CSS Font Loading §2; CSS Fonts 4 §4.4; Blink font_face.idl; Blink font_face_descriptors.idl.

FontFace.width

Inputs & accepted values. A CSSOMString representing a valid CSS @font-face font-width / font-stretch descriptor value: "auto", any single width keyword ("ultra-condensed" through "ultra-expanded"), a positive percentage (for example "75%" or "125%"), or a space-separated percentage range for variable fonts (for example "75% 125%").

Outputs & aliasing behavior. In Blink’s font_face.idl, FontFace.width carries [ImplementedAs=stretch], so face.width and face.stretch read and write the exact same backing descriptor slot (FontFace::stretch() / FontFace::setStretch() in font_face.cc). Reading face.width returns the serialized descriptor string (defaulting to "normal" when unset). Writing face.width = "75%" immediately makes face.stretch === "75%", and writing face.stretch = "condensed" immediately updates face.width.

Source: CSS Font Loading §2; Blink font_face.idl; Blink font_face.cc.

FontFaceDescriptors.width

Inputs & precedence. Optional CSSOMString member in the third argument (descriptors) of new FontFace(family, source, descriptors). Accepts the exact same grammar as FontFace.width. Unlike stretch (which declares default "normal" in font_face_descriptors.idl), width has no dictionary default so Blink can detect whether the caller explicitly passed it.

Outputs & conflict resolution. In FontFace::FontFace(), Blink resolves the initial width descriptor via descriptors->hasWidth() ? descriptors->width() : descriptors->stretch(). Consequently, if a caller supplies both width and stretch in the same descriptors object (for example { stretch: "50%", width: "200%" }), width wins and sets both face.width and face.stretch to "200%" (verified in WPT font-face-width-descriptor-aliasing.html). When neither is supplied, both default to "normal".

Source: CSS Font Loading FontFaceDescriptors; Blink font_face_descriptors.idl; Blink font_face.cc; WPT.

@font-face font-width descriptor

Inputs & keyword-to-percentage table. Inside a CSS @font-face rule, font-width is registered as a direct descriptor alias for font-stretch in Blink at_rule_names.json5 ({ name: "font-stretch", alias: "font-width" }). It accepts auto, a single percentage or keyword, or a two-value percentage range (lower upper) for variable fonts with a wdth axis:

Standard CSS Fonts 4 font-width / font-stretch keywords and equivalent percentages
KeywordPercentageUsage
ultra-condensed50%Narrowest named face
extra-condensed62.5%Extra narrow face
condensed75%Condensed face
semi-condensed87.5%Slightly narrow face
normal100%Default width (initial value when descriptor is omitted)
semi-expanded112.5%Slightly wide face
expanded125%Expanded face
extra-expanded150%Extra wide face
ultra-expanded200%Widest named face
auto / rangee.g. 75% 125%Variable font wdth axis range (two-value form) or automatic clamping

Outputs & CSSOM reflection. When an @font-face rule declares font-width: 75% 125%, Blink parses it through AtRuleDescriptorID::FontStretch and populates the same descriptor slot exposed on the resulting CSS-connected FontFace instance’s width and stretch properties. If both font-stretch and font-width appear in the same @font-face block, standard CSS declaration order applies — the last valid declaration wins — so write font-stretch first and font-width second for progressive enhancement.

Source: CSS Fonts 4 §2.3; CSS Fonts 4 §4.4; Blink at_rule_names.json5.

Errors and validation

  • FontFace.width setter (SyntaxError): Assigning a malformed value (such as a negative percentage "-50%", a non-width keyword like "bold", an empty string, or three values) to face.width (or face.stretch) synchronously throws a SyntaxError DOMException from FontFace::SetPropertyFromString() and leaves the previous descriptor value unchanged.
  • new FontFace(..., { width }) constructor (async error state, no throw): Passing an unparseable FontFaceDescriptors.width value (for example { width: "-10%" } or { width: "bogus" }) does not throw synchronously; instead, per CSS Font Loading §2.2 and font_face.cc, the constructed FontFace enters status === "error" and its loaded promise rejects with a SyntaxError DOMException.
  • @font-face font-width descriptor (parse-time drop): Invalid values (negative percentages, unknown keywords, or reversed/out-of-grammar values) are ignored at CSS parse time without invalidating other descriptors in the @font-face block. On older browsers that do not recognize font-width, the declaration is dropped and falls back to an earlier font-stretch declaration if present.
Source: CSS Font Loading §2.2; Blink font_face.cc; CSS Fonts 4 §4.4.

Context, exposure, and scope boundaries

FontFace (including FontFace.width and FontFaceDescriptors.width) is exposed in both Window and Worker contexts ([Exposed=(Window,Worker)] in font_face.idl), where workers access self.fonts (FontFaceSet) for OffscreenCanvas text rendering. No secure context, permission, or user activation is required. The @font-face font-width descriptor works in any stylesheet (<style>, linked CSS, or constructable CSSStyleSheet).

Important Chrome 154 boundary: This feature ships FontFace.width, FontFaceDescriptors.width, and the @font-face font-width descriptor. In element style rules, Blink’s css_properties.json5 still defines only the font-stretch CSS property (matching BCD css/properties/font-width.json where Chrome is false), so keep pairing font-stretch alongside font-width on element selectors.

Source: Blink font_face.idl; Blink css_properties.json5; BCD css/properties/font-width.json.

Lifecycle, mutation invalidation, and aliasing semantics

FontFace.width and FontFace.stretch share one internal CSSValue slot on the FontFace instance. Mutating face.width (or face.stretch) on a font face already added to document.fonts triggers InvalidateFontFaceOnDescriptorUpdate() in font_face.cc whenever the parsed value actually changes, causing the font matching cache to re-evaluate affected elements on the next style/layout pass. Updating a CSS-connected FontFace created from an @font-face rule updates the rule’s effective descriptor immediately without reloading the font binary.

Source: CSS Font Loading §2; Blink font_face.cc.

Examples

Live demo & FontFace.width / FontFaceDescriptors.width

// Feature-detect FontFace.width and initialize with backward-compatible fallback
const supportsFontFaceWidth = "width" in FontFace.prototype;

function createVariableFace(family, url, widthRange = "75% 125%") {
  // Pass both width and stretch: browsers supporting FontFaceDescriptors.width
  // give width precedence; older browsers read stretch.
  const face = new FontFace(family, `url(${url})`, {
    stretch: widthRange,
    width: widthRange,
  });

  if (supportsFontFaceWidth) {
    // Reading or mutating face.width reflects directly on face.stretch
    console.log(face.width === face.stretch); // true
  }
  return face;
}

// Validate setter error handling
function updateFaceWidth(face, nextWidth) {
  try {
    if ("width" in face) {
      face.width = nextWidth;
    } else {
      face.stretch = nextWidth;
    }
    return true;
  } catch (err) {
    // SyntaxError DOMException on invalid descriptor value (e.g., "-50%")
    return err.name === "SyntaxError" ? false : Promise.reject(err);
  }
}
Source: CSS Font Loading §2; WPT font-face-width-descriptor-aliasing.html.

Progressive-enhancement @font-face font-width descriptor

@font-face {
  font-family: "Editorial Sans";
  src: url("/fonts/editorial-sans-vf.woff2") format("woff2");
  font-weight: 100 900;
  /* Legacy alias first for older browsers, standardized font-width descriptor second */
  font-stretch: 75% 125%;
  font-width: 75% 125%;
  font-display: swap;
}

.condensed-label {
  font-family: "Editorial Sans", sans-serif;
  /* Keep font-stretch on element rules until the CSS font-width property ships in Chrome */
  font-stretch: condensed;
  font-width: condensed;
}
Source: CSS Fonts 4 §4.4; Blink at_rule_names.json5.

Security and privacy

FontFace.width, FontFaceDescriptors.width, and the @font-face font-width descriptor are pure naming aliases over the pre-existing stretch / font-stretch descriptor machinery. They introduce no new font-enumeration, network, storage, or permission capabilities and do not expand fingerprinting surface beyond what FontFace.stretch and standard CSS feature detection already expose.

Source: ChromeStatus 5145402365050880; CSS Font Loading §2.
