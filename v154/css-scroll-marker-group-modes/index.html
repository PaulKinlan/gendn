CSS scroll-marker-group modes

Limited availability

  • Chrome · property since 135; links/tabs modes in 154
  • Edge · mirrors Chrome (property since 135)
  • Firefox · not shipped
  • Safari · not shipped

The underlying scroll-markers web-feature is Baseline limited (queried 2026-09-27) — Chromium-only since Chrome/Edge 135. The links/tabs mode keywords documented here are newer still: they ship in Chrome 154 and are not yet recorded in BCD css/properties/scroll-marker-group.json (whose value subfeatures are still only none/before/after, verified 2026-09-27). See the full table.

Chrome 154 extends the scroll-marker-group property with two mode keywords, links and tabs, that choose the accessibility contract of the generated ::scroll-marker-group: a navigation list of links (the default), or a WAI-ARIA tablist with roving focus, automatic tabpanel roles, and accessibility-tree pruning of inactive panels — the interactive foundation for a native tabbed carousel.

Early-stage surface. The modes are enabled by default in Chrome 154 (no flag needed — runtime feature CSSScrollMarkerGroupModes is stable), but the scroll-marker family is Chromium-only, BCD marks the property experimental: true, and the defining spec is a CSS Working Group Editor’s Draft still under active discussion. The keywords and their accessibility semantics may change before this is Baseline — don’t build tab UIs that only work with this feature.

syntax

Chrome 154 upgrades the scroll-marker-group grammar from none | before | after to the following value definition, quoted verbatim from the css-overflow-5 property definition:

scroll-marker-group: none  |  [ [ before | after ]  ||  [ links | tabs ] ]
/* position only — mode defaults to links */
scroll-marker-group: after;

/* position + mode, any order (|| combinator) */
scroll-marker-group: after tabs;
scroll-marker-group: links before;

/* mode only — the || grammar permits a bare mode keyword.
   NOTE: css-overflow-5 §3.1.4 defines the group box's placement
   only for the `before` and `after` keywords; the draft text read
   on 2026-09-27 does not state which position applies when the
   position keyword is omitted. */
scroll-marker-group: tabs;
links (default mode)
The generated ::scroll-marker-group takes the navigation role and each ::scroll-marker the link role — the <nav> + <a href="#target"> pattern. All markers are sequential tab stops, in order. The originating elements’ roles are unaffected. Activating a marker moves the sequential focus navigation starting point to the target element, mimicking a standard same-document anchor link.
tabs
The ::scroll-marker-group takes the tablist role and each ::scroll-marker the tab role; each marker’s originating element is implicitly given the tabpanel role (when the originating element is a ::column, the tabpanel role goes to the ::column’s originating element). The group behaves as a single focusable component establishing a focusgroup: only the active marker is a tab stop and arrow keys switch between markers (roving tabindex="-1" behavior, with a guaranteed tab stop on the first marker when none is active). Each marker is a focus navigation scope owner for its originating element, so Tab from the active marker moves into the active panel’s content. Content of inactive tabs is hidden from the accessibility tree, so authors do not need to script interactivity: inert on inactive panels themselves.

The mode keywords select accessibility semantics only and add no privacy or security surface: css-overflow-5’s Appendix C (Privacy Considerations) and Appendix D state the specification “introduces no new privacy considerations” and “no new security considerations” (read 2026-09-27).

Source: css-overflow-5 §3.1.6 Scroll Marker Modes; propdef scroll-marker-group

choosing a mode

Both modes exist because carousel-style UI splits into two established accessibility patterns, and the right one depends on whether out-of-view content should stay reachable:

linkstabs
Group / marker rolesnavigation / linktablist / tab
Originating elementsRoles unaffectedImplicit tabpanel role
Keyboard modelEvery marker a sequential tab stopRoving focus: arrow keys within the group; only the active marker is a tab stop
Activation focusFocus leaves the marker; sequential focus start point moves to the targetFocus stays on the marker; Tab then enters the active panel
Inactive contentRemains in the accessibility treePruned from the accessibility tree (implicit inertness)

Use links for pagers whose sections are all part of the page (a scrolling journal, a table of contents), and tabs when the scroller behaves as a tabbed interface where only the visible panel is “current” — the spec positions it as the interactive foundation for the Tabbed Carousel Pattern.

Source: css-overflow-5 §3.1.6 (roles, focus, tree pruning); framing per the explainer and the ChromeStatus summary

examples

A scroll container whose markers behave as a proper tablist — no ARIA attributes, no roving-tabindex script:

.carousel {
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  /* dots after the scroller, operating as a tablist */
  scroll-marker-group: after tabs;
}

.carousel > .slide {
  scroll-snap-align: start;
  /* each slide implicitly becomes the marker's tabpanel */
}

.carousel > .slide::scroll-marker {
  content: "";
  /* style the generated tab dot */
}
