WebTransport reliability attributes

Chrome adds the WebTransport.prototype.reliability instance attribute and the static WebTransport.supportsReliableOnly attribute from the W3C WebTransport specification. reliability reads "pending" while a session connects and then reports whether it can carry unreliable traffic such as datagrams ("supports-unreliable", HTTP/3) or only reliable streams ("reliable-only", HTTP/2). supportsReliableOnly reports, without opening a connection, whether the browser can run WebTransport over an exclusively reliable connection at all.

what Chrome reports

Chromium implements WebTransport only over HTTP/3 and has no HTTP/2 fallback, so in Chrome the values are fixed: WebTransport.supportsReliableOnly is false, and a session’s reliability moves from "pending" to "supports-unreliable" once ready fulfils. Chrome never reports "reliable-only". A session that fails to connect never leaves "pending": the spec only assigns the final value in the step that resolves ready.

// Capability check without opening a connection.
if (typeof WebTransport !== "undefined" && "supportsReliableOnly" in WebTransport) {
  // Chrome 158: false. A network that blocks UDP (QUIC) cannot fall back to HTTP/2.
  console.log(WebTransport.supportsReliableOnly);
}

const wt = new WebTransport("https://example.com:4433/wt");
console.log(wt.reliability); // "pending" while connecting
await wt.ready;              // rejects if the session cannot be established
console.log(wt.reliability); // Chrome: "supports-unreliable" (HTTP/3)
if (wt.reliability === "reliable-only") {
  // HTTP/2 session (other engines only): avoid relying on datagrams.
}

quick reference

The changeTwo read-only attributes on WebTransport: readonly attribute WebTransportReliabilityMode reliability; and static readonly attribute boolean supportsReliableOnly;, with enum WebTransportReliabilityMode { "pending", "reliable-only", "supports-unreliable" }; (IDL verbatim from the WebTransport spec). Both are exposed in Window and Worker contexts and require a secure context, like the rest of WebTransport.
Related optionWebTransportOptions.requireUnreliable (default false): when true, the session cannot be established over HTTP/2 if HTTP/3 is not possible. Not covered by this ChromeStatus entry; listed because it is the constructor-side counterpart of "reliable-only".
Chrome statusThe milestone=158 listing files it under “Enabled by default” (fetched 2026-11-22). No origin trial; the detail record’s implementation-status text still reads “Proposed”, which is stale against the stable runtime flag above. Flag before shipping: chrome://flags/#enable-experimental-web-platform-features (dev trial from 155). Tracking bug: crbug 545636884
BaselineThe parent WebTransport web-feature is Baseline Newly available since 2026-03-24 (Chrome/Edge 97, Firefox 114, Safari 26.4) per the webstatus.dev API. That date predates Chrome’s support for these two members (157/158, above), so the parent badge does not cover them in older Chrome; BCD tags reliability to the webtransport web-feature but gives supportsReliableOnly no web-feature tag
SpecWebTransport — reliability, supportsReliableOnly, WebTransportReliabilityMode (W3C Candidate Recommendation Snapshot; Editor’s Draft). Explainer: Transport Modes. Spec change linked by ChromeStatus: w3c/webtransport#385
TestsWPT reliability.https.any.html ("pending" synchronously after construction, window + worker) and reliability.https.window.html ("reliable-only" or "supports-unreliable" after ready)
