WebTransport draining

Chrome adds the read-only WebTransport.prototype.draining attribute — a stable Promise<undefined> that fulfills once when the server signals that the WebTransport session is going to be gracefully retired (for example via a WT_DRAIN_SESSION capsule or HTTP/3 GOAWAY). Applications can open a replacement session and wrap up in-flight work while existing streams and datagrams remain usable.

Chrome 158 details & edge behavior

In Chromium’s web_transport.idl, readonly attribute Promise<undefined> draining is exposed in both Window and Worker secure contexts behind the now-stable WebTransportDraining runtime flag. Key invariants verified by WPT webtransport/draining.https.any.js:

  • Same-object promise before ready: wt.draining is created during construction ([[Draining]] internal slot), returns the identical Promise instance on repeated reads, and may be observed before wt.ready fulfills.
  • Session stays usable after draining: fulfilling wt.draining does not settle wt.closed and does not stop either peer from opening new unidirectional or bidirectional streams or exchanging datagrams.
  • Stays pending on normal close without drain signal: if the session closes via wt.close() without the server sending a WT_DRAIN_SESSION capsule, wt.draining remains pending rather than settling.
// Feature-detect for Chrome < 158 and older engines
if (typeof WebTransport !== "undefined" && "draining" in WebTransport.prototype) {
  const wt = new WebTransport("https://example.com:4433/wt");
  wt.draining.then(async () => {
    // Server requested graceful retirement; open a replacement session
    // while existing streams remain active.
    const next = new WebTransport("https://example.com:4433/wt");
    await next.ready;
    wt.close();
  });
  await wt.ready;
}
