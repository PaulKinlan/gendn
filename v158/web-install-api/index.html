Web Install API

navigator.install() allows a secure top-level website to prompt the user to install either the current page’s web application (with no arguments) or another same-origin or cross-origin web application identified by its manifest URL and optional manifestId. It provides a promise-based imperative counterpart to the declarative HTML <install> element and replaces the event-driven beforeinstallprompt workflow while keeping browser-controlled consent UI and explicit user activation.

Limited availability — Chromium desktop only (not Baseline; Firefox no signal, Safari opposed)

  • Edge · Chromium-based (co-authored by Microsoft Edge; mirrors Chromium)

why it exists

Previously, websites could only trigger web app installation for the currently loaded page by intercepting the non-standard beforeinstallprompt event, and had no web-platform way to offer installation of sibling apps in a multi-app suite or third-party web apps from a catalog or search result without navigating away or relying on platform app stores.

The Web Install API provides a direct, promise-based navigator.install() entry point for both same-document and explicit-manifest (same-origin or cross-origin) installations, while keeping installation gated behind transient user activation, explicit browser-controlled confirmation UI, and a dedicated origin-level web-app-installation permission for background/cross-origin installs.

Source: ChromeStatus motivation (5183481574850560); Web Install API explainer.

Syntax

Verbatim WebIDL from the WICG Web Install draft specification and Chromium’s navigator_web_install.idl, install_params.idl, and web_install_result.idl:

partial interface Navigator {
  [SecureContext] Promise<WebInstallResult> install();
  [SecureContext] Promise<WebInstallResult> install(InstallParams options);
};

dictionary InstallParams {
  required USVString manifest;
  USVString? manifestId;
};

dictionary WebInstallResult {};

Migration note from the Chrome 143–148 Origin Trial: the earlier positional string overloads (navigator.install(url) and navigator.install(url, manifestId)) were removed before shipping and now reject with TypeError. Always pass either no arguments or an InstallParams dictionary containing a manifest URL (not a document URL).

This reference covers three parts of the contract: navigator.install() overloads and execution order, InstallParams and WebInstallResult, and web-app-installation permission, Permissions Policy, and enterprise control.

Source: WICG Web Install draft; Blink navigator_web_install.idl; WPT navigator-install-bad-inputs.tentative.https.html.

navigator.install() — overloads, inputs, and outputs

Inputs (two overloads).

  • Zero-argument form — navigator.install(): targets the web application associated with the currently loaded document’s linked web app manifest. The document’s manifest must declare an explicit id member; otherwise installation rejects with DataError.
  • Dictionary form — navigator.install(options): accepts an InstallParams dictionary specifying the target app’s manifest URL and optional manifestId URL. Can install either a same-origin sibling app or a cross-origin web app without loading the target app’s HTML document.

Outputs. Returns a Promise<WebInstallResult> that resolves to an empty WebInstallResult object ({}) once the user confirms installation (or, if the app is already installed and the browser shows a launch confirmation dialog, once the user confirms launching it). The resolved object intentionally omits the manifest ID or install metadata to minimize cross-origin state disclosure.

Source: Blink navigator_web_install.cc; Web Install explainer §Proposed Approach.

Errors and exact precondition order

Because navigator.install() returns a Promise, WebIDL overload/conversion failures and all precondition failures reject the returned promise rather than throwing synchronously. Chromium evaluates checks in the following exact order (verified in navigator_web_install.cc):

Rejection order and recovery guidance for navigator.install()
OrderRejection errorConditionRecovery
1TypeError (WebIDL binding)Wrong argument type (including removed positional strings install(url)) or missing required manifest key in InstallParams.Call navigator.install() or navigator.install({ manifest, manifestId }).
2SecurityErrorweb-app-installation Permissions Policy blocks this document, or the document/frame has any sandbox flag set (even allow-scripts allow-same-origin).Ensure policy allows self and invoke from a non-sandboxed top-level document.
3InvalidStateErrorDetached window, non-main frame (including same-origin <iframe>), prerendering document, fenced frame tree, or invalid script state.Invoke only in an active, primary top-level browsing context.
4NotAllowedErrorNo active transient user activation (note: a valid call consumes transient user activation immediately).Invoke directly from a user click/keypress handler without awaiting unrelated async work first.
5TypeError (URL validation)manifest is empty, whitespace-only, or an invalid URL; or non-null manifestId is empty, whitespace-only, or an invalid URL.Pass valid absolute or base-relative URLs; omit manifestId (or pass undefined/null) when relying on the manifest’s id.
6AbortErrorUser denies the web-app-installation origin permission, cancels the install/launch confirmation UI, or the browser suppresses the flow (e.g., off-the-record/Incognito profile).Treat as user cancellation; avoid re-prompting automatically without a new explicit click.
7DataErrorCurrent document has no linked manifest (0-arg); manifest fetch fails (fetched with credentials: "omit"); malformed manifest; manifest origin differs from start_url origin; manifest has no id when manifestId was omitted; or manifestId does not match the computed manifest ID.Verify the manifest URL returns valid JSON with an explicit id (or supply the exact computed manifestId).
Source: Blink navigator_web_install.cc; WPT navigator-install-sandboxed-iframe; WPT navigator-install-user-activation.

Context and exposure

navigator.install() is exposed on Window (via Navigator) in Secure Contexts (https:// or localhost) only; it is not defined on HTTP origins (verified by WPT navigator-install-not-defined.tentative.http.html) and is not exposed in Workers. Calls are restricted to non-sandboxed, primary top-level browsing contexts (disallowed in all iframes, fenced frames, and prerendering pages) with transient user activation and web-app-installation Permissions Policy allowance. Web app installation is not available in Incognito / off-the-record profiles.

Source: Blink navigator_web_install.idl; Blink navigator_web_install.cc; Web Install explainer §Private / Incognito.

Lifecycle and state transitions

When invoked on a user gesture, the browser: (1) checks Permissions Policy, document/frame/sandbox preconditions, and consumes transient user activation; (2) parses and resolves manifest and optional manifestId against the current document’s base URL; (3) for explicit-manifest calls, checks or prompts for the origin’s web-app-installation permission; (4) fetches the manifest with credentials mode "omit" (no cookies) without loading the target app’s document, validates JSON and same-origin start_url, and verifies the manifest’s explicit or computed id; (5) presents browser-controlled install confirmation UI (or a launch prompt if already installed); and (6) resolves with {} on acceptance or rejects with AbortError/DataError. Because the target app’s page is not loaded during explicit-manifest installation, its service worker is not registered until the installed app is launched.

Source: Web Install explainer §Steps to install; Web Install explainer §Service worker registration.

Examples

No interactive Chrome Platform Showcase demo exists yet for v158/web-install-api (checked 2026-11-24). Live external samples from the feature authors are available at MicrosoftEdge PWA Install API Demo and Web Install manifest-URL demo.

Installing the current document’s web app (0-argument overload)

const installSelfBtn = document.querySelector("#install-self");

if (typeof navigator.install === "function") {
  installSelfBtn.hidden = false;

  installSelfBtn.addEventListener("click", async () => {
    try {
      // Requires the current page's linked manifest to declare an explicit "id"
      await navigator.install();
      installSelfBtn.textContent = "Installed";
    } catch (err) {
      if (err.name === "AbortError") {
        // User dismissed the install dialog; no error UI required
        return;
      }
      console.error(`Install failed (${err.name}):`, err.message);
    }
  });
}
Source: WICG Web Install draft; Web Install explainer §Sample code.

Checking permission and installing a cross-origin app by manifest URL

const installCatalogAppBtn = document.querySelector("#install-catalog-app");

async function canOfferBackgroundInstall() {
  if (typeof navigator.install !== "function") return false;
  if (!navigator.permissions?.query) return true;
  try {
    const { state } = await navigator.permissions.query({
      name: "web-app-installation",
    });
    return state !== "denied";
  } catch {
    return true;
  }
}

installCatalogAppBtn.addEventListener("click", async () => {
  if (!(await canOfferBackgroundInstall())) {
    // Fallback: link directly to the app so the user can install it there
    window.open("https://music.example/", "_blank", "noopener");
    return;
  }

  try {
    await navigator.install({
      manifest: "https://music.example/manifest.webmanifest",
      // Optional only if the target manifest explicitly defines "id"
      manifestId: "https://music.example/app",
    });
    console.log("Web app installed successfully.");
  } catch (err) {
    switch (err.name) {
      case "AbortError":
        console.info("User cancelled permission or install confirmation.");
        break;
      case "DataError":
      case "TypeError":
        console.error("Invalid manifest URL, fetch failure, or manifestId mismatch.");
        break;
      case "NotAllowedError":
        console.warn("Must be called directly inside a user gesture.");
        break;
      default:
        console.error(`Unexpected install error (${err.name}):`, err.message);
    }
  }
});
Source: Web Install explainer §New installation permission; Blink navigator_web_install.cc.

Security and privacy

Allowing one origin to initiate installation of a cross-origin web app introduces spam, spoofing, cross-origin probing, and credential-leakage risks. The specification and Chromium implementation enforce multiple safeguards:

  • No unattended installs & clear attribution: Transient user activation is consumed on every call, and the browser always displays a browser-controlled confirmation dialog identifying the requesting site and target app.
  • Origin-scoped permission for background/cross-origin installs: Requesting origins must hold the web-app-installation permission before installing apps other than the currently loaded document, allowing users to block abusive catalogs persistently.
  • Credential-free manifest fetch & same-origin manifest constraint: Explicit-manifest requests are fetched with credentials mode "omit" (no cookies or auth headers) and are subject to Local Network Access checks; the manifest URL must be same-origin with its resolved start_url.
  • Minimal state disclosure: Successful installs resolve to an empty WebInstallResult ({}), and already-installed apps follow the same confirmation/AbortError contract rather than returning an installation-status oracle. Off-the-record/Incognito profiles avoid immediate distinguishable failure signals.
  • Strict framing & origin isolation: Disallowed in all iframes, sandboxed documents, fenced frames, and prerendering pages; installed apps never inherit permissions from the installing origin.
Source: Web Install explainer §Privacy & Security; WICG Web Install draft; W3C TAG design review #1245.
