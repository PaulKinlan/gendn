OfflineAudio­Context.close()

Stops an OfflineAudioContext for good: rendering halts, any chunk promises still pending reject with AbortError, and the context moves to "closed". It is the only way to end a length: null (open-ended) render and the way to cancel a long finite one. New in Chrome 158 (ChromeStatus 5109900936085504); its presence is also the recommended feature-detection signal for incremental rendering.

syntax

close()

Spec IDL (Web Audio API § OfflineAudioContext close(), verbatim):

Promise<undefined> close();

Chromium (offline_audio_context.idl) marks it [RuntimeEnabled=OfflineAudioContextIncrementalRendering], so close only exists on OfflineAudioContext.prototype where the feature is on. It is distinct from AudioContext.close(); BaseAudioContext has no close.

Source: spec; offline_audio_context.idl

parameters

None. close() takes no arguments; any passed are ignored per Web IDL overload resolution. Its behaviour depends only on the context’s current state: not yet started, rendering or suspended, between chunks, or already closed.

return value

A Promise<undefined> that fulfils once the rendering thread has stopped and the context is "closed". Effects, in order:

  • Rendering stops at the current render quantum; the partially rendered chunk is not delivered.
  • Every pending startRendering() promise — the one rendering and any queued — rejects with AbortError.
  • Pending suspend() promises reject with InvalidStateError.
  • state becomes "closed" and statechange fires. complete does not fire.
  • currentTime stops advancing. Nodes are not automatically released; drop your references to let them be collected.
const ctx = new OfflineAudioContext({ numberOfChannels: 2, sampleRate: 44100, length: null });
const big = ctx.startRendering(10 * 44100);   // state === "running"
await ctx.close();                            // big rejects with AbortError
console.log(ctx.state);                       // "closed"
Source: close() algorithm; offline_audio_context.cc (closeContext, OnRenderStopped); WPT offlineaudiocontext-close

exceptions

Rejections of close()
ExceptionWhen
InvalidStateErrorThe document is not fully active (spec)
InvalidStateErrorThe context is already "closed", or a previous close() is still in progress (the second of two back-to-back calls rejects; WPT)
InvalidStateErrorA finite context has already rendered all its frames — it closed itself, so a trailing close() rejects. Guard with if (ctx.state !== "closed")

After close(), startRendering(), resume() and suspend() all reject with InvalidStateError. A closed context cannot be reopened; construct a new one.

Source: spec; offline_audio_context.cc; WPT

context and exposure

  • [Exposed=Window], on OfflineAudioContext only. No secure-context, permission or user-activation requirement.
  • Available from Chrome 158 (runtime feature OfflineAudioContextIncrementalRendering, status: "stable" in runtime_enabled_features.json5).
  • Feature detection: typeof OfflineAudioContext.prototype.close === "function" — recommended by the explainer as the signal for the whole incremental-rendering feature.

lifecycle

What close() does in each state
State when calledResult
"suspended", never renderedResolves; context closed. Valid — WPT “close before rendering”
"running", chunk renderingRendering stops; that chunk and any queued chunks reject AbortError; resolves
"suspended" by suspend() mid-chunkQueued chunks reject AbortError; future suspends reject InvalidStateError; no complete; resolves
"running", between chunks (open-ended)Resolves; context closed
"closed"Rejects InvalidStateError

Not idempotent: call it once. Re-entrant calls are safe — calling close() synchronously while a chunk promise resolves rejects the chunk queued in the same turn with AbortError (WPT).

Source: WPT offlineaudiocontext-close; WPT incremental-rendering; offline_audio_context.cc

examples

A cancel button for a long export

const cancel = document.querySelector("#cancel");
const ctx = new OfflineAudioContext({ numberOfChannels: 2, sampleRate: 48000, length: 48000 * 3600 });
buildGraph(ctx);

cancel.addEventListener("click", () => {
  if (ctx.state !== "closed") ctx.close();
}, { once: true });

try {
  while (ctx.state !== "closed") {
    await save(await ctx.startRendering(48000));
  }
} catch (err) {
  if (err.name !== "AbortError") throw err;    // AbortError = user cancelled
}

Always release an open-ended context

const ctx = new OfflineAudioContext({ numberOfChannels: 1, sampleRate: 16000 }); // length: null
try {
  for (let i = 0; i < 100; i++) feed(await ctx.startRendering(1600));
} finally {
  if (ctx.state !== "closed") await ctx.close();
}
Source: behaviour per the spec and WPT; buildGraph, save, feed are placeholders

security and privacy

close() exposes nothing; it only ends work the page started. It is the page’s tool for releasing the rendering thread an open-ended context holds. See the spec’s Privacy Considerations for the unchanged Web Audio fingerprinting notes.
