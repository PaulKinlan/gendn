Shared dictionaries and enum values

The remaining source-declared values used by printer capabilities and job templates. They are typed strings and dictionaries, not IPP’s arbitrary attribute map.

Proposal and implementation differ from the old overviewChromeStatus currently records this API as Proposed, not shipped. This reference follows the current WICG IDL and Chromium source; test in the intended IWA configuration and feature-detect rather than relying on the v147 label.

Syntax

typedef (WebPrintingRange or unsigned long) WebPrintingMediaSizeDimension;

dictionary WebPrintingMediaSize {
  WebPrintingMediaSizeDimension yDimension;
  WebPrintingMediaSizeDimension xDimension;
};

dictionary WebPrintingMediaSizeRequested {
  required unsigned long yDimension;
  required unsigned long xDimension;
};

In JavaScript, a WebPrintingMediaSizeDimension returned in WebPrintingMediaSize.xDimension or yDimension is either an integer value or a WebPrintingRange dictionary such as { from: 7620, to: 21590 }. It is not used by WebPrintingMediaSizeRequested, whose two dimensions are fixed unsigned long values.

Inputs

WebPrintingMediaSizeDimension is an output capability type, not a submitPrintJob() input. To request media, supply WebPrintingMediaCollectionRequested.mediaSize with both fixed unsigned-long dimensions; do not send a range. The proposal does not define a range-to-value selection algorithm.

Outputs

The typedef occurs exactly in WebPrintingMediaSize.xDimension and yDimension, nested in returned WebPrintingMediaCollection values such as mediaColDefault and mediaColDatabase. A scalar reports one supported dimension; a WebPrintingRange reports a supported interval. These values do not independently return promises.

Errors

The current proposal does not define conversion of a returned range into one printable dimension. Treat either union branch as data to inspect. Invalid enum strings/type coercion fail Web IDL conversion with TypeError; request-media validation is separate and requires positive fixed dimensions.

Context and permission

The IDL requires a secure, isolated context. The specification also defines the web-printing Permissions Policy with default allowlist self; Chromium additionally checks an isolated context and cross-origin isolation before getPrinters(). The current proposal requires express, origin-specific consent triggered by enumeration. The exact chooser scope, persistence, and whether a later operation prompts again remain user-agent UX, not a settled web contract.

Lifecycle, cancellation, and cleanup

Ranges describe supported printer size dimensions; requested media dimensions are fixed positive values. Chromium converts its internal media-size union branch-for-branch: a Mojo range becomes WebPrintingRange, and a Mojo value becomes an unsigned long. It does not collapse a range to a scalar. Inspect fresh capability values before reuse because printer configuration can change.

Examples

function dimensionBounds(dimension) {
  return typeof dimension === "number"
    ? { min: dimension, max: dimension }
    : { min: dimension.from, max: dimension.to };
}

const attributes = await printer.fetchAttributes();
for (const media of attributes.mediaColDatabase ?? []) {
  const { xDimension, yDimension } = media.mediaSize;
  console.log(media.mediaSizeName, dimensionBounds(xDimension), dimensionBounds(yDimension));
}

// A job request uses fixed values, never a capability range.
await printer.submitPrintJob("A4 job", pdfBlob, {
  mediaCol: { mediaSize: { xDimension: 21000, yDimension: 29700 } },
  sides: "two-sided-long-edge",
});

Security and privacy

Printer names, IDs, capabilities and state can fingerprint a device and reveal printing activity. A compromised IWA could create unwanted jobs or denial of service. Minimize enumeration and polling, do not expose attributes to untrusted content, validate documents before submitting, and offer an app-level confirmation/audit trail. The spec requires isolation and consent; it does not make printer information non-sensitive.
