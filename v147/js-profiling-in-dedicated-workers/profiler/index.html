Profiler (in dedicated workers)

Limited availability

  • Chrome · main thread since 94; dedicated workers: developer trial, behind a flag
  • Edge · main thread since 94; no shipped worker signal
  • Firefox · not implemented
  • Safari · not implemented

Baseline status of the underlying API is limited (web-features entry “Profiler”); the worker exposure has no web-features entry and is not Baseline (verified 2026-09-13).

The Profiler interface of the JS Self-Profiling API is a sampling profiler for the realm it is constructed in. This page documents its complete surface as exposed inside DedicatedWorkerGlobalScope under Chrome's developer trial: the constructor, the sampleInterval and stopped attributes, the stop() method, the samplebufferfull event, and the trace dictionaries.

Developer trial — behind a flag

In dedicated workers this interface is behind chrome://flags/#enable-experimental-web-platform-features (Blink runtime features ProfilerAPIForDedicatedWorker, DocumentPolicyInDedicatedWorker, DocumentPolicyJSProfilingMode, per runtime_enabled_features.json5, fetched 2026-09-13). The surface may change before it ships; do not use in production. On the main thread the interface has shipped since Chrome 94 and is documented on MDN.

Syntax

Verbatim WebIDL from the specification (exposure widened to workers by commit e603c27, PR #88):

[Exposed=(Window, Worker)]
interface Profiler : EventTarget {
  readonly attribute DOMHighResTimeStamp sampleInterval;
  readonly attribute boolean stopped;

  constructor(ProfilerInitOptions options);
  Promise<ProfilerTrace> stop();
};

dictionary ProfilerInitOptions {
  required DOMHighResTimeStamp sampleInterval;
  required unsigned long maxBufferSize;
};

typedef DOMString ProfilerResource;

dictionary ProfilerTrace {
  required sequence<ProfilerResource> resources;
  required sequence<ProfilerFrame> frames;
  required sequence<ProfilerStack> stacks;
  required sequence<ProfilerSample> samples;
};

dictionary ProfilerSample {
  required DOMHighResTimeStamp timestamp;
  unsigned long long stackId;
};

dictionary ProfilerStack {
  unsigned long long parentId;
  required unsigned long long frameId;
};

dictionary ProfilerFrame {
  required DOMString name;
  unsigned long long resourceId;
  unsigned long long line;
  unsigned long long column;
};

Each Profiler is associated with exactly one profiling session — an abstract producer of samples with a state (started / paused / stopped), a sample interval, an agent and realm to profile, a time origin, a sample buffer size limit, and a ProfilerTrace. Sessions begin in started; a stopped session never restarts. Note the specification defines no sample() method — sampling is automatic at the session's interval; on-demand sampling exists only as the Force Sample WebDriver extension command for test automation.

Source: spec — The Profiler Interface; spec — Profiling Sessions, Automation.

new Profiler(options)

Syntaxconstructor(ProfilerInitOptions options) — called as new Profiler({ sampleInterval, maxBufferSize }) in any global where the interface is exposed; in this trial, a DedicatedWorkerGlobalScope. Construction starts the profiling session immediately (sessions begin in the started state).
Parametersoptions, a required ProfilerInitOptions: sampleInterval (required DOMHighResTimeStamp, desired milliseconds between samples, MUST be ≥ 0) and maxBufferSize (required unsigned long, sample buffer size limit in samples).
Return valueA new Profiler whose session's sample interval is set to either options.sampleInterval or “the next lowest interval supported by the UA” (read the effective value back from sampleInterval); time origin equal to the global object's time origin (in a worker, the worker's time origin); agent and realm set to the surrounding agent and current realm; an empty trace { resources: [], frames: [], stacks: [], samples: [] }.
ExceptionsRangeError — options.sampleInterval < 0. "NotAllowedError" DOMException — the global's Document Policy value for js-profiling-mode is neither "eager" nor "lazy" AND the deprecated js-profiling boolean is false; also thrown when the global is neither a Window nor a WorkerGlobalScope.
Context & exposure[Exposed=(Window, Worker)] per spec; Chrome's trial enables it in dedicated workers only (ProfilerAPIForDedicatedWorker). The worker obtains its authorizing policy from its own script response's Document-Policy header (network workers) or by inheritance from the creator document (blob:/data: workers). Feature-detect with typeof Profiler !== "undefined".
LifecycleConstructing starts sampling; the UA makes a best effort to take a sample each time the interval elapses (and MAY pause a session, e.g. for a backgrounded context; the spec recommends pausing when the browsing context is not foreground). Multiple concurrent profilers in one page SHOULD be supported. The session ends via stop() or automatically when the buffer fills (samplebufferfull).
Exampleconst p = new Profiler({ sampleInterval: 10, maxBufferSize: 10_000 }); — see examples.
CompatibilityMain thread: Chrome/Edge 94+. Dedicated workers: Chrome developer trial only — see browser compatibility.
Security & privacyGated by explicit Document Policy opt-in; without it construction throws. See security and privacy.
Source: spec — new Profiler(options); Document Policy in Workers explainer.

Profiler.sampleInterval

Syntaxreadonly attribute DOMHighResTimeStamp sampleInterval; — read as profiler.sampleInterval.
ParametersNone — a read-only IDL attribute takes no inputs; the requested interval is supplied at construction via ProfilerInitOptions.sampleInterval.
ValueA DOMHighResTimeStamp that MUST reflect the session's effective sample interval in milliseconds — the constructor may have rounded the requested value to the next lowest UA-supported interval, so this can differ from what was requested.
ExceptionsNone — reading the attribute has no failure path defined by the specification.
Context & exposureAvailable wherever the interface is exposed (here: dedicated workers under the trial); value is per-profiler, not global.
LifecycleConstant for the lifetime of the profiler; the spec defines no mechanism that changes a session's sample interval after construction.
Exampleconsole.log(profiler.sampleInterval); — log the effective interval; see examples.
CompatibilityAs the interface: see browser compatibility (BCD tracks sampleInterval from Chrome 94 on the main thread).
Security & privacyReveals only the UA's chosen sampling granularity; UAs are encouraged to be careful with extremely low intervals (< 1 ms) — see security and privacy.
Source: spec — The Profiler Interface.

Profiler.stopped

Syntaxreadonly attribute boolean stopped; — read as profiler.stopped.
ParametersNone — a read-only IDL attribute takes no inputs; its value is derived entirely from the session state.
ValueMUST be true if and only if the profiling session has state stopped. false covers both started and paused (pausing, e.g. in a background context, is not observable through this attribute).
ExceptionsNone — reading the attribute has no failure path defined by the specification.
Context & exposureAvailable wherever the interface is exposed (here: dedicated workers under the trial).
LifecycleTransitions to true exactly once — when stop() is called or the buffer fills (samplebufferfull). A stopped session MUST NOT return to started or paused.
Exampleif (!profiler.stopped) await profiler.stop(); — see examples.
CompatibilityAs the interface: see browser compatibility (BCD tracks stopped from Chrome 94 on the main thread).
Security & privacyExposes only the profiler's own state; no cross-context information — see security and privacy.
Source: spec — The Profiler Interface.

Profiler.stop()

SyntaxPromise<ProfilerTrace> stop(); — called as const trace = await profiler.stop();.
ParametersNone — the method takes no arguments; which samples are included is determined by the session's history up to the call.
Return valueA promise resolved with the session's ProfilerTrace after the UA performs any implementation-defined work to stop the session (in parallel). Samples taken after stop() is invoked SHOULD NOT be included.
ExceptionsReturns a promise rejected with an "InvalidStateError" DOMException if the session is already stopped (including after samplebufferfull auto-stop). No synchronous throw is specified.
Context & exposureAvailable wherever the interface is exposed (here: dedicated workers under the trial). The returned trace is an ordinary dictionary value — JSON-serializable and safe to postMessage() to the page.
LifecycleSets the session state to stopped synchronously (step 2), then resolves in parallel; stopped reads true immediately after the call. Terminal: the session cannot be restarted — construct a new Profiler to sample again.
Exampleconst trace = await profiler.stop(); then postMessage({ trace }) — see examples.
CompatibilityAs the interface: see browser compatibility (BCD tracks stop() from Chrome 94 on the main thread; MDN documents it at Profiler.stop()).
Security & privacyThe resolved trace contains only same-realm, CORS-same-origin-attributable frames — see security and privacy.
Source: spec — stop() method; MDN — Profiler.stop().

samplebufferfull event

Syntaxprofiler.addEventListener("samplebufferfull", handler) — Profiler inherits from EventTarget; the spec fires “a new event of type samplebufferfull” at the profiler (a plain Event; no specialized event interface or onsamplebufferfull IDL attribute is defined in the specification).
ParametersNone — the event carries no payload fields; retrieve the collected samples by calling stop() from the handler.
EffectSignals that ProfilerTrace.samples reached the session's sample buffer size limit (maxBufferSize). The take-a-sample algorithm fires the event, moves the session state to stopped, and returns without recording a further sample.
ExceptionsNone — event dispatch has no error surface; a subsequent stop() on the auto-stopped session rejects with InvalidStateError (see stop()).
Context & exposureFires on the Profiler object in the global it was constructed in — inside the worker for a worker-constructed profiler; the page never observes it directly.
LifecycleFires at most once per session, at the sampling step that finds the buffer full; afterwards stopped is true and the session is terminal.
ExampleSee the buffer-full handler in examples.
CompatibilityAs the interface: see browser compatibility. BCD's api/Profiler.json has no separate entry for the event (checked 2026-09-13); MDN documents it at samplebufferfull event.
Security & privacyReveals only that the profiler's own buffer filled; no timing beyond the sampling the caller already opted into — see security and privacy.
Source: spec — Processing Model (take a sample); MDN — samplebufferfull event.

ProfilerInitOptions

Syntaxdictionary ProfilerInitOptions { required DOMHighResTimeStamp sampleInterval; required unsigned long maxBufferSize; };
FieldssampleInterval — the application's desired sample interval in milliseconds; MUST be ≥ 0 (0 requests the fastest supported rate). maxBufferSize — the desired sample buffer size limit, in number of samples. Both are required; omitting either is a TypeError per WebIDL required-member conversion.
ResultConsumed by the constructor to configure the profiling session; the effective interval is readable back via sampleInterval.
ErrorsRangeError from the constructor when sampleInterval < 0 (see constructor exceptions).
ContextPlain dictionary argument; any object with the two properties converts (no ProfilerInitOptions global exists to construct).
LifecycleRead once during construction; later mutation of the options object has no effect on the running session.
Example{ sampleInterval: 10, maxBufferSize: 10_000 } — see examples.
CompatibilityAs the constructor: see browser compatibility.
Security & privacysampleInterval is a request, not a guarantee — UAs choosing to honor sub-millisecond intervals are urged to re-verify the cross-origin protections; see security and privacy.
Source: spec — The ProfilerInitOptions dictionary.

ProfilerTrace

Syntaxdictionary ProfilerTrace { required sequence<ProfilerResource> resources; required sequence<ProfilerFrame> frames; required sequence<ProfilerStack> stacks; required sequence<ProfilerSample> samples; }; with typedef DOMString ProfilerResource;
Fields (inputs)Not constructed by authors — the trace is produced by the UA's take-a-sample algorithm; scripts only read it. Its four lists are populated via the interning “get an element ID” algorithm (append if not present, return index), so entries are deduplicated and referenced by index.
Contentsresources — script base URLs (strings); frames — interned ProfilerFrames; stacks — interned ProfilerStack nodes forming parent-linked chains; samples — time-ordered ProfilerSamples. The format is designed to be easily and efficiently serializable, inspired by the V8 trace event and Gecko profile formats.
ErrorsNone — a returned dictionary value has no failure surface of its own; failures occur at stop().
ContextDelivered by stop()'s promise in the profiler's own global. Plain data: structured-cloneable and JSON-serializable, so a worker can postMessage() it to the page or JSON.stringify() it for upload.
LifecycleAccumulates from construction until the session stops; the buffer is bounded by maxBufferSize samples, after which samplebufferfull fires and no further samples are added.
ExampleSee the trace-decoding walk in examples.
CompatibilityAs the interface: see browser compatibility.
Security & privacyThe trace's frame inclusion rules are the API's core privacy boundary (CORS-same-origin scripts only, same realm only) — see security and privacy.
Source: spec — The ProfilerTrace Dictionary; Processing Model.

ProfilerSample

Syntaxdictionary ProfilerSample { required DOMHighResTimeStamp timestamp; unsigned long long stackId; };
Fields (inputs)Not author-constructed; each sample is created by the take-a-sample algorithm. timestamp is set to the current high resolution time relative to the session's time origin; stackId to the result of the get-a-stack-ID algorithm.
Contentstimestamp — when the sample was taken, in ms relative to the worker's time origin. stackId — index into ProfilerTrace.stacks; absent (undefined) when the execution context stack was empty, i.e. the worker was idle at the sampling instant.
ErrorsNone — plain data with no failure surface; both fields MUST return the value they were initialized to.
ContextRead from ProfilerTrace.samples; ordering follows sampling order across the session.
LifecycleOne entry appended per successful sampling step, up to maxBufferSize entries; samples after stop() SHOULD NOT be included.
ExampleIdle-time detection: samples without stackId are idle — see examples.
CompatibilityAs the interface: see browser compatibility.
Security & privacyTimestamps MUST come from the same source as High Resolution Time's clock to avoid a new side channel — see security and privacy.
Source: spec — The ProfilerSample Dictionary; Processing Model.

ProfilerStack

Syntaxdictionary ProfilerStack { unsigned long long parentId; required unsigned long long frameId; };
Fields (inputs)Not author-constructed; built by the recursive get-a-stack-ID algorithm, which walks the execution context stack from outermost to innermost and interns one node per (parent, frame) pair.
ContentsframeId — index into ProfilerTrace.frames for this node's frame. parentId — index of the caller's stack node in ProfilerTrace.stacks; absent for a stack's outermost frame. Frames the algorithm filters out (other-realm or non-attributable) are skipped, splicing their callees onto the surviving parent.
ErrorsNone — plain data with no failure surface; both fields MUST return the value they were initialized to.
ContextRead from ProfilerTrace.stacks; reconstruct a full call stack by following parentId links from a sample's stackId to the root.
LifecycleInterned on first observation and reused by every later sample sharing the same call path (the get-an-element-ID dedup step), keeping traces compact.
ExampleThe stack-walk loop in examples.
CompatibilityAs the interface: see browser compatibility.
Security & privacyStack nodes only ever reference frames that passed the same-realm and CORS-same-origin checks — see security and privacy.
Source: spec — The ProfilerStack Dictionary; Processing Model.

ProfilerFrame

Syntaxdictionary ProfilerFrame { required DOMString name; unsigned long long resourceId; unsigned long long line; unsigned long long column; };
Fields (inputs)Not author-constructed; built by the get-a-frame-ID algorithm from the execution context's function instance and its ScriptOrModule.
Contentsname — the function instance name. resourceId — index into ProfilerTrace.resources (the script's base URL); line / column — 1-based position where the function is defined. The three optional members are absent for frames without an attributable script (e.g. builtins invoked from accessible script keep only attribution rules described in the processing model).
ErrorsNone — plain data with no failure surface; all fields MUST return the value they were initialized to.
ContextRead from ProfilerTrace.frames via ProfilerStack.frameId. In a worker trace, resources typically name the worker script and its importScripts()/module imports.
LifecycleInterned once per distinct frame (component-wise equality) and referenced by index thereafter.
ExampleFrame-name resolution in examples.
CompatibilityAs the interface: see browser compatibility.
Security & privacyFrames from scripts served CORS-cross-origin (muted errors) return no frame at all, and cross-realm contexts are filtered — the frame list is the enforcement point; see security and privacy.
Source: spec — The ProfilerFrame Dictionary; Processing Model.

Examples

Complete worker-side session with the buffer-full path handled (the worker script's response carries Document-Policy: js-profiling-mode=lazy):

// worker.js — dedicated worker, Chrome developer trial
if (typeof Profiler === "undefined") {
  self.postMessage({ trace: null }); // no trial / no policy — degrade honestly
} else {
  const profiler = new Profiler({ sampleInterval: 10, maxBufferSize: 10_000 });
  console.log(profiler.sampleInterval); // effective interval (may be rounded)

  profiler.addEventListener("samplebufferfull", async () => {
    // Session auto-stopped: state is already `stopped`.
    // stop() would now reject with InvalidStateError — the trace was
    // finalized when the buffer filled, so collect it defensively:
    console.warn("profile buffer full", profiler.stopped); // true
  });

  const result = doHeavyWork();

  let trace = null;
  if (!profiler.stopped) {
    trace = await profiler.stop();
  }
  self.postMessage({ result, trace });
}

Decoding a trace: resolve a sample's stack by walking parentId links, then map frames to names and resources:

function stackFor(trace, sample) {
  const names = [];
  for (let id = sample.stackId; id !== undefined;
       id = trace.stacks[id].parentId) {
    const frame = trace.frames[trace.stacks[id].frameId];
    const resource = frame.resourceId !== undefined
      ? trace.resources[frame.resourceId] : "(builtin)";
    names.push(`${frame.name || "(anonymous)"} @ ${resource}:${frame.line ?? "?"}`);
  }
  return names; // innermost → outermost
}

const idle = trace.samples.filter((s) => s.stackId === undefined).length;
console.log(`worker idle in ${idle}/${trace.samples.length} samples`);

Security and privacy

  • Opt-in construction. The constructor is gated on the global's Document Policy (js-profiling-mode / deprecated js-profiling) — a worker whose script response carries no authorizing header (and, for blob:/data: workers, whose creator held none) cannot profile at all.
  • Cross-origin script contents. Frames must come from CORS-same-origin script (classic-script muted errors check); builtins are attributed to accessible invoking script only. The API exposes no new insight into cross-origin script beyond manual instrumentation.
  • Cross-origin execution. The realm check filters execution contexts whose realm differs from the session's: a worker profiler observes only its own worker realm.
  • Timing. Sample timestamps use the same clock source as High Resolution Time, avoiding a new high-resolution timing vector; UAs supporting sub-millisecond sampleInterval values are urged to re-verify the protections.
Source: spec — Privacy and Security; Document Policy in Workers explainer.
