Timeline Named Range "scroll"

Baseline status: not tracked separately for this keyword

  • Chrome · 147
  • Edge · 147
  • Firefox · 159
  • Safari · 26.5

webstatus.dev has no web-feature for the scroll range keyword on its own: it is not among the BCD keys of the parent Scroll-driven animations feature, which webstatus.dev reports as Baseline Newly available since 2026-10-27 (queried 2026-11-22). That parent status is not a claim about this keyword. For the keyword itself, BCD css.types.timeline-range-name.scroll records Chrome 147, Firefox 159 and Safari 26.5 (versions listed above; see Browser compatibility). Older engines that support scroll-driven animations but not this keyword drop the whole animation-range declaration, so feature-detect it.

A new scroll named range keyword for view timeline animations, extending the existing set of timeline range names (cover, contain, entry, exit, entry-crossing, exit-crossing). The scroll range spans the entire scroll extent of the scroll container — from the very start to the very end — rather than being limited to the portion where the subject element is visible.

Syntax

scroll is a new value of the <timeline-range-name> type, so it is accepted wherever that type is. Grammar quoted verbatim from the CSS Scroll-driven Animations Level 1 editor’s draft (fetched 2026-11-22):

animation-range-start:
  [ normal | <length-percentage> | <timeline-range-name> <length-percentage>? ]#
animation-range-end:
  [ normal | <length-percentage> | <timeline-range-name> <length-percentage>? ]#
animation-range:
  [ <'animation-range-start'> <'animation-range-end'>? ]#

<keyframe-selector> = from | to | <percentage [0,100]> | <timeline-range-name> <percentage>

Value

From the spec definition of scroll: it “represents the full range of the scroll container on which the view progress timeline is defined.”

  • scroll 0% — the startmost scroll position of the scroll container underlying the view progress timeline.
  • scroll 100% — the endmost scroll position of that scroll container.
  • Start and end sides resolve in the scroll container’s writing mode.
  • In the animation-range shorthand, animation-range: scroll alone sets the end to scroll 100% (an omitted end copies the start’s range name).
  • Only meaningful on a view progress timeline (view() or view-timeline-name); a scroll progress timeline has no named ranges, so keyframes attached to scroll <percentage> are ignored there.
Source: scroll-animations-1 §scroll range; §animation-range; §<timeline-range-name> (fetched 2026-11-22).

Examples

Progress bar across the whole scroller

@keyframes grow {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

/* lets the sibling bar see the timeline name */
.reader  { timeline-scope: --article; }
/* the view timeline's subject, inside the scroller */
.article { view-timeline: --article block; }

.progress-bar {
  transform-origin: left;
  animation: grow linear both;
  animation-timeline: --article;
  /* whole scroll extent, not just while .article is visible */
  animation-range: scroll 0% scroll 100%;
}

Feature detection

@supports (animation-range: scroll 0% scroll 100%) {
  .progress-bar { animation-range: scroll 0% scroll 100%; }
}

if (CSS.supports("animation-range", "scroll 0% scroll 100%")) {
  // the scroll named range is available
}
Source: scroll-animations-1 §scroll range; pattern as used by the live full-range-fade demo.
