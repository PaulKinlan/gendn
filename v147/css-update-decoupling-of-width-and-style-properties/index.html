CSS update: decoupling of Width and Style properties

Limited availability

  • Chrome · decoupled in 147
  • Firefox · border/outline earlier; column-rule in 147
  • Safari · border/outline earlier; column-rule fix in WebKit
  • Edge · no independent record

This behavior change carries no Baseline badge: webstatus.dev has no web-feature tracking the width/style decoupling (queries for border-width, outline-width and column-rule on 2026-10-04 return none). The underlying properties are themselves Baseline Widely available via the borders and outlines web-features. Per-engine status above is from the ChromeStatus API record (“aligns Chrome with Firefox and WebKit, which have already implemented this behavior”), Firefox bug 1998285 (RESOLVED FIXED, target 147 Branch) and WebKit bug 304940 (RESOLVED FIXED). See the full table.

Chrome 147 aligns with Firefox and Safari: the computed values of border-width, outline-width, and column-rule-width are now independent of their corresponding *-style properties. Previously Chrome forced the computed width to 0px when style was none or hidden; now the author-specified width is always preserved in the computed value, and for outline-width and column-rule-width it is also what getComputedStyle() returns. border-width still resolves to the used value — 0px when no border is painted.

what changed

PropertyBefore Chrome 147Chrome 147+
border-width Computed value forced to 0px when border-style: none Computed value reflects the authored value regardless of border-style
outline-width Computed value forced to 0px when outline-style: none Computed value and resolved value both reflect the authored value
column-rule-width Computed value forced to 0px when column-rule-style: none Computed value and resolved value both reflect the authored value

Note the asymmetry: for border-width only the computed value is decoupled. The spec now says explicitly that its resolved value (what getComputedStyle() returns) is the used value, and “if the border-style corresponding to a given border-width is none or hidden, then the used width is 0”. For outline-width and column-rule-width no such used-value clause exists, so their resolved values follow the computed value and report the authored width.

Source: ChromeStatus — CSS update: decoupling of Width and Style properties; CSS Backgrounds & Borders Level 3 §3.3 (resolved-value clause); verified 2026-10-04.

syntax

The value grammar of the three properties is unchanged. What changed is each property’s Computed value line: the trailing special case (“; zero if the … style is none or hidden”) was removed by csswg-drafts PR #11913 (“Adjust *-width zero value special cases per WG resolution”, resolving issue #11494). Value definitions and the current computed-value lines, quoted verbatim from the editor’s drafts (read 2026-10-04):

<line-width> = <length [0,∞]> | thin | medium | thick

The new normative clause added for borders only:

The resolved value for the border-width properties is the used value. If the border-style corresponding to a given border-width is none or hidden, then the used width is 0.
Source: css-backgrounds-3 §3.3; css-ui-4 outline-width; css-multicol-1 §crw; css-gaps-1 gap decoration width; diff verified against PR #11913 (commit 5e14aa0), 2026-10-04.

why it matters

Pages that read getComputedStyle().outlineWidth or columnRuleWidth — for example, to compute layout or animate from a base state — now get the authored value reliably across Chrome, Firefox, and Safari. For border-width the readback is unchanged (0px with border-style: none, because the resolved value is the used value), but its computed value no longer collapses to zero: since the Animation type of these properties is “by computed value”, toggling only border-style no longer makes border-width itself jump 0px → 4px, so a registered transition: border-width is no longer triggered by a pure style toggle, and values inherited with inherit carry the authored width.

Source: ChromeStatus summary; Animation-type and computed-value lines in css-backgrounds-3 §3.3.

examples

/* CSS */
.card {
  border-style: none;   /* no border painted */
  border-width: 4px;    /* preserved in the computed value since Chrome 147 */
  outline-style: none;
  outline-width: 6px;
}
// JavaScript
const cs = getComputedStyle(document.querySelector(".card"));

// outline-width (and column-rule-width): the resolved value now
// reflects the author-specified value even while the style is "none".
cs.outlineWidth;   // Chrome 147+: "6px"   (previously "0px")

// border-width still resolves to the USED value, which is 0 when no
// border is painted — only its COMPUTED value was decoupled.
cs.borderWidth;    // "0px" while border-style is none (unchanged)
Source: value behavior per the ChromeStatus summary and css-backgrounds-3 §3.3; snippet gendn-derived (labelled accordingly), not executed.
