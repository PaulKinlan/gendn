Lazy loading for video and audio elements

Limited availability

  • Chrome · 150 (148–149 partial)
  • Edge · 150
  • Firefox · not shipped
  • Safari · not shipped

The loading-lazy-media web-feature is Limited availability — not Baseline — on webstatus.dev (checked 2026-08-30): Chrome, Chrome Android, and Edge became available at 150 (2026-06/07); Firefox and Safari have not shipped. Per-version detail is in the browser compatibility table below. The long-Baseline loading-lazy web-feature covers only <img> and <iframe> — do not conflate the two.

Adds the loading attribute to <video> and <audio> elements, letting browsers defer media resource loading until the element is near the viewport — the same mechanism already available for <img> and <iframe>.

Status has moved since this page’s milestone — and cross-browser support is still limited In Chrome 147 (this page’s milestone) the feature was in developer trial behind chrome://flags/#enable-experimental-web-platform-features. Since then the spec change merged — WHATWG HTML PR #11980 now defines loading as an attribute common to all media elements — and Chrome shipped it: partial in 148–149 (not honored for <source> children, crbug 514611050), full in 150; the Blink runtime feature LazyLoadVideoAndAudio is stable in runtime_enabled_features.json5 at trunk (all verified 2026-08-30). Firefox and Safari have not shipped — keep an IntersectionObserver fallback for them.

Syntax

The merged spec makes loading one of “the attributes common to all media elements” and defines it as a lazy loading attribute — the same enumerated attribute <img> and <iframe> use:

<!-- keyword values: "lazy" or "eager" (the default) -->
<video loading="lazy">   <video loading="eager">
<audio loading="lazy">   <audio loading="eager">
Keywords and states (spec, verbatim semantics)
lazy → Lazy state“Used to defer fetching a resource until some conditions are met.”
eager → Eager state“Used to fetch a resource immediately; the default state.” The attribute’s missing value default and invalid value default are both the Eager state — omitting the attribute or giving it any unknown value behaves as eager.

Reflected in the DOM as HTMLMediaElement’s inherited content attribute; feature-detect with 'loading' in HTMLVideoElement.prototype (see the examples). One spec-level anti-tracking rule inherited from the shared definition: when scripting is disabled, lazy loading is disabled (the “will lazy load element steps” return false), so scroll position cannot be tracked through deferred fetches.

Source: WHATWG HTML §2.5.7 Lazy loading attributes and §4.8.11 media elements, fetched 2026-08-30.

why it exists

Since Chrome 76, <img loading="lazy"> and <iframe loading="lazy"> have let browsers skip fetching off-screen resources until the user scrolls close to them. The same pattern has never applied to <video> and <audio>, which start loading their source files as soon as the parser encounters them regardless of position on the page. Long-form pages with multiple embedded videos pay a large up-front network cost even when most users never scroll to those media elements. The loading attribute on media elements closes this gap and aligns behaviour across all embeddable resources.

Source: chromestatus summary (API record) and WHATWG HTML PR #11980, May 2026.

the attribute

Attributeloading
Elements<video>, <audio>
loading="eager"Default. Load the resource immediately, same as current behavior without the attribute.
loading="lazy"Defer resource loading until the element is within the browser's lazy-loading distance threshold from the viewport. The exact threshold is browser-defined and may vary by network conditions.

When the loading attribute is in the Lazy state, the merged spec (fetched 2026-08-30) requires all of the following — note the preload rule below corrects an earlier version of this page, which was written from the open PR and understated it:

Data fetchingDeferred until the element’s lazy load resumption steps are invoked (the element approaches the viewport per the shared lazy-loading machinery).
preload interaction“When the loading attribute is in the Lazy state, it takes precedence over the preload attribute by deferring data fetching” — i.e. even preload="auto"/"metadata" hints are deferred until resumption; the hinted behavior then applies.
poster interaction“If the poster attribute is present and the loading attribute is in the Lazy state, the user agent must defer loading the poster image source data until the element’s lazy load resumption steps are invoked.”
Autoplay“If the autoplay attribute is present and the loading attribute is in the Lazy state, the user agent must also defer starting playback (and any associated network requests autoplay can introduce) until the element’s lazy load resumption steps are invoked.”
Switching to eagerChanging the attribute’s state to Eager runs the element’s stored lazy load resumption steps immediately — loading proceeds as if the element had come into range.
load eventA lazy media element does not delay the window load event; only Eager-state elements (or scripting-disabled documents) set the delaying-the-load-event flag.
Source: WHATWG HTML §4.8.11 (merged spec text), fetched 2026-08-30; previously cited from the then-open PR #11980.

Examples

Basic lazy video

<video loading="lazy" controls>
  <source src="feature-demo.mp4" type="video/mp4">
  <source src="feature-demo.webm" type="video/webm">
</video>

Lazy audio

<audio loading="lazy" controls>
  <source src="podcast-episode.mp3" type="audio/mpeg">
  <source src="podcast-episode.ogg" type="audio/ogg">
</audio>

Combining with preload

<!-- Best practice for a long page with many videos:
     lazy defers fetching; preload="metadata" limits initial load to just
     duration/dimensions once the element enters the threshold zone. -->
<video loading="lazy" preload="metadata" controls>
  <source src="explainer.mp4" type="video/mp4">
</video>

Switching a lazy element to eager

// The loading content attribute is reflected on media elements, so
// flipping it to "eager" runs the element's stored lazy load resumption
// steps immediately — loading proceeds as if it had scrolled into range.
const video = document.querySelector('video[loading="lazy"]');
const playButton = document.querySelector("#play-now"); // e.g. <button id="play-now">
playButton.addEventListener("click", () => {
  video.loading = "eager"; // spec: state change to Eager resumes loading now
});

Detecting support

const supportsLazyMedia = 'loading' in HTMLVideoElement.prototype;
if (!supportsLazyMedia) {
  // Fall back to IntersectionObserver-based lazy loading
}
