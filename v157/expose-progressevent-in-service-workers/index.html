Expose ProgressEvent in service workers

Chrome 157 exposes the ProgressEvent interface inside service workers, closing a long-standing implementation gap: the XMLHttpRequest Standard declares the interface [Exposed=(Window,Worker)] — every worker type — but Chromium exposed it only in Window, dedicated workers, and shared workers. Firefox and Safari already expose it everywhere. Code that constructs progress events (lengthComputable, loaded, total) can now be reused unchanged in service workers.

this feature is documented on MDN

MDN: ProgressEvent

MDN’s reference covers the interface in full — constructor, lengthComputable/loaded/total, examples, specifications, and browser compatibility including worker support (verified substantive, 2026-11-01). This Chrome 157 change is an exposure fix on that same documented surface; gendn doesn’t duplicate the API reference here.

// In a ServiceWorkerGlobalScope (Chrome 157+, Firefox, Safari):
if ("ProgressEvent" in self) {
  const e = new ProgressEvent("progress", {
    lengthComputable: true, loaded: 512, total: 1024,
  });
}
