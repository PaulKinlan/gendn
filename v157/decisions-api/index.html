Decisions API

Exposes window.DecisionModel, a Built-in AI primitive for fast, single-pass, on-device semantic decision-making (“Semantic If”). Instead of autoregressively decoding tokens like generative language models, DecisionModel scores natural-language text against a developer-defined schema of boolean, choice, and score questions in one forward pass, returning strict-schema labels, calibrated per-option probabilities, a normalized confidence score, and continuous ordinal score values.

Limited availability — Developer trial behind a flag in Chrome 157 (desktop only; not yet enabled by default); Firefox and Safari have no signal or implementation

why it exists

Web apps and agentic UIs frequently need fast, deterministic semantic branching over unstructured text—turning a search query into filter toggles, routing a command palette entry to a tool, checking a draft for missing details or accidental PII before submission, or classifying non-standard form fields. Keyword rules break on paraphrasing and typos; cloud endpoints add network round trips, recurring costs, and off-device data exposure; and running a generative LLM (such as LanguageModel) to decode JSON token-by-token is 10–50× heavier than needed and lacks calibrated option probabilities. DecisionModel brings compact, non-autoregressive “System 1” decision models (such as Laya/Jev-style encoders) into the browser, evaluating an entire schema of questions in a single forward pass in tens or low hundreds of milliseconds.

Source: Decisions API explainer; ChromeStatus 5155080092385280.

Syntax

The complete WebIDL implemented in Chromium’s decision_model.idl:

enum DecisionModelQuestionType {
  "boolean",
  "choice",
  "score"
};

dictionary DecisionModelOption {
  required DOMString label;
  DOMString description;
};

dictionary DecisionModelQuestion {
  required DOMString id;
  required DOMString prompt;
  required DecisionModelQuestionType type;
  sequence<DecisionModelOption> options;
};

// DevTrial-only backend selector (crbug.com/565849508)
enum DecisionModelBackend {
  "embedding-gemma-v1",
  "language-model",
  "laya-en-wint8",
  "laya-ml-wint8"
};

dictionary DecisionModelCreateCoreOptions {
  DecisionModelBackend devTrialBackend;
  sequence<LanguageModelExpected> expectedInputs;
  sequence<DecisionModelQuestion> questions;
  PerformancePreference preference = "auto";
};

dictionary DecisionModelCreateOptions : DecisionModelCreateCoreOptions {
  AbortSignal signal;
  CreateMonitorCallback monitor;
};

dictionary DecisionModelDecideOptions {
  AbortSignal signal;
};

dictionary DecisionModelDecision {
  DOMString id;
  DOMString label;
  float score;
  float confidence;
  record<DOMString, float> probabilities;
};

typedef record<DOMString, DecisionModelDecision> DecisionModelResult;

[
  Exposed(Window AIDecisionModelAPI, Worker AIDecisionModelAPIForWorkers),
  RuntimeEnabled=AIDecisionModelAPI,
  SecureContext
]
interface DecisionModel {
  static Promise<Availability> availability(
    optional DecisionModelCreateCoreOptions options = {}
  );
  static Promise<DecisionModel> create(
    optional DecisionModelCreateOptions options = {}
  );
  Promise<DecisionModelResult> decide(
    DOMString input,
    optional DecisionModelDecideOptions options = {}
  );
  undefined destroy();
  readonly attribute PerformancePreference preference;
};

Schema & creation option types

Inputs & schema grammar. A decision schema is passed via DecisionModelCreateCoreOptions (and its subclass DecisionModelCreateOptions):

DecisionModel.availability(options)

Inputs. Accepts an optional DecisionModelCreateCoreOptions dictionary (default {}). Unlike create(), questions may be omitted for a generic readiness check; if questions is supplied, it still undergoes full schema validation (non-empty, ≤16 questions, valid option counts, unique IDs/labels).

Outputs. Returns a Promise<Availability> resolving to one of the standard Built-in AI Availability strings: "available", "downloadable", "downloading", or "unavailable". Resolves immediately to "unavailable" (rather than rejecting) when the "language-model" Permissions Policy is blocked or when expectedInputs specifies any non-"text" modality.

Source: Blink DecisionModel::availability(); Decisions API explainer.

DecisionModel.create(options)

Inputs. Accepts DecisionModelCreateOptions with a required non-empty questions array (1–16 questions), optional expectedInputs, preference (default "auto"), DevTrial-only devTrialBackend, optional signal (AbortSignal), and optional monitor (CreateMonitorCallback) invoked with a monitor exposing downloadprogress events.

Outputs. Returns a Promise<DecisionModel> resolving to a live DecisionModel session bound to the browser’s AIDecisionModel Mojo remote once availability is verified and any required model download completes. When model availability is "downloadable" or "downloading" in a Window context, transient user activation is required before initiating download.

Source: Blink DecisionModel::create() & CreateDecisionModelClient; Decisions API explainer.

DecisionModel.prototype.decide(input, options)

Inputs. Accepts a required DOMString input (must contain non-whitespace characters) and an optional DecisionModelDecideOptions dictionary containing an optional per-call signal (AbortSignal), which is combined with the session’s creation signal.

Outputs. Evaluates input against every question in the session’s schema in a single pass and returns a Promise<DecisionModelResult> (a plain JS record keyed by each question’s id, mapping to a DecisionModelDecision dictionary).

Source: Blink DecisionModel::decide(); Decisions API explainer.

DecisionModel.prototype.destroy()

Inputs. Takes no arguments.

Outputs. Returns undefined synchronously. Signals the session’s internal abort manager (aborting any in-flight decide() promises) and resets the underlying decision_model_remote_ Mojo pipe, releasing model session resources. Subsequent decide() calls reject/throw a session-destroyed error; calling destroy() again is safe.

Source: Blink DecisionModel::destroy(); Decisions API explainer.

DecisionModel.prototype.preference

Inputs. Read-only attribute (no setter).

Outputs. Returns the PerformancePreference enum value (for example "auto", "speed", or "capability"; default "auto") captured from DecisionModelCreateCoreOptions.preference when the session was created.

Source: Blink decision_model.idl; decision_model.cc.

Evaluation options & result types (DecisionModelDecideOptions, DecisionModelDecision, DecisionModelResult)

Inputs & outputs. DecisionModelDecideOptions carries an optional AbortSignal signal for cancelling a single decide() call. DecisionModelResult is a WebIDL record<DOMString, DecisionModelDecision> keyed by each question’s id. Each DecisionModelDecision contains:

  • id (DOMString): matches the question’s id.
  • label (DOMString): winning option label (strictly guaranteed to be one of the schema’s option labels, or "true" / "false" for boolean questions).
  • confidence (float): normalized certainty from 0 (uniform chance across options) to 1 (full certainty), letting apps choose thresholds to act automatically or prompt the user.
  • probabilities (record<DOMString, float>): calibrated per-option probabilities in [0.0, 1.0] keyed by option label.
  • score (float, present for score questions): continuous expected ordinal value from 0 to options.length - 1.
Source: Blink decision_model.idl; decision_model.cc; Decisions API explainer.

Errors, validation, and rejection paths

  • TypeError (schema & input validation): Thrown/rejected by DecisionModel.availability() and DecisionModel.create() for missing/empty questions (in create()), >16 questions, blank or duplicate DecisionModelQuestion.id, blank prompt, options provided on a boolean question, choice option count outside 2–26, score level count outside 2–11, or blank/duplicate DecisionModelOption.label. Also thrown by decide() when input is empty or whitespace-only, or when an invalid BCP-47 language tag is passed in expectedInputs.
  • NotAllowedError (DOMException): Rejected by DecisionModel.create() when the "language-model" Permissions Policy is disabled in the document, or when model download is required ("downloadable" / "downloading") without transient user activation.
  • NotSupportedError (DOMException): Rejected by DecisionModel.create() when expectedInputs requests a non-"text" modality (such as image or audio), or when model availability resolves to "unavailable" on the current device/backend (including unsupported devTrialBackend or preference combinations).
  • InvalidStateError (DOMException): Rejected by create() if the browser cannot create the session or calculate token size, and by decide() after destroy() has been called or the Mojo session disconnects.
  • QuotaExceededError: Rejected when the schema or decide() input exceeds the on-device model’s context window (carrying quota and requested counts).
  • AbortError (or custom signal.reason): Rejected by create() or decide() if the creation DecisionModelCreateOptions.signal or per-call DecisionModelDecideOptions.signal aborts.
Source: Blink decision_model.cc; decision_model.h.

Context, exposure, and Permissions Policy

DecisionModel requires a secure context ([SecureContext]). In Chromium’s DevTrial, it is exposed on Window when AIDecisionModelAPI is enabled (desktop Windows, macOS, Linux, ChromeOS; not Android or iOS) and on Worker only when AIDecisionModelAPIForWorkers (status: "test") is additionally enabled. Both availability() and create() check the "language-model" Permissions Policy feature during the DevTrial phase, so cross-origin iframes require explicit delegation via allow="language-model". Feature-detect with "DecisionModel" in self.

Source: Blink decision_model.idl; runtime_enabled_features.json5; decision_model.cc.

Lifecycle and state transitions

  1. Availability check: Call DecisionModel.availability(schema) to inspect whether weights are "available", "downloadable", "downloading", or "unavailable" without triggering a download.
  2. Session creation & download monitoring: Call DecisionModel.create({ ...schema, monitor, signal }) (inside a user gesture if a download is needed). The browser validates the schema, downloads weights if necessary (emitting downloadprogress events on the monitor), and binds an AIDecisionModel session.
  3. Repeated stateless evaluations: Call await model.decide(input, { signal }) as many times as needed. Each evaluation is stateless—prior calls do not accumulate conversation history—and can be cancelled independently via per-call AbortSignal.
  4. Explicit cleanup: Call model.destroy() (or abort the creation signal) when the schema is no longer needed to cancel pending requests and release native model session memory immediately rather than waiting for garbage collection.
Source: Blink decision_model.cc; Decisions API explainer.

Examples

Interactive Semantic-If router & complete DecisionModel workflow

async function evaluateSearchQuery(queryText, abortSignal) {
  if (!("DecisionModel" in self)) {
    return { supported: false, reason: "DecisionModel unavailable" };
  }

  // DecisionModelCreateCoreOptions with boolean, choice, and score questions
  const schema = {
    expectedInputs: [{ type: "text", languages: ["en"] }],
    preference: "auto",
    questions: [
      {
        id: "pet_friendly",
        type: "boolean",
        prompt: "Does the traveler require pet-friendly accommodations?"
      },
      {
        id: "property_type",
        type: "choice",
        prompt: "Which property type best matches the request?",
        options: [
          { label: "hotel", description: "Standard hotel, resort, or inn" },
          { label: "rental", description: "Entire apartment, house, or cabin" },
          { label: "any", description: "No specific property type mentioned" }
        ]
      },
      {
        id: "price_tier",
        type: "score",
        prompt: "Rate target price tier from 0 (budget) to 3 (luxury).",
        options: [
          { label: "0", description: "Budget or inexpensive stay" },
          { label: "1", description: "Moderate mid-range stay" },
          { label: "2", description: "Upscale or premium property" },
          { label: "3", description: "Luxury five-star resort" }
        ]
      }
    ]
  };

  const status = await DecisionModel.availability(schema);
  if (status === "unavailable") {
    return { supported: false, reason: "Model unavailable for schema" };
  }

  // DecisionModelCreateOptions: optional devTrialBackend, monitor, and signal
  const model = await DecisionModel.create({
    ...schema,
    signal: abortSignal,
    monitor(m) {
      m.addEventListener("downloadprogress", (e) => {
        console.debug(`Model download: ${Math.round(e.loaded * 100)}%`);
      });
    }
  });

  try {
    // Inspect readonly preference and run single-pass decide() with DecisionModelDecideOptions
    const activePreference = model.preference;
    const result = await model.decide(queryText, { signal: abortSignal });
    // result is DecisionModelResult: record<id, DecisionModelDecision>
    return {
      supported: true,
      preference: activePreference,
      petFriendly: result.pet_friendly.confidence > 0.85
        ? result.pet_friendly.label === "true"
        : null,
      propertyType: result.property_type.label,
      propertyProbabilities: result.property_type.probabilities,
      priceScore: result.price_tier.score
    };
  } finally {
    model.destroy();
  }
}

Security and privacy

  • On-device, stateless inference: Inputs passed to decide() are evaluated locally and are not sent over the network, persisted to disk, or used to train models. The API has no access to cross-origin browsing history or user profile state.
  • Schema/input separation: Untrusted user text passed to decide(input) is kept distinct from developer-defined questions and options, so prompt injection cannot synthesize out-of-schema labels.
  • User agency & confirmation: High confidence is a probabilistic signal, not authorization. Applications MUST still require explicit user confirmation before executing state-changing or sensitive actions.
  • Download gating & fingerprinting posture: Initiating a model download via create() requires transient user activation, and cross-origin iframes are blocked unless delegated the "language-model" Permissions Policy. The explainer notes that timing and probability precision should remain bounded to limit device fingerprinting.
Source: Decisions API explainer (Security & Privacy); Blink decision_model.cc.
