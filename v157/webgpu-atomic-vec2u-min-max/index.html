WebGPU: atomic-vec2u-min-max

Adds the optional WebGPU adapter feature "atomic-vec2u-min-max" and matching WGSL enable extension enable atomic_vec2u_min_max;, allowing shaders in compute and fragment stages to perform 64-bit unsigned integer atomic minimum and maximum writes on atomic<vec2<u32>> (atomic<vec2u>) storage buffers via atomicStoreMin() and atomicStoreMax() — without requiring full 64-bit scalar integer support in WGSL.

Limited availability — enabled by default in Chrome 157 on adapters with hardware 64-bit atomic min/max support; Firefox and Safari do not ship "atomic-vec2u-min-max" yet

  • Chrome · 157 (desktop, Android, WebView; hardware-dependent; dev trial in 155)
  • Edge · Mirrors Chromium (157, hardware-dependent)
  • Firefox · No release yet (participated in W3C WG PR #5610)
  • Safari · Positive signal via PR #5610; no release yet

The parent webgpu web-feature is Limited availability on webstatus.dev (checked 2026-11-27), and no separate web-features entry exists for "atomic-vec2u-min-max". BCD api/GPUSupportedFeatures.json does not yet list "atomic-vec2u-min-max", and MDN’s GPUSupportedFeatures page does not document this feature or WGSL’s atomicStoreMin()/atomicStoreMax() built-ins — so gendn publishes a complete spec-backed reference here.

why it exists

GPU compute rasterizers (such as software visibility buffers for virtual geometry), dense point-cloud splatting, and key-value reduction kernels routinely need to compare a 32-bit sort key (such as Z-depth) and atomically store an associated 32-bit payload (such as a triangle ID or packed color) in one indivisible memory update. Standard WGSL only provides 32-bit atomic<u32> and atomic<i32> and has no scalar u64 type. Splitting depth and payload across two 32-bit buffers introduces race conditions, while packing both into a single 32-bit word sacrifices depth precision. Hardware backends differ in which 64-bit atomic operations they support — in particular, Metal 2.4+ restricts 64-bit atomics to void-returning min and max on uint64_t. Scoping this optional feature to 64-bit unsigned atomicStoreMin and atomicStoreMax over the existing 8-byte vec2<u32> surrogate type delivers broad cross-API reach across Vulkan, Metal, and Direct3D 12.

Source: ChromeStatus 4882016087703552; GPUWeb 64-bit atomics proposal; gpuweb/gpuweb#5071.

Syntax

The feature adds one enum value to WebGPU’s GPUFeatureName (W3C WebGPU §25.25) and pairs it with one WGSL enable directive, one 64-bit surrogate atomic storage type, and two void-returning WGSL built-in functions (W3C WGSL §17.8.6):

// WebGPU WebIDL enum addition (GPUFeatureName)
"atomic-vec2u-min-max"

// JavaScript adapter check & device opt-in
adapter.features.has("atomic-vec2u-min-max")
await adapter.requestDevice({ requiredFeatures: ["atomic-vec2u-min-max"] })

// WGSL enable directive (top of shader module)
enable atomic_vec2u_min_max;

// WGSL storage buffer declaration (read_write storage only; 8-byte size & alignment)
@group(0) @binding(0)
var<storage, read_write> target: array<atomic<vec2<u32>>>; // alias: array<atomic<vec2u>>

// WGSL built-in functions (compute and fragment stages only; no return value)
fn atomicStoreMin(atomic_ptr: ptr<storage, atomic<vec2<u32>>, read_write>, v: vec2<u32>)
fn atomicStoreMax(atomic_ptr: ptr<storage, atomic<vec2<u32>>, read_write>, v: vec2<u32>)

This reference covers all three surfaces of the contract: the "atomic-vec2u-min-max" WebGPU adapter feature, the enable atomic_vec2u_min_max; WGSL extension and atomic<vec2u> storage type, and the atomicStoreMin() and atomicStoreMax() built-in functions.

Source: W3C WebGPU §25.25; W3C WGSL §4.1.1; W3C WGSL §17.8.6; Dawn/Tint wgsl.def.

WebGPU feature: GPUFeatureName "atomic-vec2u-min-max"

Inputs. Pass the string "atomic-vec2u-min-max" to adapter.features.has("atomic-vec2u-min-max") to probe hardware and driver support on a GPUAdapter, and include "atomic-vec2u-min-max" in the requiredFeatures sequence of GPUDeviceDescriptor when calling adapter.requestDevice({ requiredFeatures: ["atomic-vec2u-min-max"] }). There are no companion feature dependencies in W3C WebGPU §3.6.1.2.

Outputs. adapter.features.has("atomic-vec2u-min-max") returns true when the adapter exposes the capability (note the hyphenated JS name versus the underscored WGSL name). When granted by adapter.requestDevice(), device.features.has("atomic-vec2u-min-max") is true and device.createShaderModule() accepts WGSL shaders declaring enable atomic_vec2u_min_max;. In Blink (dawn_enum_conversions.cc), V8GPUFeatureName::Enum::kAtomicVec2UMinMax maps directly to Dawn’s wgpu::FeatureName::AtomicVec2uMinMax.

Source: W3C WebGPU §25.25; Blink gpu_supported_features.idl; Blink dawn_enum_conversions.cc.

WGSL enable extension: enable atomic_vec2u_min_max; and atomic<vec2<u32>>

Inputs & declaration rules. A WGSL shader module must declare enable atomic_vec2u_min_max; at global scope before any declaration that uses atomic<vec2<u32>> (or its predeclared alias atomic<vec2u>). Note that in Dawn/Tint (wgsl.def), atomic_vec2u_min_max is registered as a WGSL extension (requiring enable atomic_vec2u_min_max; and the WebGPU device feature "atomic-vec2u-min-max"), not as an automatic navigator.gpu.wgslLanguageFeatures entry.

Outputs & 64-bit word layout. Per W3C WGSL §6.2.8, atomic<vec2<u32>> has size 8 bytes and alignment 8 bytes (matching vec2<u32>) and represents an unsigned 64-bit integer in little-endian word order:

  • Component 0 (v[0] / v.x): the 32 least significant bits (payload / tie-breaker).
  • Component 1 (v[1] / v.y): the 32 most significant bits (primary comparison key, e.g., Z-depth).
  • Numeric value: value64 = 2^32 × v[1] + v[0]. Swapping .x and .y compares the payload before the sort key — always place the sort key in .y (index 1) and the payload in .x (index 0).

Address space constraint. If a variable’s store type is or contains atomic<vec2<u32>>, the variable must be declared in the storage address space with read_write access mode (var<storage, read_write>). Declaring atomic<vec2u> in the workgroup address space, in a read-only storage buffer, or in textures is forbidden and fails shader creation. Expressions cannot evaluate to an atomic type.

Source: W3C WGSL §4.1.1; W3C WGSL §6.2.8 Atomic Types; Dawn/Tint wgsl.def.

Built-ins: atomicStoreMin() and atomicStoreMax()

Inputs. Both functions require enable atomic_vec2u_min_max; and accept two arguments in compute or fragment shader stages:

WGSL 64-bit atomic min/max built-in functions (W3C WGSL §17.8.6 & Tint wgsl.def)
FunctionParametersReturn value & atomic effect
atomicStoreMin(atomic_ptr, v)atomic_ptr: ptr<storage, atomic<vec2<u32>>, read_write>, v: vec2<u32>No return value (void). Atomically loads old, computes new64 = min(2^32 × old[1] + old[0], 2^32 × v[1] + v[0]), and stores vec2u(lo32(new64), hi32(new64)) back to atomic_ptr.
atomicStoreMax(atomic_ptr, v)atomic_ptr: ptr<storage, atomic<vec2<u32>>, read_write>, v: vec2<u32>No return value (void). Atomically loads old, computes new64 = max(2^32 × old[1] + old[0], 2^32 × v[1] + v[0]), and stores vec2u(lo32(new64), hi32(new64)) back to atomic_ptr.

Outputs & differences from 32-bit atomics. Unlike 32-bit atomicMin() and atomicMax() (which return the previous u32/i32 value), atomicStoreMin() and atomicStoreMax() do not return a value and cannot be used in an expression. Furthermore, no other WGSL atomic built-ins — including atomicLoad, atomicStore, atomicAdd, atomicSub, atomicExchange, or atomicCompareExchangeWeak — are overloaded for atomic<vec2u>. Initialize the buffer before the pass (with commandEncoder.clearBuffer() for max-reductions or a compute clear pass writing vec2u(0xffffffffu, 0xffffffffu) for min-reductions) and read the resolved 64-bit pairs in a subsequent pass that binds the same GPUBuffer as plain array<vec2u>.

Backend mappings. Per the GPUWeb proposal, Tint lowers atomicStoreMin / atomicStoreMax to SPIR-V OpAtomicUMin / OpAtomicUMax (Vulkan), MSL atomic_min_explicit / atomic_max_explicit (Metal), and HLSL SM 6.6 InterlockedMin / InterlockedMax (Direct3D 12).

Source: W3C WGSL §17.8.6; Dawn/Tint wgsl.def; GPUWeb 64-bit atomics proposal.

Errors, validation failures, and fallbacks

  • Unsupported adapter (requestDevice rejection): Calling adapter.requestDevice({ requiredFeatures: ["atomic-vec2u-min-max"] }) when adapter.features.has("atomic-vec2u-min-max") is false rejects with a TypeError per WebGPU’s requestDevice() feature-validation rules. Always probe adapter.features.has("atomic-vec2u-min-max") first and fall back to packed 32-bit atomic<u32> or a multi-pass/render-pipeline depth buffer when absent.
  • Missing enable directive or missing device feature (shader-creation error): Using atomic<vec2u>, atomicStoreMin(), or atomicStoreMax() without enable atomic_vec2u_min_max; — or compiling a shader with enable atomic_vec2u_min_max; on a GPUDevice that did not enable "atomic-vec2u-min-max" — fails WGSL compilation and reports an error message in shaderModule.getCompilationInfo() plus a WebGPU validation error on the device.
  • Disallowed address space, stage, or atomic op (shader-creation error): Declaring var<workgroup> x: atomic<vec2u>, calling atomicStoreMin/atomicStoreMax from a vertex shader, assigning their void return value (let old = atomicStoreMin(...)), or calling atomicLoad/atomicStore/atomicMin/atomicMax on an atomic<vec2u> pointer all produce shader-creation errors.
Source: W3C WebGPU §25.25; W3C WGSL §4.1.1; W3C WGSL §6.2.8; W3C WGSL §17.8.6.

Context, exposure, and hardware requirements

GPUSupportedFeatures and navigator.gpu are exposed in Window and Worker (including DedicatedWorkerGlobalScope) in secure contexts (HTTPS or loopback) only. Because "atomic-vec2u-min-max" is an optional hardware-backed feature, Chrome 157 only populates it in adapter.features when the active GPU driver satisfies backend 64-bit storage-buffer atomic requirements:

  • Vulkan: Vulkan 1.2 shaderBufferInt64Atomics or the VK_KHR_shader_atomic_int64 device extension.
  • Metal: Metal 2.4+ with 64-bit atomic min/max support (for example Apple GPU family 9 and modern macOS/iOS GPUs supporting MSL 64-bit atomic_min_explicit/atomic_max_explicit).
  • Direct3D 12: Shader Model 6.6 with D3D12_FEATURE_D3D12_OPTIONS1::Int64ShaderOps and 64-bit integer atomics.

Software fallback adapters or older mobile GPUs without 64-bit buffer atomics will return false from adapter.features.has("atomic-vec2u-min-max") even on Chrome 157+.

Source: Blink gpu_supported_features.idl; GPUWeb 64-bit atomics proposal (Backend Requirements); ChromeStatus 4882016087703552.

Lifecycle, memory scope, and synchronization

Feature availability is immutable for a given GPUAdapter / GPUDevice pair: once enabled at requestDevice() time, "atomic-vec2u-min-max" stays active until device.destroy() or device loss. Inside WGSL, atomic<vec2<u32>> lives exclusively in the storage address space and therefore has a QueueFamily memory scope (W3C WGSL §6.2.8). Every call to atomicStoreMin or atomicStoreMax counts as an atomic modification (even when the existing value wins the comparison) and is mutually ordered per atomic object across invocations in the dispatch or render pass. Because there is no atomicLoad on atomic<vec2u>, separate the atomic write pass from the non-atomic readback/resolve pass using WebGPU pass boundaries (two compute passes or a compute/fragment pass followed by a resolve pass reading the same GPUBuffer as array<vec2u>) so WebGPU inserts the required storage-buffer barrier automatically.

Source: W3C WGSL §6.2.8 Atomic Types; W3C WGSL §17.8.6.

Examples

Interactive word-order inspector & WebGPU feature check

async function initAtomicVec2uDevice() {
  if (!navigator.gpu) {
    return { supported: false, reason: "WebGPU unavailable" };
  }

  const adapter = await navigator.gpu.requestAdapter();
  if (!adapter) {
    return { supported: false, reason: "No WebGPU adapter" };
  }

  const hasFeature = adapter.features.has("atomic-vec2u-min-max");
  const device = await adapter.requestDevice(
    hasFeature ? { requiredFeatures: ["atomic-vec2u-min-max"] } : {}
  );

  return {
    supported: device.features.has("atomic-vec2u-min-max"),
    device,
  };
}
Source: W3C WebGPU §25.25; Blink gpu_supported_features.idl.

WGSL compute shader using enable atomic_vec2u_min_max;, atomicStoreMin, and atomicStoreMax

enable atomic_vec2u_min_max;

struct Sample {
  pixelIndex: u32,
  payloadId: u32,
  depthBits: u32,
};

@group(0) @binding(0) var<storage, read> samples: array<Sample>;
@group(0) @binding(1) var<storage, read_write> minVisBuffer: array<atomic<vec2u>>;
@group(0) @binding(2) var<storage, read_write> maxVisBuffer: array<atomic<vec2u>>;

@compute @workgroup_size(64)
fn splat(@builtin(global_invocation_id) gid: vec3u) {
  if (gid.x >= arrayLength(&samples)) {
    return;
  }
  let s = samples[gid.x];

  // Component 0 (.x) = low 32 bits (payload), component 1 (.y) = high 32 bits (sort key).
  // Both built-ins return void; read results in a subsequent pass binding array<vec2u>.
  let packed = vec2u(s.payloadId, s.depthBits);
  atomicStoreMin(&minVisBuffer[s.pixelIndex], packed);
  atomicStoreMax(&maxVisBuffer[s.pixelIndex], packed);
}
Source: W3C WGSL §4.1.1; W3C WGSL §6.2.8; W3C WGSL §17.8.6.

Compiling and validating the shader in JavaScript

async function createAtomicVisPipeline(device, wgslSource) {
  if (!device.features.has("atomic-vec2u-min-max")) {
    throw new Error("Device was not created with requiredFeatures: ['atomic-vec2u-min-max']");
  }

  const module = device.createShaderModule({ code: wgslSource });
  const info = await module.getCompilationInfo();
  const errors = info.messages.filter((m) => m.type === "error");
  if (errors.length > 0) {
    throw new Error(errors.map((m) => `${m.lineNum}: ${m.message}`).join("\n"));
  }

  return device.createComputePipelineAsync({
    layout: "auto",
    compute: { module, entryPoint: "splat" },
  });
}
Source: W3C WebGPU §25.25; W3C WGSL §17.8.6.

Security and privacy

"atomic-vec2u-min-max" executes within WebGPU’s existing bounds-checked storage-buffer memory model and secure-context boundary. Like other hardware-dependent optional entries in adapter.features, presence or absence of "atomic-vec2u-min-max" adds one bit of GPU capability entropy (for example distinguishing GPUs supporting Vulkan shaderBufferInt64Atomics, Metal Apple9+/2.4+, or D3D12 SM 6.6 from older devices), consistent with existing WebGPU adapter feature probing. Out-of-bounds buffer indexing remains subject to WebGPU’s robust buffer access protections, and the feature adds no network, storage, or cross-origin capability.

Source: W3C WebGPU §25.25; W3C WGSL §6.2.8; ChromeStatus 4882016087703552.
