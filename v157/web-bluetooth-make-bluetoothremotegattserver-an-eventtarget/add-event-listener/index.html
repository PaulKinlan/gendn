BluetoothRemoteGATTServer.addEventListener()

Registers a listener for events of a given type on a BluetoothRemoteGATTServer. The method is inherited unchanged from EventTarget. It became available on the server when Chromium CL 8363084 made the interface inherit from EventTarget, as specified by Web Bluetooth PR #672. See the overview shipping note for which Chrome release contains it.

syntax

server.addEventListener(type, callback)
server.addEventListener(type, callback, options)
server.addEventListener(type, callback, useCapture)

Declared in the DOM Standard as:

undefined addEventListener(DOMString type, EventListener? callback, optional (AddEventListenerOptions or boolean) options = {});
Source: DOM §2.7 EventTarget IDL (verbatim); receiver per Web Bluetooth PR #672 IDL.

parameters

addEventListener() takes three arguments. The third can be an options dictionary or a boolean:

ParameterTypeMeaning
typeDOMStringThe event type to listen for. The spec defines one type for this target: "maxwritewithoutresponsesizechanged", which ships as a separate feature. Any other string is accepted and only matches events you dispatch yourself.
callbackEventListener?A function, or an object with a handleEvent(event) method. null is accepted and makes the call do nothing.
options.captureboolean, default falsePart of the listener’s identity. The server has no parent, so there is no capture or bubble path and capture listeners run in the at-target phase. Passing a boolean instead of a dictionary sets only capture.
options.onceboolean, default falseRemove the listener automatically after its first invocation.
options.passiveboolean, no defaultIf true, a call to preventDefault() in the listener is ignored.
options.signalAbortSignalWhen the signal aborts, the listener is removed. If it is already aborted, the listener is not added.
Source: DOM AddEventListenerOptions; DOM “add an event listener”; PR #672 event definition.

return value

addEventListener() returns undefined. The effect is that an entry is added to the server’s event listener list. If an entry with the same type, callback and capture is already registered, the call does nothing, so attaching the same function twice does not make it run twice.

Source: DOM “add an event listener” algorithm.

exceptions

  • The method itself does not throw for any type string or a null callback.
  • TypeError if callback is not callable and not an object, or if options.signal is not an AbortSignal (Web IDL conversion).
  • TypeError if called with a this that is not an EventTarget, for example EventTarget.prototype.addEventListener.call({}, …).
  • On a browser without the inheritance change, server.addEventListener is undefined and calling it throws TypeError: server.addEventListener is not a function. Check EventTarget.prototype.isPrototypeOf(BluetoothRemoteGATTServer.prototype) first.
  • An exception thrown by your listener is reported to the global error handler (window.onerror). It does not propagate to the code that caused the event.
Source: DOM EventTarget IDL; Web IDL; DOM dispatch (“report the exception”).

context

Available on any BluetoothRemoteGATTServer in a secure-context Window, whether or not the server is connected. You get the receiver from device.gatt, after requestDevice() (user gesture and chooser) or getDevices(). The gatt getter returns null in the spec unless the origin may use GATT on that device. The document must be allowed the "bluetooth" Permissions Policy feature. No extra permission is needed to add a listener.

Source: PR #672 IDL ([Exposed=Window, SecureContext]); Web Bluetooth gatt getter.

lifecycle

  • device.gatt is the same object for the life of the BluetoothDevice, so a listener survives disconnect() and connect(). Add it once, not on every reconnect.
  • The server is not in the Bluetooth tree. A listener on the server receives only events targeted at the server: it never sees gattserverdisconnected (fired at the device) or characteristicvaluechanged (fired at characteristics).
  • A listener stops running when it is removed with removeEventListener(), when its signal aborts, after one run if once is set, or when the document is torn down.
  • Listeners added during a dispatch do not run for that same dispatch.
Source: Web Bluetooth §Bluetooth tree; DOM dispatch; CL 8363084.

examples

const device = await navigator.bluetooth.requestDevice({
  filters: [{ services: ["heart_rate"] }],
});
const server = device.gatt;

if (EventTarget.prototype.isPrototypeOf(BluetoothRemoteGATTServer.prototype)) {
  const controller = new AbortController();

  // The connection-level event designed for this target (separate feature).
  server.addEventListener("maxwritewithoutresponsesizechanged", () => {
    console.log("max write size:", server.maxWriteWithoutResponseSize);
  }, { signal: controller.signal });

  // Disconnects are still fired at the device: stop listening there.
  device.addEventListener("gattserverdisconnected", () => controller.abort(), { once: true });
}

await server.connect();
Source: written for this page against the DOM addEventListener() and PR #672 IDL; not executed against real hardware.

security and privacy

Adding a listener gives no access to device data and does not connect to the device or keep it connected. Any UA-fired event the listener receives is one the page could already observe through the server’s attributes. Web Bluetooth’s chooser, secure-context requirement, service allowlist, blocklist and Permissions Policy are unchanged.

Source: ChromeStatus API record (security risks).
