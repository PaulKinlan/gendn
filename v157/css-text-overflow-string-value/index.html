CSS text-overflow: <string> value

Adds support for a CSS <string> value on the text-overflow property (for example, text-overflow: " (more)" or text-overflow: ""), letting authors replace the default clip or ellipsis (…) overflow cue with any custom string while keeping the underlying DOM text intact for selection, copy-paste, and assistive technology.

Limited availability — custom <string> ellipses shipped in Firefox 9, Safari 27.3, and Chrome 157 (base text-overflow is Baseline Widely available since 2018-01-29)

  • Chrome · 157 (desktop, Android, WebView; single-value <string>)
  • Edge · Mirrors Chromium (157)
  • Firefox · 9 (single-value & two-value <string>)
  • Safari · 27.3 (per BCD; WebKit PR #72631)

The custom-ellipses web-feature is currently Limited availability on webstatus.dev (recording Firefox 9), while base text-overflow is Baseline Widely available since 2018-01-29. BCD css/properties/text-overflow.json records Firefox 9 and Safari 27.3 for string, and still lags Chrome as false (checked 2026-11-27) even though Chrome 157 enables TextOverflowString by default.

what Chrome 157 actually does

Verified against Blink’s ConsumeTextOverflow() in css_parsing_utils.cc, runtime_enabled_features.json5, and the text-overflow-string-* WPT suite:

  • Single-value <string> only in Chrome 157: Blink’s ConsumeTextOverflow() parses a single token — clip, ellipsis, or a CSS <string> when TextOverflowString is enabled (status: "stable"). Chrome 157 does not implement CSS Overflow 4’s two-value start/end syntax (such as text-overflow: "< " " >"); two-value declarations remain invalid in Chrome and Safari and are currently Firefox-only per BCD two_value_syntax.
  • Required overflow prerequisites: Just like ellipsis, text-overflow: <string> applies only to block containers overflowing in the inline progression direction with overflow set to a value other than visible (for example, overflow: hidden or overflow: clip alongside white-space: nowrap).
  • Empty string vs. clip: Specifying an empty string (text-overflow: "") hides overflowing glyphs at character boundaries rather than slicing mid-character like clip. If the container lacks space to render the custom string itself, the string is clipped per CSS Overflow 4 §4.1 ellipsing details.
  • Progressive enhancement & detection: Always precede a custom <string> declaration with text-overflow: ellipsis so non-supporting browsers fall back cleanly, or test with CSS.supports("text-overflow", '" (more)"').
.truncated-title {
  overflow: hidden;
  white-space: nowrap;
  /* Fallback for browsers without text-overflow: <string> */
  text-overflow: ellipsis;
  /* Chrome 157+, Firefox 9+, Safari 27.3+ */
  text-overflow: " (more)";
}
const supportsCustomString = CSS.supports("text-overflow", '" (more)"');
const supportsTwoValue = CSS.supports("text-overflow", '"< " " >"');
console.log({ supportsCustomString, supportsTwoValue });
Source: Blink css_parsing_utils.cc; CSS Overflow Module Level 4 §4.1 text-overflow; WPT text-overflow-string-*.
