Popup Capability Delegation

Extends Capability Delegation so a Service Worker handling a trusted notificationclick event can delegate a single-use transient "popup" capability to a same-origin WindowClient via client.postMessage(message, { delegate: "popup" }). The receiving tab can then call window.open() within 1 second to spawn an auxiliary popup that shares in-memory state via window.opener without being blocked by the popup blocker, maintaining a strict 1:1 click-to-popup invariant.

Limited availability — Developer trial behind a flag in Chrome 157 (desktop and Android; not yet enabled by default); Firefox and Safari have no signal or implementation

  • Chrome · Developer trial behind flag in Chrome 157+ (desktop & Android; not yet shipped enabled by default)
  • Edge · No release (not enabled by default)
  • Firefox · No signal

why it exists

In the legacy document-bound Notifications API (new Notification()), clicking a notification runs onclick inside the originating Window with transient user activation, so the app can call window.open() to launch a fast auxiliary preview or compose popup that shares live in-memory state via window.opener. With Service Worker Notifications (registration.showNotification()), notificationclick runs in the background worker without a DOM. Calling Clients.openWindow() opens an isolated top-level tab requiring a cold-start bootstrap with no window.opener, while posting a message to an existing tab leaves that tab without user activation so window.open() is blocked. Popup Capability Delegation closes this gap by transferring a single-use, time-bounded "popup" capability explicitly to one chosen WindowClient.

Source: Popup Capability Delegation explainer; ChromeStatus 5091965583622144.

Syntax

The explainer proposes adding ClientPostMessageOptions to W3C Service Workers (Chromium implements delegate on Blink’s shared PostMessageOptions dictionary accepted by Client.postMessage()):

dictionary ClientPostMessageOptions : StructuredSerializeOptions {
  DOMString? delegate;
};

partial interface Client {
  undefined postMessage(any message, optional ClientPostMessageOptions options = {});
};

This reference covers all three parts of the contract: Client.postMessage() with ClientPostMessageOptions.delegate, the Service Worker notificationclick transient "popup" token, and client window.open() consumption of DELEGATED_CAPABILITY_TIMESTAMPS["popup"].

Source: Popup Capability Delegation explainer (Web IDL); Blink client.idl; post_message_options.idl.

Client.postMessage(message, { delegate: "popup" }) & ClientPostMessageOptions.delegate

Inputs. Call client.postMessage(message, options) from a ServiceWorkerGlobalScope with options matching ClientPostMessageOptions (Blink PostMessageOptions): optional transfer (from StructuredSerializeOptions) and delegate: "popup" (a space-separated ASCII capability list parsed by PostMessageHelper::MapStringToDelegatedCapability(); in Service Workers, only "popup" is accepted when CapabilityDelegationPopup is enabled).

Outputs. Returns undefined synchronously. When valid, Blink consumes the Service Worker’s transient "popup" capability token via ServiceWorkerGlobalScope::ConsumePopupCapabilityDelegation(), attaches DelegatedCapability::kPopup to the BlinkTransferableMessage, and queues the message event on the target WindowClient’s navigator.serviceWorker.

Source: Blink service_worker_client.cc; post_message_helper.cc; Popup Delegation explainer.

notificationclick transient "popup" capability token

Inputs. Granted automatically by the user agent when dispatching a trusted Service Worker notificationclick NotificationEvent (no JavaScript constructor or option creates this token). Other Service Worker events such as push or fetch do not grant a "popup" token.

Outputs. Activates a single-use transient "popup" capability on the worker (AllowPopupCapabilityDelegation(); proposed sender lifespan ≤5 seconds or until event.waitUntil() settles). Notably, this token is tracked separately from the worker’s window-interaction allowance used by await client.focus(), so a single notification click can both focus an existing client tab and delegate one "popup" capability to it.

Source: Popup Delegation explainer (§Specification Changes); Blink service_worker_global_scope.cc.

Client window.open() consumption & DELEGATED_CAPABILITY_TIMESTAMPS["popup"]

Inputs. When the target same-origin WindowClient receives the delegated message event on navigator.serviceWorker, the user agent records the current high-resolution timestamp in DELEGATED_CAPABILITY_TIMESTAMPS["popup"] with a 1-second lifespan. The client window must be foreground/visible (brought forward via await client.focus() in the Service Worker) and not sandboxed without allow-popups.

Outputs. Calling window.open(url, target, windowFeatures) succeeds if the window has either standard transient user activation or an unexpired DELEGATED_CAPABILITY_TIMESTAMPS["popup"] entry, returning a synchronous WindowProxy wired with window.opener. Opening the popup performs unified consumption: it immediately clears both the "popup" delegated timestamp and any transient user activation so a second consecutive window.open() is blocked. If the client needs async data before rendering, open window.open("about:blank", ...) synchronously inside the message handler before awaiting network fetches so the 1-second token does not expire.

Source: Popup Delegation explainer (WHATWG HTML changes); WICG Capability Delegation spec.

Errors, restrictions, and blocked calls

  • NotSupportedError (DOMException): Thrown by Client.postMessage() when:
    • delegate names any capability other than "popup" from a Service Worker (or when CapabilityDelegationPopup is disabled).
    • The target Client is not a WindowClient (e.g., a dedicated or shared worker client: “Delegation of ‘popup’ is only supported for WindowClient.”).
    • A Window attempts frame-to-frame delegation via window.postMessage(msg, { delegate: "popup" }) (“Delegation of ‘popup’ is only supported from Service Workers.”, verified by WPT).
    • delegate is passed to unsupported messaging channels such as MessagePort, BroadcastChannel, or Worker.postMessage().
  • NotAllowedError (DOMException): Thrown by Client.postMessage(msg, { delegate: "popup" }) if called outside an active notificationclick capability window, after the ≤5-second lifespan expires, or on a second delegation attempt after the single-use token was already consumed.
  • window.open() returns null (blocked): Occurs if the 1-second client token expired before window.open() ran, if a first window.open() already consumed the token, if the client tab was not focused/visible (await client.focus() omitted), or if the target frame is sandboxed without allow-popups.
Source: Blink service_worker_client.cc; post_message_helper.cc; Popup Delegation explainer.

Context, exposure, and feature detection

Client.postMessage() runs in ServiceWorkerGlobalScope (secure contexts only, same-origin clients only) and delivers to a same-origin WindowClient. Feature detection cannot rely on checking "postMessage" in Client.prototype because Client.postMessage() has existed since Chrome 40; instead, wrap client.postMessage(payload, { delegate: "popup" }) in try/catch and fall back to self.clients.openWindow(url) (or an in-tab route) if NotSupportedError is thrown or if the client reports window.open() === null.

Source: Blink client.idl; Popup Delegation explainer.

Lifecycle and timing bounds

  1. Notification click: User clicks a Service Worker notification; browser dispatches trusted notificationclick and activates a single-use "popup" token (≤5s / waitUntil() lifetime) plus window-focus allowance.
  2. Focus foreground client: Service Worker selects an open same-origin WindowClient (excluding unloaded or BFCache-frozen clients) and awaits client.focus() so the tab is visible and foregrounded.
  3. Delegate via postMessage(): Service Worker calls client.postMessage(payload, { delegate: "popup" }), consuming the sender token immediately (preventing re-use or multi-client fan-out).
  4. Receive & open popup: Browser sets DELEGATED_CAPABILITY_TIMESTAMPS["popup"] (1-second expiry) when dispatching the message event on navigator.serviceWorker. The handler calls window.open() synchronously (or within 1 second), consuming both the delegated token and any transient activation, and receives a live WindowProxy. If the document is unloaded or enters BFCache, any pending token is destroyed or expires.
Source: Popup Delegation explainer (Lifecycle & Mitigations); Blink service_worker_client.cc.

Examples

Interactive delegation lab & Service Worker + WindowClient flow

// Service Worker (sw.js): delegate "popup" from notificationclick to an existing WindowClient
function registerNotificationClickHandler(swScope) {
  swScope.addEventListener("notificationclick", (event) => {
    event.notification.close();
    const emailId = event.notification.data?.emailId ?? "latest";

    event.waitUntil((async () => {
      const clients = await swScope.clients.matchAll({ type: "window", includeUncontrolled: true });
      const client = clients.find((c) => c.visibilityState === "visible") || clients[0];

      if (!client) {
        await swScope.clients.openWindow(`/inbox?open=${encodeURIComponent(emailId)}`);
        return;
      }

      // 1. Focus the client tab so window.open() passes foreground visibility checks.
      await client.focus();

      // 2. Delegate the single-use "popup" capability (ClientPostMessageOptions).
      try {
        client.postMessage(
          { action: "open_email_preview", emailId },
          { delegate: "popup" }
        );
      } catch (err) {
        // Fallback when CapabilityDelegationPopup is unavailable (NotSupportedError)
        // or the transient notificationclick capability expired (NotAllowedError).
        await swScope.clients.openWindow(`/preview?id=${encodeURIComponent(emailId)}`);
      }
    })());
  });
}

// Client Window (main.js): consume DELEGATED_CAPABILITY_TIMESTAMPS["popup"] via window.open()
function registerClientMessageHandler(swContainer, win) {
  swContainer.addEventListener("message", (event) => {
    if (event.data?.action !== "open_email_preview") return;

    // Call window.open() synchronously inside the message handler before the 1s token expires.
    const url = `/preview?id=${encodeURIComponent(event.data.emailId)}`;
    const popup = win.open(url, "email_preview", "popup=yes,width=650,height=500");
    if (!popup) {
      // Blocked (expired token, sandbox without allow-popups, or browser popup setting)
      win.location.assign(url);
    }
  });
}

Security and privacy

  • Strict 1:1 click-to-popup invariant: One trusted notificationclick grants one transient token, consumed by one Client.postMessage(..., { delegate: "popup" }) call and then consumed by at most one window.open() call (also clearing transient user activation), preventing popup amplification or loops.
  • Same-origin & no forwarding: Service Workers can only target same-origin WindowClients, and a receiving window cannot re-delegate "popup" to another frame (frame-to-frame popup delegation throws NotSupportedError).
  • Double-sided expiry & no ambient worker activation: Sender capability expires within ≤5 seconds (scoped to the notification click, not ambient worker state so push/fetch cannot hijack it), and the client window’s DELEGATED_CAPABILITY_TIMESTAMPS["popup"] expires after 1 second.
  • Popunder & sandbox defenses: Popup blockers still enforce foreground visibility (requiring await client.focus()) and iframe sandbox restrictions without allow-popups remain enforced.
  • Privacy: Tokens are strictly ephemeral in-memory timestamps with zero persistent storage or cross-origin identifiers.
Source: Popup Delegation explainer (Security & Privacy); WPT frame-to-frame block test.
