Ship anchor-visible and anchor-valid, and deprecate the plural versions

Ships the CSSWG-renamed singular keywords anchor-visible and anchor-valid on the CSS position-visibility property, keeps the previously shipped plural anchors-visible working as a deprecated alias that serializes as anchor-visible (with a one-per-document DevTools deprecation warning), and provides a zero-JavaScript dual-write migration path across browsers.

Limited availability — singular anchor-visible and anchor-valid ship in Chrome 157, Safari 27, and Firefox 162; plural spellings remain deprecated aliases during the transition

  • Chrome · 157 (singular anchor-visible & anchor-valid; anchors-visible aliased & deprecated)
  • Edge · 157 (mirrors Chromium)
  • Firefox · 162 for singular (147 shipped plural anchors-visible & anchors-valid)
  • Safari · 27 for singular (26.2 shipped plural anchors-visible & anchors-valid)

On webstatus.dev, anchor-positioning (singular values) is Limited availability (Chrome/Edge 157, Safari 27; Firefox pending 162) and anchor-positioning-position-visibility-plurals tracks the deprecated plural forms. BCD css/properties/position-visibility.json marks anchors-visible and anchors-valid as deprecated: true (checked 2026-11-27). Because MDN’s position-visibility page does not document the plural-to-singular rename, deprecation warning, alias serialization, or dual-write migration pattern (and still lists Initial value: anchors-visible in its formal definition table), gendn publishes a complete spec- and source-backed reference here.

why it exists

Earlier drafts of CSS Anchor Positioning used plural keyword names — anchors-visible and anchors-valid — reflecting an initial design that quantified over every anchor an element referenced. Once the CSSWG resolved that position-visibility evaluates only the single default anchor box, the plural spelling became actively misleading. In w3c/csswg-drafts#10201 (anchors-valid) and w3c/csswg-drafts#10201 (anchors-visible), the working group renamed both keywords to singular anchor-valid and anchor-visible and permitted user agents to treat the legacy plurals as aliases during migration. Chrome 157 ships the canonical singular names and deprecates (without removing) anchors-visible so existing stylesheets continue to work while authors migrate cleanly.

Source: ChromeStatus 5136123851571200; w3c/csswg-drafts#10201.

Syntax

Normative CSS Anchor Positioning 1 §6.6 grammar alongside Blink’s actual Chrome 157 parser grammar (verified in longhands_custom.cc):

/* Normative CSS Anchor Positioning 1 §6.6 */
position-visibility = always | [ anchor-valid || anchor-visible || no-overflow ]

/* Legacy aliases permitted by spec (optional per UA):
   anchors-valid   -> legacy alias of anchor-valid
   anchors-visible -> legacy alias of anchor-visible */

/* Blink Chrome 157 parser (PositionVisibility::ParseSingleValue):
   always | [ anchor-valid || [ anchor-visible | anchors-visible ] || no-overflow ]
   Initial value: anchor-visible */

This reference covers both parts of the Chrome 157 rename contract: canonical singular keywords (anchor-visible and anchor-valid) and plural deprecation, alias serialization, and cross-browser divergence (anchors-visible and anchors-valid).

Source: CSS Anchor Positioning 1 §6.6; Blink longhands_custom.cc.

Canonical singular keywords: anchor-visible and anchor-valid

Inputs & outputs. With PositionVisibilitySingularValues enabled in Chrome 157, position-visibility adopts singular spellings as its canonical values and initial value:

  • anchor-visible (new canonical initial value): Hides an absolutely positioned box (computes visibility to force-hidden) when its default anchor box is invisible or completely clipped by intervening boxes between the anchor and the positioned element’s containing block. Unspecified position-visibility computes to "anchor-visible" (replacing "anchors-visible" from Chrome 125–156).
  • anchor-valid: Hides the positioned box (force-hidden) when the box references its default anchor box and that default anchor cannot be resolved to an acceptable anchor element. See gendn’s full position-visibility: anchor-valid reference for all resolution rules.
  • Composition & canonical order: Both singular values compose freely with each other and with no-overflow (for example, position-visibility: anchor-valid anchor-visible no-overflow), always serializing in grammar order: anchor-valid, then anchor-visible, then no-overflow.
Source: CSS Anchor Positioning 1 §6.6; Blink longhands_custom.cc.

Plural alias, deprecation warning, and anchors-valid divergence

Inputs & outputs. Blink’s Chrome 157 migration behavior differs sharply between the two legacy plural spellings because anchors-visible shipped in Chrome 125 while anchors-valid was reverted before shipping:

Errors, invalid combinations, and the dual-write migration pattern

  • Duplicate visibility slot error: Because anchors-visible and anchor-visible occupy the same visibility slot in Blink’s parser, combining both in one declaration (position-visibility: anchors-visible anchor-visible) is a parse error and causes the entire declaration to be dropped.
  • anchors-valid dropped in Blink: Including anchors-valid anywhere in a multi-keyword declaration (such as position-visibility: anchors-valid anchors-visible) fails parsing in Chrome 157 and drops the whole declaration.
  • Zero-JS dual-write migration pattern: Write the legacy plural declaration first, followed immediately by the singular declaration in the same rule block. Browsers that only know plural spellings (Chrome 125–156, Firefox 147–161, Safari 26.2–26.x) keep line 1 and drop line 2; browsers that know singular spellings (Chrome 157+, Safari 27+, Firefox 162+) override line 1 with line 2 via normal CSS cascade ordering. Note that on Chrome 157, parsing line 1 (anchors-visible) still triggers the one-per-document deprecation console warning; if zero console warnings are desired in Chrome 157+, wrap the legacy fallback inside @supports not (position-visibility: anchor-visible).
Source: Blink longhands_custom.cc; CSS Anchor Positioning 1 §6.6.

Context, exposure, and CSSOM behavior

The singular keywords and the anchors-visible alias work in all CSS contexts (author stylesheets, inline style attributes, Shadow DOM, @supports, CSS.supports(), and CSSOM style.positionVisibility / getComputedStyle()) on absolutely positioned elements, with no secure context, permission, or user activation required. Scripts that previously compared getComputedStyle(el).positionVisibility === "anchors-visible" will see "anchor-visible" starting in Chrome 157 and should check for "anchor-visible" (or accept both during cross-browser rollout).

Source: Blink longhands_custom.cc; CSS Anchor Positioning 1 §6.6.

Serialization and deprecation lifecycle

Parse-time canonicalization. Blink rewrites anchors-visible to CSSValueID::kAnchorVisible directly inside PositionVisibility::ParseSingleValue(). As a result, aliasing is immediately observable in CSSOM: setting el.style.setProperty("position-visibility", "anchors-visible") reads back as "anchor-visible" from both el.style.getPropertyValue("position-visibility") and getComputedStyle(el).positionVisibility.

Deprecation is not removal. Per ChromeStatus 5136123851571200, this launch explicitly ships the singular names and deprecates anchors-visible without removing it. Removal of the plural alias will be tracked as a separate future intent once use-counter telemetry (kCSSValuePositionVisibilityAnchorsVisible) drops sufficiently.

Source: ChromeStatus 5136123851571200; Blink longhands_custom.cc.

Examples

Live demo & CSSOM alias-serialization probe

function probePositionVisibilityRename() {
  const el = document.createElement("div");
  el.style.setProperty("position-visibility", "anchors-visible");
  const pluralSerialized = el.style.getPropertyValue("position-visibility");

  return {
    singularVisible: CSS.supports("position-visibility", "anchor-visible"),
    singularValid: CSS.supports("position-visibility", "anchor-valid"),
    pluralVisible: CSS.supports("position-visibility", "anchors-visible"),
    pluralValid: CSS.supports("position-visibility", "anchors-valid"),
    aliasesPluralToSingular: pluralSerialized === "anchor-visible",
    pluralSerialized,
  };
}
Source: CPS conformance suite; Blink longhands_custom.cc.

Dual-write CSS migration (with warning-free @supports option)

/* Pattern 1: Concise cascade dual-write (works across Chrome 125–157+, Firefox 147+, Safari 26.2+) */
.tooltip {
  position: fixed;
  position-anchor: --help-btn;
  position-area: top;
  position-visibility: anchors-visible;
  position-visibility: anchor-visible;
}

/* Pattern 2: Zero deprecation-warning variant for Chrome 157+ */
.tooltip-quiet {
  position: fixed;
  position-anchor: --help-btn;
  position-area: top;
  position-visibility: anchor-valid anchor-visible;
}

@supports not (position-visibility: anchor-visible) {
  .tooltip-quiet {
    position-visibility: anchors-valid anchors-visible;
  }
}
Source: CSS Anchor Positioning 1 §6.6; Blink longhands_custom.cc.

Security and privacy

Renaming position-visibility keywords from plural to singular (anchors-visible → anchor-visible, anchors-valid → anchor-valid) and aliasing anchors-visible is a pure CSS parser and CSSOM serialization change. It introduces no new permissions, storage, network, or cross-origin capabilities, and adds no fingerprinting surface beyond standard CSS.supports() and CSSOM serialization probing.

Source: ChromeStatus 5136123851571200; CSS Anchor Positioning 1 §6.6.
