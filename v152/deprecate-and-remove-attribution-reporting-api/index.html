Deprecate and remove: Attribution Reporting API

Chrome 152 begins the stepped removal of the Attribution Reporting API (ARA), a Privacy Sandbox API designed to measure ad conversions without third-party cookies. Following Chrome's decision to maintain third-party cookies, ARA and other Privacy Sandbox APIs are being removed.

Deprecation / removal: The Attribution Reporting API is being removed from Chrome. Ad measurement integrations built on ARA should plan migration back to existing cookie-based or server-side measurement approaches.

background

The Attribution Reporting API (ARA) was a Privacy Sandbox proposal that allowed ad networks to measure click and view conversions without third-party cookies or cross-site tracking. It used two report types:

  • Event-level reports: coarse, noisy conversion data sent after a delay.
  • Aggregatable reports: encrypted summaries processed through a trusted aggregation server.

ARA was designed as a privacy-preserving replacement for cookie-based measurement in a cookieless future. Following Google's announcement that Chrome will maintain support for third-party cookies, the core motivation for ARA no longer applies and it is being removed along with other Privacy Sandbox APIs.

Source: chromestatus feature summary; Privacy Sandbox next steps

what is removed

The Attribution Reporting API comprised declarative HTML attributes (such as attributionsrc on <a>, <img>, and <script>), HTTP response headers (Attribution-Reporting-Register-Source and Attribution-Reporting-Register-Trigger), and browser-managed background reporting pipelines. Upon removal, the attributes are ignored by the HTML parser as unrecognized attributes, response headers are discarded without generating reports, and calls do not raise JavaScript runtime exceptions.

examples and migration

Historical usage of the Attribution Reporting API before deprecation and removal (now inactive; commented out per deprecation rules):

// DEPRECATED & REMOVED in Chrome: Attribution Reporting API surfaces are no longer functional.
// Historically, an anchor or image declared attribution source registration:
// <a href="https://advertiser.example/landing"
//    attributionsrc="https://ad-tech.example/register-source">
//   Click here
// </a>

// The server responded with registration headers:
// Attribution-Reporting-Register-Source: {
//   "destination": "https://advertiser.example",
//   "source_event_id": "1234567890",
//   "expiry": "604800"
// }

// Migration note: Ad measurement integrations must transition back to
// cookie-based or first-party server-side measurement workflows.
