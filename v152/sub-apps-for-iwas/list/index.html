subApps.list()

Enumerates the sub apps currently installed under the calling parent Isolated Web App, as a record mapping each sub app’s manifest id to its display name — the id set that remove() accepts.

Syntax

const installed = await window.subApps.list();
// Promise<record<USVString, SubAppsListResult>> list();

dictionary SubAppsListResult {
  required DOMString appName;  // name from the sub app's manifest
};
Source: Blink sub_apps.idl at trunk and spec §4.3, fetched 2026-08-30

Inputs

None. The parent app is implied by the calling document’s associated installed web application; there is no way to enumerate another app’s sub apps.

Source: spec §4.3, fetched 2026-08-30

Outputs

A Promise<record<USVString, SubAppsListResult>> — manifest id → result entry. The record shape (rather than a sequence) makes id lookups direct, e.g. manifestId in installed:

appNameDOMString, required — the sub app’s name as extracted from its web manifest
Source: spec §4.3 and the explainer’s API design notes, fetched 2026-08-30

Errors

SecurityErrorRejects the promise: sub-apps policy-controlled feature not allowed
NotSupportedErrorRejects the promise: called from a sub-app document
OperationErrorRejects the whole promise: reading the platform registry failed — unlike add()/remove(), there is no per-entry failure map
Source: spec §4.3 method steps, fetched 2026-08-30

Context and exposure

Callable only on the SubApps instance at window.subApps: [Exposed=Window, SecureContext, IsolatedContext] in Blink’s sub_apps.idl and the spec — an installed Isolated Web App on desktop Chrome, never an ordinary tab. Every call additionally requires the sub-apps policy-controlled feature (default allowlist 'none'; Permissions-Policy: sub-apps=(self) on the parent document) and rejects with NotSupportedError when called from a sub-app document — sub apps cannot manage sub apps.

Source: spec §4, §6.1; Blink IDL — all fetched 2026-08-30

Lifecycle

Reads the platform registry in parallel with no prompt; for each installed sub app the user agent takes its manifest id and manifest name and resolves the promise with the assembled record. A freshly resolved record reflects the registry at read time — it is a snapshot, not a live view.

Source: spec §4.3, fetched 2026-08-30

Examples

const installed = await window.subApps.list();
for (const [id, { appName }] of Object.entries(installed)) {
  console.log(`${appName} (${id})`);
}
// Direct membership test by manifest id:
if ("/calc" in installed) showAlreadyInstalledBadge();
Source: adapted from the WICG explainer’s examples (fetched 2026-08-30)

Security and privacy

Only data the parent already owns is exposed: its own sub apps’ ids and manifest names, never another app’s. The shared threat model — single origin identity, bidirectional permission inheritance, explicit consent, quota limits — is documented in the parent reference’s security section from spec §5.
