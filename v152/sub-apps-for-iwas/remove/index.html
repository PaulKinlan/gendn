subApps.remove(manifest_ids)

Uninstalls one or more previously installed sub apps of the calling parent Isolated Web App, addressed by the manifest ids that add() returned. Per-id results are reported independently — a missing id does not fail the batch.

Syntax

const response = await window.subApps.remove(manifest_ids);
// Promise<SubAppsRemoveResponse> remove(sequence<USVString> manifest_ids);

dictionary SubAppsRemoveResponse {
  sequence<USVString> removedApps;             // uninstalled manifest ids
  record<USVString, DOMException> failedApps;  // manifest id -> failure
};
Source: Blink sub_apps.idl at trunk and spec §4.2, fetched 2026-08-30

Inputs

manifest_ids — a sequence<USVString> of manifest ids of the sub apps to uninstall: the values add() returned in installedApps, or the keys of list()’s result. Each id must satisfy the same valid-relative-path rules as add() paths (a manifest id is a path under the shared origin).

Source: spec §4.2, fetched 2026-08-30

Outputs

A Promise<SubAppsRemoveResponse>:

removedAppssequence<ManifestId> — the ids successfully uninstalled from the system launcher and registry
failedAppsrecord<USVString, DOMException> — each failed id mapped to the DOMException naming why (see Errors)
Source: spec §4.2, fetched 2026-08-30

Errors

SecurityErrorRejects the promise: sub-apps policy-controlled feature not allowed
NotSupportedErrorRejects the promise: called from a sub-app document
TypeErrorRejects the promise: an id is not a valid relative path or fails to parse
NotFoundErrorPer-id in failedApps: no installed sub app of this parent has the manifest id
OperationErrorPer-id in failedApps: platform uninstall failed with a system error
Source: spec §4.2 method steps, fetched 2026-08-30

Context and exposure

Callable only on the SubApps instance at window.subApps: [Exposed=Window, SecureContext, IsolatedContext] in Blink’s sub_apps.idl and the spec — an installed Isolated Web App on desktop Chrome, never an ordinary tab. Every call additionally requires the sub-apps policy-controlled feature (default allowlist 'none'; Permissions-Policy: sub-apps=(self) on the parent document) and rejects with NotSupportedError when called from a sub-app document — sub apps cannot manage sub apps.

Source: spec §4, §6.1; Blink IDL — all fetched 2026-08-30

Lifecycle

Ids are validated synchronously, then uninstallation runs in parallel with no user prompt in the spec’s steps: each sub app is removed from the system launcher and platform registry, its id appended to removedApps (or an exception recorded in failedApps), and the promise resolves once every id is accounted for. Shared origin data (cookies, storage) belongs to the parent and is not deleted by removing a sub app.

Source: spec §4.2 and §5.1, fetched 2026-08-30

Examples

<script type="module">  <!-- module context: top-level await -->
const installed = await window.subApps.list();
const ids = Object.keys(installed);

// Uninstall everything; inspect per-id outcomes.
const { removedApps, failedApps } = await window.subApps.remove(ids);
console.log(`removed: ${removedApps.join(", ")}`);
for (const [id, err] of Object.entries(failedApps)) {
  console.warn(`${id}: ${err.name}`); // e.g. NotFoundError if already gone
}
</script>

Security and privacy

Removal needs no per-call consent in the spec’s steps (it reduces, not extends, OS integration); it is still gated by the policy and IWA context like every method. The shared threat model — single origin identity, bidirectional permission inheritance, explicit consent, quota limits — is documented in the parent reference’s security section from spec §5.
