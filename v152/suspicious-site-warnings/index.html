Suspicious site warnings

Limited availability

  • Chrome · Android 152 (no desktop milestone recorded)
  • Edge · not applicable (Chrome Safe Browsing UI)
  • Firefox · not applicable
  • Safari · not applicable

This is a Chrome browser-UI change inside Safe Browsing's Enhanced protection mode, not a web platform API. It has no Baseline status: webstatus.dev has no matching web-features entry and BCD does not track browser security UI (both checked 2026-08-23).

From Chrome 152, users enrolled in Safe Browsing > Enhanced protection who visit a site whose signals indicate it is potentially malicious see a by-passable warning pop-up, which must be clicked before they can continue to the site. The warning is an additional, lower-confidence layer on top of the existing full-page red interstitials, which continue to appear on confirmed malicious sites. Site owners cannot opt out from the web; administrators control the behavior with the existing SafeBrowsingProtectionLevel and SafeBrowsingAllowlistDomains enterprise policies.

Scope advisory — Enhanced-protection users, Android-first, bypassable This warning only reaches users who opted into Safe Browsing > Enhanced protection (enrollment: chrome://settings/security → “Enhanced protection”), and the ChromeStatus API record lists only an Android 152 ship milestone — desktop timing is unrecorded as of 2026-08-23. Because the pop-up is deliberately by-passable and there is no page-observable signal, do not treat it as a site-side security control: it changes what some visitors see before your site loads, nothing else.

syntax

This feature adds no new web syntax — no interface, event, header, or attribute. The only configuration surface is the pair of existing Chrome enterprise policies; users control it through the Safe Browsing protection-level setting:

// No web API. Configuration surfaces only:

chrome://settings/security          // user: Safe Browsing protection level
SafeBrowsingProtectionLevel         // policy: 0 = off, 1 = standard, 2 = enhanced
SafeBrowsingAllowlistDomains        // policy: domains excluded from Safe Browsing checks

There is no origin trial, no runtime flag documented in the ChromeStatus record, and no way for a page to detect that a warning was shown for it.

Source: ChromeStatus record (no flag/OT recorded); SafeBrowsingProtectionLevel policy; SafeBrowsingAllowlistDomains policy

the warning behavior

trigger conditions

The warning triggers when both hold, per the ChromeStatus record:

  • The user is enrolled in Safe Browsing > Enhanced protection — the tier that, per the protection-levels help article, “analyzes data from sites that you visit to detect and warn you about potentially risky sites and iframes, even if Google didn't know about them before”.
  • The visited site carries signals that indicate it is potentially malicious. The concrete signal set is deliberately not enumerated in any public document — Google does not publish Safe Browsing detection heuristics — so this reference cannot list it; treat the trigger as Google-side risk classification below the confidence bar of the confirmed-malicious list.

what the user sees

A by-passable pop-up warning displays before the user can interact with the site: the ChromeStatus record states it “must be clicked before they can continue”. This is deliberately lighter-weight than the full-page red interstitial. The warning does not modify the page, does not inject content into it, and is rendered by the browser UI, outside the web content area.

bypass and escalation lifecycle

The lifecycle has three outcomes, all decided by the user in browser UI:

  • Bypass: the warning is by-passable — clicking through dismisses it and loads the site normally. Nothing is surfaced to the page.
  • Leave: the user navigates away; the site never gets the visit beyond what Safe Browsing already fetched for classification.
  • Escalation: if the site is later confirmed malicious, the existing red interstitial takes over — the ChromeStatus record is explicit that red interstitials “will continue to be shown on confirmed malicious websites”. The suspicious-site warning does not replace that path and there is no error state beyond it.
Source: ChromeStatus record — summary; Choose your Safe Browsing protection level in Chrome

admin control: SafeBrowsingProtectionLevel

Administrators control the warning through the existing SafeBrowsingProtectionLevel policy — there is no dedicated policy for this warning. The policy's integer values select the Safe Browsing tier, and the suspicious-site warning only exists inside tier 2:

ValueTierEffect on this warning
0No protectionSafe Browsing disabled; no suspicious-site warnings (and no red interstitials)
1Standard protectionNo suspicious-site warnings; red interstitials on confirmed malicious sites remain
2Enhanced protectionSuspicious-site warnings active from Chrome 152, in addition to red interstitials

When the policy is unset, the user chooses the tier at chrome://settings/security; the warning then follows the user's own Enhanced-protection enrollment. Setting the policy locks the tier and the user cannot change it.

Source: Chrome Enterprise policy — SafeBrowsingProtectionLevel; ChromeStatus record (“Admins can control this warning using the existing SafeBrowsingProtectionLevel policy”)

admin exclusions: SafeBrowsingAllowlistDomains

To exclude specific sites from triggering the warning, administrators add domains to the existing SafeBrowsingAllowlistDomains policy — the ChromeStatus record names this as the supported exclusion mechanism. The policy takes a list of domains on which Safe Browsing trust checks are skipped entirely, so an allowlisted domain gets neither suspicious-site warnings nor other Safe Browsing warnings for that profile. It is an enterprise policy: individual users and site owners have no equivalent self-serve exclusion.

Source: Chrome Enterprise policy — SafeBrowsingAllowlistDomains; ChromeStatus record

examples

There is no JavaScript to write — the developer-relevant “example” is the enterprise configuration and the operational checks a site owner can do:

# Enterprise: pin Enhanced protection (warning active) — Linux JSON policy
# /etc/opt/chrome/policies/managed/safebrowsing.json
{
  "SafeBrowsingProtectionLevel": 2,
  "SafeBrowsingAllowlistDomains": ["intranet.example.com"]
}

# Windows registry equivalents
# HKLM\Software\Policies\Google\Chrome\SafeBrowsingProtectionLevel = 2 (REG_DWORD)
# HKLM\Software\Policies\Google\Chrome\SafeBrowsingAllowlistDomains\1 = "intranet.example.com"

# Site owners: check what Google's systems currently think of your site
# https://transparencyreport.google.com/safe-browsing/search?url=example.com
# and register it in Search Console to receive security-issue notices.

No live demo is embedded: the warning is browser security UI that a web page cannot trigger, so there is nothing a showcase iframe could demonstrate — and the Chrome Platform Showcase v152 index has no route for this feature (HEAD-checked 404, 2026-08-23).

Source: policy value semantics from SafeBrowsingProtectionLevel and SafeBrowsingAllowlistDomains; Safe Browsing site status via Google Transparency Report

security and privacy

  • Enhanced protection's data trade-off applies. The warning exists only in the tier where, per the help article, Chrome sends more real-time browsing data (URLs, samples of page content) to Google, and links it to a signed-in Google Account where applicable. The warning itself sends nothing extra; enrollment in the tier does.
  • Lower-confidence layer, user-decidable. Because the signals are “potentially malicious” rather than confirmed, the warning is deliberately by-passable — Chrome does not block the navigation, and false positives cost one click. Confirmed threats keep the harder red interstitial.
  • No page-observable side effect. A site cannot detect that the warning was shown; there is no fingerprinting surface, no new header, and no DOM change.
  • Site owners' recourse is Safe Browsing's existing pipeline — the Transparency Report site-status lookup and Search Console security issues — since no public artifact enumerates the suspicion signals.
Source: Chrome Help — Safe Browsing protection levels; ChromeStatus record
