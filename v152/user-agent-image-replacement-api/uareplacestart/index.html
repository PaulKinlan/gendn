uareplacestart event

Fired at an HTMLImageElement when the user agent begins substituting the image's content on the user's behalf. From this point replacedByUserAgent is true, and page UI that renders from the original image (zoom lenses, dimension labels, captions) should be adjusted so it does not mislead the user.

Origin trial — may change or be removed Part of the Chrome 152 origin-trial listing for the User Agent Image Replacement API. Enable locally with --enable-blink-features=UAImageReplacementAPI or register in the Origin Trials console; see the overview's enable steps.

syntax

// Event handler IDL attribute, verbatim from Chromium html_image_element.idl:
[RuntimeEnabled=UAImageReplacementAPI] attribute EventHandler onuareplacestart;

// Usage:
imageElement.addEventListener("uareplacestart", (event) => { /* ... */ });
imageElement.onuareplacestart = (event) => { /* ... */ };
Source: html_image_element.idl

inputs

None from the page's perspective — the event cannot be requested or triggered by script. It is initiated solely by a user-agent image-replacement feature acting on explicit user intent or user-configured browser policy (explainer, anti-fingerprinting section).

Source: explainer — non-goals (“Content-driven replacement”) + privacy

outputs

A plain Event whose type is "uareplacestart" and whose target is the replaced HTMLImageElement. In the Chromium implementation it is created with Event::Create(event_type_names::kUareplacestart) (html_image_element.cc): it carries no payload, does not bubble, and is not cancelable — listeners must be attached to the image element itself (or use a capturing listener on an ancestor). Nothing about the replacement content or the feature that caused it is exposed.

Source: html_image_element.cc; explainer — non-goals

errors

The event itself has no error variant — a substitution that fails is reported by uareplaceend, which fires when the substitution “finishes, fails, or is reverted”. When the runtime feature is off, the event is simply never dispatched and onuareplacestart does not exist on the prototype; feature-detect via "onuareplacestart" in HTMLImageElement.prototype.

Source: explainer — proposed approach; html_image_element.idl

context and exposure

Dispatched to HTMLImageElement in Window contexts when the UAImageReplacementAPI runtime feature is enabled (origin trial token or --enable-blink-features=UAImageReplacementAPI, per runtime_enabled_features.json5). Chrome-only; no other engine has signalled support (ChromeStatus API record).

Source: runtime_enabled_features.json5; ChromeStatus API record

lifecycle

Enqueued when StartImageReplacement() switches the element into the image-replacement layout disposition — replacement only starts for an image that has already loaded successfully. The event is enqueued asynchronously on the DOM-manipulation task source (EnqueueEvent(…, TaskType::kDOMManipulation)), so replacedByUserAgent already reads true by the time listeners run, and a script attached after the fact misses the event but not the state. The pairing uareplacestart → uareplaceend brackets each replacement episode.

Source: html_image_element.cc — StartImageReplacement

examples

// Disable an interactive zoom overlay while UA-substituted content
// is showing (it would zoom the wrong pixels).
const img = document.querySelector("img.product-view");
const zoomLens = document.querySelector(".zoom-lens");

img.addEventListener("uareplacestart", () => {
  zoomLens.style.display = "none";
});

// Track replacements page-wide with a capturing listener:
document.addEventListener("uareplacestart", (e) => {
  console.log("UA replaced:", e.target.currentSrc);
}, { capture: true });
Source: explainer — example + capturing-listener pattern (adapted). Note: capturing reaches the target listener even for non-bubbling events.

security and privacy

Per the explainer, the event only fires “when an actual replacement operation is initiated by explicit user intent or user-configured browser policy” — pages cannot use it to probe for replacement capabilities, and the user agent may withhold the event entirely when the replacement is sensitive. It exposes timing and target element only, never content.
