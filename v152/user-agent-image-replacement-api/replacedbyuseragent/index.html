HTMLImageElement.replacedByUserAgent

Read-only boolean on HTMLImageElement: true while the element currently displays substitute content provided by the user agent, false otherwise. It is the synchronous complement to the uareplacestart / uareplaceend events — use it to catch a replacement that happened before your script ran.

Origin trial — API surface may change Available only in the Chrome 152–157 desktop origin trial (token via Origin-Trial header or meta tag) or locally with --enable-blink-features=UAImageReplacementAPI. There is no chrome://flags entry. Full enable steps are on the feature overview.

Syntax

Verbatim from Chromium's html_image_element.idl (fetched 2026-09-06; the explainer describes the same member in prose — there is no formal spec):

[RuntimeEnabled=UAImageReplacementAPI, Measure] readonly attribute boolean replacedByUserAgent;
// Usage
const isReplaced = imgElement.replacedByUserAgent; // boolean

The [Measure] extended attribute means Chromium records a use counter each time the getter is read. The property has no setter — assignment is ignored (or throws in strict mode).

Source: Chromium html_image_element.idl; Explainer — proposed approach.

Inputs

None. This is a parameterless read-only attribute getter; it takes no arguments and there is no way to write it from script. The state it reflects is set exclusively by the user agent's own image-replacement machinery.

Source: Chromium html_image_element.idl — readonly attribute.

Outputs

A boolean. In the Chromium implementation the getter returns whether the element's layout disposition is currently the image-replacement state — the same condition that gates the substitute rendering:

// Chromium html_image_element.cc (verbatim, fetched 2026-09-06)
bool HTMLImageElement::replacedByUserAgent() const {
  return HasImageReplacement();
}

bool HTMLImageElement::HasImageReplacement() const {
  return layout_disposition_ == LayoutDisposition::kImageReplacement;
}

The value is true from the moment replacement starts (before the queued uareplacestart event has even fired — the state flips synchronously, the event is asynchronous) until the replacement ends. It reports current state, not history: after a replacement is reverted it is false again, indistinguishable from never-replaced.

Source: Chromium html_image_element.cc — replacedByUserAgent(), HasImageReplacement().

Errors

The getter never throws. The only failure mode is absence: on a build or context where the UAImageReplacementAPI runtime feature is not enabled, the property does not exist on HTMLImageElement.prototype and reads as undefined — which is falsy, so naive if (img.replacedByUserAgent) code degrades safely to the “not replaced” branch. Feature-detect explicitly when you need to distinguish “not replaced” from “API unavailable”: "replacedByUserAgent" in HTMLImageElement.prototype.

Source: Chromium html_image_element.idl — [RuntimeEnabled=UAImageReplacementAPI]; Chromium runtime_enabled_features.json5.

Context

Exposed on HTMLImageElement (<img> elements) in Window contexts, only where the UAImageReplacementAPI runtime feature is enabled — by origin-trial token during the Chrome 152–157 trial, or the --enable-blink-features=UAImageReplacementAPI switch. The explainer's privacy goal applies to this property exactly as to the events: a user agent may withhold the fact of replacement (keeping the property false) when disclosing it is sensitive, so false means “not observably replaced”, not a guarantee about what is on screen.

Source: Chromium runtime_enabled_features.json5 — origin_trial_feature_name: "UAImageReplacementAPI"; Explainer — privacy goal; ChromeStatus API record — origin-trial stage 152–157.

Lifecycle

The value tracks the element's replacement disposition one-to-one:

  1. false — element shows its own content (initial state).
  2. Flips to true synchronously when the user agent starts replacement; the uareplacestart event that announces the same transition is queued asynchronously, so inside that event handler the property is already true.
  3. Flips to false synchronously when replacement ends — finish, failure, revert, element removal from a connected document, document move, or a source change away from the replaced original (current Chromium behavior; what ends a replacement is ultimately user-agent-specific). The queued uareplaceend handler observes false.

Because events are asynchronous and replacement can predate script execution, the property is the reliable way to initialize UI state on load — the explainer's own example ends with exactly this check.

Source: Chromium html_image_element.cc — StartImageReplacement, ResetImageReplacement; Explainer — example.

Examples

Initialize UI correctly whether or not replacement happened before your script ran, then keep it in sync with the events:

function syncTryOnUI(img) {
  const sizeCaption = img.closest("figure")?.querySelector(".size-caption");
  if (!sizeCaption) return;
  // Hide the "model is wearing size M" caption while the user sees
  // a generated image of themselves instead of the model.
  sizeCaption.hidden = img.replacedByUserAgent === true;
}

const img = document.querySelector("img.product-view");

if ("replacedByUserAgent" in HTMLImageElement.prototype) {
  syncTryOnUI(img);                                   // catch pre-script replacement
  img.addEventListener("uareplacestart", () => syncTryOnUI(img));
  img.addEventListener("uareplaceend", () => syncTryOnUI(img));
}
Source: pattern derived from the explainer's example (which hides a zoom lens the same way).

Security and privacy

The property discloses one bit — “this image is currently replaced” — and only when a replacement was actually initiated by explicit user intent or user-configured policy; pages must not be able to probe for replacement capability through it. The user agent may keep it false for replacements it considers sensitive to disclose. It never exposes the replacement media, which in Chromium renders in an isolated UA shadow-root iframe.

Source: Explainer — privacy & security considerations; Chromium html_image_element.cc.
