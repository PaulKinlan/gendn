uareplacestart / uareplaceend events

The two lifecycle signals of the User Agent Image Replacement API, fired at an <img> element: uareplacestart when the user agent begins substituting the image's content, uareplaceend when the substitution finishes, fails, or is reverted. Both are plain, non-bubbling Events with no payload — the element's replacedByUserAgent property carries the state.

Origin trial — API surface may change These events fire only in the Chrome 152–157 desktop origin trial (token via Origin-Trial header or meta tag) or locally with --enable-blink-features=UAImageReplacementAPI. There is no chrome://flags entry. Full enable steps are on the feature overview.

Syntax

Handler attributes, verbatim from Chromium's html_image_element.idl (fetched 2026-09-06):

[RuntimeEnabled=UAImageReplacementAPI] attribute EventHandler onuareplacestart;
[RuntimeEnabled=UAImageReplacementAPI] attribute EventHandler onuareplaceend;

Listener form (equivalent; the type strings "uareplacestart" and "uareplaceend" are registered verbatim in Blink's event_type_names.json5):

img.addEventListener("uareplacestart", (event) => { /* replacement began */ });
img.addEventListener("uareplaceend",   (event) => { /* finished, failed, or reverted */ });

img.onuareplacestart = (event) => { /* handler-attribute form */ };
img.onuareplaceend   = (event) => { /* handler-attribute form */ };
Source: Chromium html_image_element.idl; Chromium event_type_names.json5; Explainer — proposed approach.

Inputs

The events take no inputs from the page and carry no configuration. Nothing a page does can cause them to fire: replacement is initiated only by a browser feature acting on explicit user intent or user-configured browser policy (an explainer MUST — pages cannot probe for replacement capability by observing side effects). The handler receives a single argument, a plain Event whose type is "uareplacestart" or "uareplaceend" and whose target is the affected <img> element.

Source: Explainer — anti-fingerprinting requirement; Chromium html_image_element.cc — Event::Create with no payload.

Errors

Neither event reports errors, and no error event variant exists. A failed replacement is folded into uareplaceend — the explainer defines the end event as firing “when the substitution finishes, fails, or is reverted”, and the page cannot distinguish the three cases. If the events never fire at all, either no replacement occurred, the runtime feature is disabled (no origin-trial token or flag), or the user agent chose to withhold notification — the API defines no way to tell these apart, by design.

Source: Explainer — proposed approach, privacy goals; Chromium runtime_enabled_features.json5.

Context

Fired at HTMLImageElement in Window contexts where the UAImageReplacementAPI runtime feature is enabled (origin-trial token during Chrome 152–157, or --enable-blink-features=UAImageReplacementAPI); the implementation checks the feature per execution context before enqueuing either event. Because they do not bubble, listen on the element itself, or use a capturing listener on document to observe all images at once — the capture phase passes through ancestors even for non-bubbling events. This is the pattern the explainer recommends for site-wide tracking.

Source: Chromium html_image_element.cc — RuntimeEnabledFeatures check; Explainer — capturing-listener pattern; ChromeStatus API record — origin-trial stage.

Lifecycle

Per replacement episode, the events come in ordered pairs around the replaced period:

  1. uareplacestart is queued when the element's disposition switches to replacement. State has already flipped: replacedByUserAgent is true inside the handler.
  2. The replaced period lasts as long as the user agent presents substitute content.
  3. uareplaceend is queued when the disposition resets. In current Chromium that is: the feature finishing/failing/reverting, the element being removed from a connected document, the element moving to another document, or a source change (src/srcset/<picture> re-selection) whose URL leaves the replaced original's candidate set. What ends a replacement is ultimately user-agent- and feature-specific — the explainer leaves it open.

Because a replacement can start before your script loads, pairing the events with an initial replacedByUserAgent check is required for correct state initialization.

Source: Chromium html_image_element.cc — StartImageReplacement, ResetImageReplacement, RemovedFrom, DidMoveToNewDocument, ResetLayoutDisposition; Explainer — proposed approach.

Examples

Element-scoped handling (the explainer's zoom-lens example, verbatim):

const imageEl = document.querySelector('img.product-view');
const zoomLens = document.querySelector('.zoom-lens');

imageEl.addEventListener('uareplacestart', () => {
  zoomLens.style.display = 'none';
});
imageEl.addEventListener('uareplaceend', () => {
  zoomLens.style.display = 'block';
});
if (imageEl.replacedByUserAgent) {
  zoomLens.style.display = 'none';
}

Document-wide analytics with a capturing listener (capture is mandatory — the events do not bubble):

document.addEventListener("uareplacestart", ({ target }) => {
  analytics.track("ua-image-replacement", { src: target.currentSrc });
  target.addEventListener(
    "uareplaceend",
    () => analytics.track("ua-image-replacement-end", { src: target.currentSrc }),
    { once: true },
  );
}, { capture: true });
Source: Explainer — example and capturing-listener pattern.

Security and privacy

The events fire only for replacements initiated by explicit user intent or user-configured browser policy — never speculatively, so pages cannot use them to probe which replacement capabilities a browser has. They disclose timing only, no media: the substitute content stays isolated from the page (in Chromium, a UA shadow-root iframe), and a user agent may withhold the events entirely when the fact of replacement is sensitive. A future optional enhancement might describe the kind of replacement; today the events deliberately carry nothing.

Source: Explainer — privacy & security considerations, non-goals; Chromium html_image_element.cc.
