User Agent Image Replacement API

Extends HTMLImageElement with one read-only boolean property (replacedByUserAgent) and two DOM events (uareplacestart / onuareplacestart and uareplaceend / onuareplaceend) so web pages can observe when the browser temporarily substitutes an <img> element’s rendered pixels on behalf of the user — for example with a generative-AI virtual try-on render — and hide or adapt surrounding overlays, zoom lenses, or model-specific captions that no longer match the substituted visual.

Limited availability — Origin trial in Chrome 152–157 on desktop (not yet enabled by default); no signals from Firefox or Safari

  • Chrome · Origin trial 152–157 desktop (not yet enabled by default)
  • Edge · Mirrors Chromium origin trial
  • Firefox · No signal / no release
  • Safari · No signal / no release

No web-features or BCD entry exists for HTMLImageElement.replacedByUserAgent or the uareplacestart/uareplaceend events yet (checked 2026-11-27 against webstatus.dev and BCD api/HTMLImageElement.json). MDN’s HTMLImageElement reference does not document this API.

Origin trial in Chrome 152–157 (not yet enabled by default): To enroll a production origin, register for the UAImageReplacementAPI origin trial (ID 1722063907515793409, desktop Chrome 152–157) at Chrome Origin Trials and deliver the token on the document. For local testing without a token, launch Chromium with --enable-blink-features=UAImageReplacementAPI (in runtime_enabled_features.json5, UAImageReplacementAPI declares only origin_trial_feature_name: "UAImageReplacementAPI" without status: "experimental", so chrome://flags/#enable-experimental-web-platform-features does not enable it; triggering actual browser-side replacements also requires the underlying Chromium ImageReplacement feature). No stable ship milestone is set.

why it exists

When a browser feature substitutes a page’s <img> content at the user’s request — for example rendering a generative-AI virtual try-on image in place of a product model photo — surrounding author UI can become confusing or broken: a custom hover zoom lens magnifies the original image rather than the replacement, and captions like “Model is 180 cm wearing size M” contradict the user’s own image. This minimal observation API lets sites detect when replacement starts and ends without exposing the replacement pixels or letting scripts trigger replacements.

Source: User Agent Image Replacement API explainer; ChromeStatus 5076374013476864.

Syntax

In Blink (html_image_element.idl), the API adds one read-only boolean attribute and two event handler IDL attributes directly onto HTMLImageElement:

partial interface HTMLImageElement {
  readonly attribute boolean replacedByUserAgent;
  attribute EventHandler onuareplacestart;
  attribute EventHandler onuareplaceend;
};

This reference documents all three developer-facing surfaces: HTMLImageElement.replacedByUserAgent, the uareplacestart event & onuareplacestart handler, and the uareplaceend event & onuareplaceend handler.

Source: Blink html_image_element.idl; Blink html_image_element.h; explainer.

HTMLImageElement.replacedByUserAgent

Inputs. Read-only getter on an HTMLImageElement instance; takes no parameters and cannot be assigned by page script.

Outputs. Returns true while the element’s layout disposition is actively displaying a user-agent replacement (LayoutDisposition::kImageReplacement in html_image_element.cc), and false otherwise. Reading img.replacedByUserAgent during initial hydration lets late-running scripts detect a replacement that already began before their event listeners were attached. The API does not expose what kind of replacement is active or grant pixel access to it.

Source: Blink html_image_element.cc (replacedByUserAgent, HasImageReplacement); explainer.

uareplacestart event & HTMLImageElement.onuareplacestart

Inputs. Attach a listener via img.addEventListener("uareplacestart", handler), assign the IDL event handler img.onuareplacestart = handler, or attach a capturing listener on an ancestor such as document.addEventListener("uareplacestart", handler, { capture: true }) to monitor all images on the page.

Outputs. Fired asynchronously on the target HTMLImageElement via EnqueueEvent(*Event::Create(event_type_names::kUareplacestart), TaskType::kDOMManipulation) when HTMLImageElement::StartImageReplacement() switches the element into kImageReplacement disposition. The event is a plain Event with bubbles: false and cancelable: false (so ancestor monitoring requires capture phase, and calling preventDefault() has no effect). By the time the listener runs, event.target.replacedByUserAgent is true (unless immediately reverted before dispatch).

Source: Blink html_image_element.cc (StartImageReplacement); Blink event_type_names.json5; explainer.

uareplaceend event & HTMLImageElement.onuareplaceend

Inputs. Attach via img.addEventListener("uareplaceend", handler), assign img.onuareplaceend = handler, or use a capturing listener on an ancestor.

Outputs. Fired asynchronously on the target HTMLImageElement via EnqueueEvent(*Event::Create(event_type_names::kUareplaceend), TaskType::kDOMManipulation) inside HTMLImageElement::SetLayoutDisposition() whenever an active replacement ends, fails, or is reverted back to primary or fallback content. Like uareplacestart, it is a plain non-bubbling, non-cancelable Event (bubbles: false, cancelable: false). When the event runs, event.target.replacedByUserAgent is false, signalling that the page can restore its original overlays, zoom controls, and captions.

Source: Blink html_image_element.cc (SetLayoutDisposition); Blink event_type_names.json5; explainer.

Errors, non-bubbling pitfalls, and silent resets

  • No author-triggered errors or imperative methods: Because the API is read-only and observation-only, page scripts cannot initiate or cancel a replacement; there are no throwing methods. Assigning to img.replacedByUserAgent throws a TypeError in strict mode (or fails silently in sloppy mode) because it is a read-only IDL attribute.
  • Non-bubbling events (bubbles: false): A non-capturing listener on document or a parent container will never receive uareplacestart or uareplaceend. Always attach directly to the <img> element or pass { capture: true } on an ancestor (as explicitly recommended in the explainer).
  • UA discretion to withhold notifications: The explainer explicitly permits user agents to withhold replacement notifications if disclosing a particular substitution would be privacy-sensitive, so replacedByUserAgent === false is a best-effort signal rather than a guarantee against all UA visual modifications.
  • DOM mutations that automatically end a replacement: In Blink (html_image_element.cc), removing the <img> from the document (unless via state-preserving atomic moveBefore()), moving it to another Document, or mutating src/srcset/<picture> such that the original source URL is no longer active or in the candidate set calls ResetImageReplacement() and enqueues uareplaceend.
Source: Blink html_image_element.cc; explainer.

Context, exposure, and feature detection

Exposed on HTMLImageElement in Window contexts ([Exposed=Window]) whenever the UAImageReplacementAPI origin trial or Blink runtime feature is active. Feature-detect via "replacedByUserAgent" in HTMLImageElement.prototype and "onuareplacestart" in HTMLImageElement.prototype. Browsers without the API never fire uareplacestart/uareplaceend and return undefined for replacedByUserAgent, so adaptive listeners degrade cleanly to normal page behavior.

Source: Blink html_image_element.idl; explainer.

Lifecycle and Blink replacement pipeline

  1. Eligibility check: When a user invokes a browser image-replacement feature, Blink’s ImageReplacement::CreateAndBindReceiver() verifies the <img> is connected, displaying primary content (not broken fallback), and has no active replacement.
  2. Start & shadow-tree isolation: Once the image has loaded, HTMLImageElement::StartImageReplacement() transitions layout disposition to kImageReplacement (attaching a UA shadow root hosting an isolated subframe for the substitute visual) and enqueues uareplacestart on TaskType::kDOMManipulation. img.replacedByUserAgent becomes true.
  3. Active state: The page hides conflicting overlays/zoom widgets or updates captions. moveBefore() (atomic move) and responsive srcset updates that keep the original URL in the candidate set preserve the replacement.
  4. Revert, failure, or DOM disconnect: When the user dismisses/reverts the replacement, generation fails, the <img> is disconnected or adopted into another document, or its image source changes away from the original candidate set, SetLayoutDisposition() tears down the UA shadow tree, sets replacedByUserAgent back to false, and enqueues uareplaceend.
Source: Blink image_replacement.cc; Blink html_image_element.cc.

Examples

Live showcase demo & adapting overlays with capture-phase listeners

function bindImageReplacementAdaptation(root = document) {
  const supported =
    typeof HTMLImageElement === "function" &&
    "replacedByUserAgent" in HTMLImageElement.prototype;

  function syncCard(img, isReplaced) {
    const card = img.closest("[data-product-card]");
    if (!card) return;
    card.dataset.uaReplaced = isReplaced ? "true" : "false";
    const zoomLens = card.querySelector(".zoom-lens");
    const modelCaption = card.querySelector(".model-fit-caption");
    if (zoomLens) zoomLens.hidden = isReplaced;
    if (modelCaption) modelCaption.hidden = isReplaced;
  }

  // Reconcile any images already replaced before this script ran.
  if (supported) {
    for (const img of root.querySelectorAll("img")) {
      if (img.replacedByUserAgent) {
        syncCard(img, true);
      }
    }
  }

  // Use capture: true because uareplacestart and uareplaceend do NOT bubble.
  const onStart = (event) => {
    if (event.target instanceof HTMLImageElement) {
      syncCard(event.target, true);
    }
  };
  const onEnd = (event) => {
    if (event.target instanceof HTMLImageElement) {
      syncCard(event.target, false);
    }
  };

  root.addEventListener("uareplacestart", onStart, { capture: true });
  root.addEventListener("uareplaceend", onEnd, { capture: true });

  return {
    supported,
    disconnect() {
      root.removeEventListener("uareplacestart", onStart, { capture: true });
      root.removeEventListener("uareplaceend", onEnd, { capture: true });
    },
  };
}

Security and privacy

  • Replacement media isolation: This API exposes only lifecycle booleans/events — never the substitute image’s pixels, URL, or prompt. In Blink (image_replacement.cc), Chromium hosts the replacement visual inside a user-agent shadow root subframe isolated from page scripts, so <canvas> readback or DOM inspection sees only the original image resource.
  • Anti-fingerprinting: Events fire only when an actual replacement is initiated by explicit user action or user-configured browser policy; pages cannot probe whether the browser offers generative image replacement features before the user invokes one.
  • UA right to withhold: Browsers may suppress uareplacestart/uareplaceend and keep replacedByUserAgent false when even notifying the page of substitution would reveal sensitive user intent.
  • Accessibility: When substituting visual content, the user agent may override the accessible description (alt / ARIA) so assistive technologies describe the substitute image accurately rather than the replaced photo.
Source: User Agent Image Replacement API explainer (Privacy, Security & Accessibility); Blink image_replacement.cc.
