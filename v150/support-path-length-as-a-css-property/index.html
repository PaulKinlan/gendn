Not on the Baseline register — no web-features entry in the webstatus.dev feature query (checked 2026-07-26). Chrome 150 ships it enabled by default per the chromestatus milestone-150 listing (the authoritative listing-position evidence, fetched 2026-07-26); the chromestatus API record (updated 2026-06-10) lists Chrome implementation status “Proposed” (browsers.chrome.status; standards maturity “Working draft”), Firefox no signal (mozilla/standards-positions#1363), and Safari closed without a position (WebKit/standards-positions#621). The SVG pathLength attribute is broadly supported — only the CSS property form is new.

Chrome 150 introduces the path-length CSS property, which maps to the existing SVG pathLength presentation attribute. It applies to the SVG geometry elements that support pathLength (<path>, <circle>, <rect>, <line>, <polyline>, <polygon>, <ellipse>), letting the author-supplied total path length participate in the cascade, specificity, transitions, and animations — affecting stroke dash rendering and text positioning along a <textPath>. The initial value none means “no author-supplied path length” and is distinct from an explicit 0.

MDN: path-length CSS property

MDN's reference covers the property — formal definition, how all path computations are scaled by the ratio path-length / computed path length (text paths, animation paths, stroke operations), examples, specifications, and browser compatibility — plus the companion SVG pathLength attribute page. gendn’s reference below predates MDN’s page and stays for its worked recipes and live example.

why it exists

SVG’s pathLength attribute lets you rescale the coordinate system used by stroke-dasharray and stroke-dashoffset. If you set pathLength="100" on a circle and then write stroke-dasharray: 50 50, you get equal dashes regardless of the circle’s actual circumference — no JavaScript needed to calculate 2πr. The classic trick is pathLength="1": all dash/offset values become fractions of 1, making “draw 70% of a path” as simple as stroke-dasharray: 0.7 0.3.

Before Chrome 150, pathLength could only be set as an SVG presentation attribute, bypassing the CSS cascade. You couldn’t animate it with @keyframes, override it with a stylesheet, or drive it with a CSS custom property. The path-length CSS property unlocks all of those scenarios; CSS declarations override the presentation attribute under standard precedence rules.

Per the spec change, the property calibrates the user agent’s distance-along-a-path calculations and affects three computations: text on a path (<textPath> positioning), motion animation (animate-motion distance), and stroke operations (stroke-dasharray, stroke-dashoffset). A value of 0 is valid and must be treated as a scaling factor of infinity.

Source: ChromeStatus motivation; w3c/svgwg issue #773

Source: w3c/svgwg#1073 — “The path-length property” definition table, quoted from the patch (Value: none | <number [0,∞]>). Note: MDN’s formal-syntax block currently shows <length>; the spec change defines a unitless <number>.

Two malformed-input behaviors, and they differ: a literal invalid declaration (for example path-length: -1 — “a <number> value must be zero or greater”) is dropped at parse time under normal CSS error handling, so an earlier cascaded declaration still wins. But when the invalid value arrives through var() substitution (for example --pl: -1; path-length: var(--pl) — the shape this page’s own recipe uses), parsing succeeds and the declaration is instead invalid at computed-value time: no earlier declaration is restored, and because path-length is not inherited the property resolves to its initial value none. Nothing throws in either case.

No security or privacy considerations are defined: the property is a presentation-attribute-backed rescaling of path computations for rendering; the spec change introduces no cross-origin, storage, or input-processing behavior.

live example

This circle uses path-length: 1 in CSS, so stroke-dasharray: 0.7 0.3 means “70% filled, 30% gap” — regardless of the circle’s radius. (In browsers without the property, the dash pattern falls back to the computed circumference — the circle still renders.)

.draw-circle {
  /* Normalise: all dash/offset values are fractions of 1 */
  path-length: 1;

  /* 70% dash, 30% gap — works for any radius */
  stroke-dasharray: 0.7 0.3;
  stroke-dashoffset: 0;

  animation: draw 2s linear infinite;
}

@keyframes draw {
  to { stroke-dashoffset: -1; }
}

recipes

Classic “draw on” animation — path-length: 1 trick

/* Attribute approach (always worked): */
/* <path d="..." pathLength="1" /> */

/* CSS approach (Chrome 150+): */
.draw-path {
  path-length: 1;
  stroke-dasharray: 1;
  stroke-dashoffset: 1;
  transition: stroke-dashoffset 0.6s ease;
}
.draw-path.visible {
  stroke-dashoffset: 0;
}

Animate path-length itself with a CSS custom property

@property --pl {
  syntax: "<number>";
  initial-value: 100;
  inherits: false;
}

.shape {
  path-length: var(--pl);
  stroke-dasharray: 50;
  transition: --pl 1s ease;
}
.shape:hover {
  --pl: 50; /* changes how long "50" dash units feel */
}

Override via stylesheet (was impossible with attribute only)

/* Base stylesheet */
.default-path { path-length: 100; }

/* Theme override — higher specificity wins */
.theme-compact .default-path { path-length: 1; }
