Programmatic scroll promises

All programmatic scroll methods on Element and Window — scrollTo(), scrollBy(), scroll(), and scrollIntoView() — now return Promise objects that resolve when the scroll completes or is interrupted, giving reliable completion signals for smooth-scroll animations.

Limited availability — shipped in Chrome and Edge 150; Firefox and Safari have not yet shipped

  • Chrome · 150 (desktop, Android, WebView)
  • Edge · 150 (Chromium mirror)
  • Firefox · No signal, not shipped
  • Safari · Support signal, not shipped

why it exists

Before this change, element.scrollTo({ behavior: 'smooth', ... }) returned undefined. Developers who needed to know when a smooth scroll finished had to resort to IntersectionObserver, polling scrollTop, or listening to the scroll event and debouncing it. None of those approaches cleanly distinguished between “scroll is still in flight” and “scroll has settled”.

The Promise-returning scroll methods — including Element.scrollBy(), Element.scrollIntoView(), and Window.scrollBy() — provide a first-class completion signal. The returned Promise resolves with undefined when the scroll reaches its destination, or when it is interrupted (e.g. by another scroll, layout change, or user interaction). A rejected Promise indicates an error (e.g. element was removed).

Update (re-checked 2026-11-27): MDN’s current Element.scrollTo() reference documents that the returned Promise fulfills with an object containing an interrupted boolean property indicating whether the scrolling operation was interrupted.

Source: chromestatus feature summary; CSSWG issue #1562; MDN: Element.scrollTo()

Source: CSSWG issue #1562; CSSOM View specification

API contract disagreement, both sides reported rather than resolved (fetched 2026-10-07): this page says the two-argument forms continue to return undefined for backwards-compatibility, while the cited CSSWG resolution adds returning a promise to all scroll functions and the CSSOM View specification declares the two-argument overloads as returning Promise. Neither side is adjudicated here.

example

// Await a smooth scroll to the top, then run an animation
await document.documentElement.scrollTo({ top: 0, behavior: 'smooth' });
revealHeroAnimation();

// Relative smooth scroll on an element, awaiting completion
await element.scrollBy({ top: 200, behavior: 'smooth' });
onScrollSettled();

// Chain multiple smooth scrolls
async function scrollTour(sections) {
  for (const section of sections) {
    await section.scrollIntoView({ behavior: 'smooth', block: 'start' });
    await highlightSection(section);
  }
}

// Instant scrolls also return a Promise (already resolved)
await window.scrollTo({ top: 500 }); // resolves immediately
console.log('done');

// Feature detection
const scroll = document.documentElement.scrollTo({ top: 0 });
if (scroll instanceof Promise) {
  console.log('Promise-returning scrolls supported');
}
