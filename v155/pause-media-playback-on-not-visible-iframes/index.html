Pause media playback on not-visible iframes

Adds the media-playback-while-not-visible Permissions Policy (default allowlist *) so embedders can pause or block audible HTMLMediaElement playback and interrupt Web Audio AudioContext rendering inside embedded <iframe> documents whenever the frame is not visible (display: none, visibility: hidden, or zero-area width/height equal to 0), without unloading the iframe or losing its DOM state.

Limited availability — enabled by default in Chrome 155 (desktop, Android, WebView); Firefox is positive on the design, and neither Firefox nor Safari ships it yet

  • Chrome · 155 (desktop, Android, WebView)
  • Edge · Mirrors Chromium (155; Microsoft-authored)
  • Firefox · Positive position (not shipped yet)
  • Safari · No signal

No published web-features entry exists on webstatus.dev yet (tracked in web-platform-dx/web-features#4292; checked 2026-11-27). BCD http/headers/Permissions-Policy.json does not yet list media-playback-while-not-visible, and MDN has no dedicated page for this directive.

why it exists

Web applications such as multi-tab workspaces, productivity suites, and slide/dashboard shells often embed third-party or cross-origin media inside <iframe> containers and hide those frames (via display: none, visibility: hidden, or collapsing them to zero width/height) when the user switches views. Removing or unloading the iframe destroys scroll position, form state, and network buffers and causes slow reloads when shown again; leaving it mounted lets hidden embeds keep playing audible video or Web Audio with no cross-origin way for the host page to silence them. Restricting the media-playback-while-not-visible Permissions Policy lets the browser pause hidden-iframe media automatically while keeping the iframe alive and responsive to JavaScript.

Source: WICG Iframe Media Pausing §1 Introduction; ChromeStatus 5082950457884672; Microsoft Edge Explainer.

Syntax

This feature introduces no new WebIDL interfaces or methods; its developer-facing surface is the media-playback-while-not-visible Permissions Policy directive (on HTTP Permissions-Policy response headers and <iframe allow>) coupled with normative playback hooks on HTMLMediaElement (play(), pause(), and autoplay) and Web Audio AudioContext (resume() and the "interrupted" state) from WICG Iframe Media Pausing §2–3:

Permissions-Policy: media-playback-while-not-visible=()
Permissions-Policy: media-playback-while-not-visible=(self)
Permissions-Policy: media-playback-while-not-visible=(self "https://trusted-audio.example")
<!-- Disallow media playback whenever this iframe (or its nested iframes) is not visible -->
<iframe
  src="https://media.example/player"
  allow="media-playback-while-not-visible 'none'"
  title="Embedded media player"
></iframe>

This reference covers all three components of the contract: media-playback-while-not-visible Permissions Policy directive, HTMLMediaElement & Autoplay integration, and Web Audio AudioContext interruption.

Source: WICG Iframe Media Pausing §2 API; §2.1 Usage example; §3 Integration with other specifications.

Permissions-Policy: media-playback-while-not-visible

Inputs. Structured Header dictionary member media-playback-while-not-visible in the HTTP Permissions-Policy header (accepting *, (), (self), or an origin allowlist), or container policy token media-playback-while-not-visible in <iframe allow="..."> (e.g., 'none', 'self', 'src', or explicit origins). The default allowlist is * (EnableForAll in Blink’s permissions_policy_features.json5) so existing iframes keep their historical behavior unless an embedder opts in to restricting them.

Outputs & behavior. Evaluates allowed to play media while not rendered on each embedded document. Disabling the policy on a parent document via Permissions-Policy: media-playback-while-not-visible=() applies to all descendant iframes (and a child iframe cannot re-enable a policy denied by its ancestor). Setting allow="media-playback-while-not-visible 'none'" on a single <iframe> restricts that iframe and all of its nested subframes.

Source: WICG Iframe Media Pausing §2; Blink permissions_policy_features.json5.

HTMLMediaElement (<audio> / <video>) & Autoplay integration

Inputs. Any HTMLMediaElement inside an embedded navigable whose document is disallowed from using media-playback-while-not-visible — whether playback is triggered via mediaElement.play() or the autoplay attribute.

Outputs & behavior. Per WICG Iframe Media Pausing §3.1 and §3.3 Autoplay (implemented in Blink’s html_media_element.cc):

  • play() while not visible: The element is not allowed to play; mediaElement.play() returns a Promise rejected with a NotAllowedError DOMException (matching an autoplay denial). If the frame’s visibility has not yet been resolved at initial load, Blink defers the play() promise in deferred_play_promise_resolvers_ and settles it as soon as visibility resolves via ProcessDeferredPlay().
  • Becoming not-visible while playing: When the embedding iframe transitions to not-visible while audible media is playing (including autoplay playback), Blink runs the internal pause steps on the HTMLMediaElement, setting paused = true and firing a standard pause event.
  • Becoming visible again (no auto-resume): Autoplay eligibility is suppressed while not-visible, and once the iframe becomes visible again, a paused HTMLMediaElement remains paused until the user or script explicitly calls play(). When the iframe is visible, the policy does not alter normal autoplay rules.
Source: WICG Iframe Media Pausing §3.1 HTMLMediaElement; §3.3 Autoplay; Blink html_media_element.cc.

Web Audio AudioContext interruption

Inputs. Any realtime Web Audio AudioContext constructed or resumed inside an embedded document where media-playback-while-not-visible is disallowed.

Outputs & behavior. Per WICG Iframe Media Pausing §3.2 and Blink’s audio_context.cc:

  • Constructed while not visible: The AudioContext is not allowed to start and initializes in the "suspended" state rather than "running".
  • Calling resume() while not visible: Transitions the AudioContext into the "interrupted" state (firing statechange) and rejects the returned Promise with an InvalidStateError DOMException ("Cannot resume an interrupted AudioContext."). If initial frame visibility is not yet known, Blink defers the resume() promise until visibility resolves.
  • Becoming not-visible while "running": Starts an interruption on the AudioContext, moving audioContext.state from "running" to "interrupted" and firing statechange.
  • Becoming visible again (automatic resume): Unlike HTMLMediaElement, when the iframe becomes visible again and the AudioContext is in "interrupted", the browser ends the interruption and transitions audioContext.state back to "running" (firing statechange).
Source: WICG Iframe Media Pausing §3.2 Web Audio; Blink audio_context.cc; WPT WebAudio tests.

Context, scope, and visibility rules

  • Applies to embedded iframes (not top-level documents): Both §3.1 HTMLMediaElement and §3.2 Web Audio require a non-null navigable container (<iframe>). Sending Permissions-Policy: media-playback-while-not-visible=() on a top-level document restricts all of its embedded iframes (not the top-level tab itself when backgrounded).
  • What counts as “not visible”: Per ChromeStatus 5082950457884672 and Blink’s viewport-intersection visibility propagation (LocalFrame::OnFrameVisibilityChangedForMediaPlayback()), an embedded iframe is considered not visible when its container (or an ancestor) has display: none, visibility: hidden, or zero-area layout geometry (width === 0 or height === 0).
  • Nested subframes inherit hidden state: Per Blink’s LocalFrame::Init(), a new subframe created inside an already-hidden parent frame inherits is_hidden_for_media_playback_ = true immediately so newly inserted HTMLMediaElement and AudioContext instances cannot bypass the restriction while the ancestor is render-throttled.
  • No secure-context requirement for the policy itself: Works on both HTTP and HTTPS documents, cross-origin or same-origin, with zero JavaScript coordination required between embedder and embedded origin.
Source: ChromeStatus 5082950457884672; WICG Iframe Media Pausing §3; Blink local_frame.cc.

Lifecycle, visibility transitions, and resume asymmetry

When an embedder hides and later reveals an iframe restricted by media-playback-while-not-visible, HTMLMediaElement and Web Audio AudioContext follow distinct state-transition lifecycles:

State-transition comparison for HTMLMediaElement vs. Web Audio AudioContext under media-playback-while-not-visible 'none'
EventHTMLMediaElement (<video> / <audio>)Web Audio AudioContext
Created/started while iframe is hiddenplay() rejects with NotAllowedError; autoplay blockedInitializes in "suspended"; resume() transitions to "interrupted" and rejects with InvalidStateError
Visibility unresolved during initial loadplay() promise deferred until visibility is knownresume() promise deferred until visibility is known
Iframe becomes hidden during active playbackInternal pause steps run; paused === true; pause event firesInterruption starts; state moves "running" → "interrupted"; statechange fires
Iframe becomes visible againStays paused until user or script calls play()Interruption ends automatically; state moves "interrupted" → "running"; statechange fires

JavaScript execution inside the hidden iframe is not frozen (unlike the abandoned execution-while-not-rendered proposal), so the embedded app keeps its DOM, WebSockets, and event listeners intact while audio is silenced.

Source: WICG Iframe Media Pausing §3.1–3.3; Blink html_media_element.cc; Blink audio_context.cc; Microsoft Edge Explainer.

Embedded frame: handling HTMLMediaElement pause and NotAllowedError

function wireEmbeddedMedia(mediaElement, playButton, statusEl) {
  mediaElement.addEventListener("pause", () => {
    // Fires for both user pauses and media-playback-while-not-visible pauses
    statusEl.textContent = "Paused";
    playButton.hidden = false;
  });

  async function requestPlayback() {
    try {
      await mediaElement.play();
      statusEl.textContent = "Playing";
      playButton.hidden = true;
    } catch (err) {
      if (err.name === "NotAllowedError") {
        // Blocked by autoplay policy or because iframe is currently not visible
        statusEl.textContent = "Playback blocked while frame is hidden or unactivated.";
        playButton.hidden = false;
      } else {
        statusEl.textContent = `Playback error: ${err.message}`;
      }
    }
  }

  playButton.addEventListener("click", () => {
    requestPlayback();
  });
}
Source: WICG Iframe Media Pausing §3.1; Microsoft Edge Explainer.

Embedded frame: handling Web Audio AudioContext "interrupted" state

function createVisibilityAwareAudio(statusEl) {
  const ctx = new AudioContext();

  ctx.addEventListener("statechange", () => {
    if (ctx.state === "interrupted") {
      statusEl.textContent = "Audio interrupted while iframe is not visible.";
    } else if (ctx.state === "running") {
      statusEl.textContent = "Audio running.";
    } else {
      statusEl.textContent = `Audio state: ${ctx.state}`;
    }
  });

  async function startAudio() {
    try {
      await ctx.resume();
    } catch (err) {
      if (err.name === "InvalidStateError" && ctx.state === "interrupted") {
        // Frame is hidden under media-playback-while-not-visible; wait for statechange
        statusEl.textContent = "Waiting for iframe to become visible to resume audio.";
      } else {
        throw err;
      }
    }
  }

  return { ctx, startAudio };
}
Source: WICG Iframe Media Pausing §3.2 Web Audio; Blink audio_context.cc.

Security and privacy

  • No new cross-origin state disclosure: Embedded frames can already infer whether they are hidden via IntersectionObserver or layout geometry, so pausing an HTMLMediaElement or interrupting an AudioContext under media-playback-while-not-visible does not leak new embedder state to cross-origin iframes.
  • Non-escalatable policy inheritance: Following the Permissions Policy model, once an embedder disables media-playback-while-not-visible via HTTP header or <iframe allow="media-playback-while-not-visible 'none'">, neither the embedded document nor any nested child frame can re-enable playback while hidden.
  • User-experience & nuisance defense: Prevents hidden or zero-pixel cross-origin iframes from emitting unexpected background audio while allowing legitimate visible media playback to remain governed by standard autoplay policies.
Source: WICG Iframe Media Pausing §2; Microsoft Edge Explainer; w3ctag/design-reviews#1084.
