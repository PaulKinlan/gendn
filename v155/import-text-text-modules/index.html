Import Text (Text Modules)

A TC39 proposal to add module import … with { type: "text" } statements to JavaScript. The import attribute loads text data as a string value — any UTF-8 file (templates, shader source, prose, even code treated as plain text) becomes a module whose default export is that string.

this feature is documented on MDN

MDN: Import attributes — Text Modules ({ type: "text" })

MDN’s Import attributes reference has a dedicated “Text Modules ({ type: "text" })” section covering the syntax, the Accept: text/plain request behavior, UTF-8 parsing, caching caveats, fetch destination "text", plus specifications and a browser-compat table that includes the type: "text" subfeature (verified substantive 2026-10-11). gendn doesn’t duplicate that here.

Why gendn doesn't duplicate MDN: this site exists for Chrome features that have no MDN reference yet. When MDN covers a feature completely, the honest page is a pointer to the canonical reference plus the shipping metadata MDN doesn't track — duplicated prose would only drift out of sync.

quick reference

The changeChrome 155 ships text modules: import text from "./file.txt" with { type: "text" } (and the dynamic import("./file.txt", { with: { type: "text" } })) imports the file’s contents as a UTF-8 string, per the TC39 import-text proposal; browsers integrate the "text" type via the HTML module-script infrastructure
