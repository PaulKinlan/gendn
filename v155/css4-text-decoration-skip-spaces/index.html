  • Edge · Chromium-based; no own record yet
  • Firefox · no signal

The webstatus.dev text-decoration-skip-spaces web feature (queried 2026-10-11) is Limited availability: only Chrome (available since 155, 2026-10-06) is recorded, and both Gecko and WebKit are “No signal” in the ChromeStatus record. Treat it as a progressive enhancement: unsupported browsers simply keep the spec’s default skipping behavior.

The text-decoration-skip-spaces CSS property controls whether text decoration lines (underlines, overlines, line-throughs) skip over whitespace characters. Per CSS Text Decoration Level 4 the default is start end — decorations already avoid spaces (and adjacent letter- or word-spacing) at line edges — and this property lets authors turn that off (none), extend it to all spaces (all), or keep only one edge (start / end).

syntax

Property definition verbatim from the css-text-decor-4 Editor’s Draft (fetched 2026-10-11):

Valuenone | all | [ start || end ]
Initialstart end
Applies toall elements
Inheritedyes
PercentagesN/A
Computed valuespecified keyword(s)
Animation typediscrete

Value meanings, quoted from the spec:

none — “Spacers are not skipped. They are decorated just like any other character.”

all — “Skip all spacers and all word separators plus any adjacent letter-spacing or word-spacing.”

start / end — “Skip all spacers, plus any adjacent letter-spacing or word-spacing, when located at the start [/end] of the line.”

“For the purpose of this property, a spacer is any typographic character unit from Unicode General Category Zs except U+202F NARROW NO-BREAK SPACE.” … “It controls all text decoration lines drawn by the element and also any text decoration lines drawn by its ancestors.”

The spec carries an open compatibility note on the initial value: “Should the initial value be none for Web-compat? If not, INS and DEL at least should be assigned none in the UA default stylesheet. See also Issue 4653.” If that resolution changes the initial value, rendered defaults may change; the property keywords themselves are not in question.

Source: CSS Text Decoration Level 4 §2.10.3, quoted verbatim

examples

Keeping an underline continuous under a multi-word link (opting out of the default edge skipping), or skipping every space (snippet gendn-derived from the spec grammar above):

/* Default per spec: start end — skip spaces at line edges */

/* Decorate spaces like any other character: */
nav a { text-decoration-skip-spaces: none; }

/* Skip ALL spaces, not just those at line edges —
   underlines attach only to the words themselves: */
.tag-list a {
  text-decoration: underline 2px;
  text-decoration-skip-spaces: all;
}

/* Only trim the line's start edge: */
blockquote p { text-decoration-skip-spaces: start; }

/* Feature-detect before relying on a non-default value: */
@supports (text-decoration-skip-spaces: all) {
  .fancy-underline { text-decoration-skip-spaces: all; }
}

security and privacy

A purely presentational text-decoration control: the Intent records “Minimal risks; this feature is purely additive” for interoperability/compatibility and lists no security sections beyond that. The property adds the usual one-bit @supports detection surface that any new CSS keyword adds; the sources read record no other security or privacy considerations.
