JS Self-Profiling Markers

Extends the JavaScript Self-Profiling API (Profiler) by adding an optional marker field (of enum type ProfilerMarker) to every captured ProfilerSample. Each marker identifies the category of browser work running when the sample was taken — "script", "gc", "style", "layout", "paint", or "other" (or omitted when idle / filtered) — using conditional exposure so safe rendering markers ("style", "layout") appear in regular contexts while sensitive timing markers ("script", "gc", "paint", "other") require cross-origin isolation.

Limited availability — Origin trial in Chrome 153–161 on desktop (planned ship target Chrome 162; not yet enabled by default); Firefox and Safari do not implement the base JS Self-Profiling API or markers

  • Chrome · Origin trial 153–161 desktop (Dev trial 148; proposed ship target 162, not yet shipped by default)
  • Edge · Mirrors Chromium origin trial (Microsoft authored the markers & conditional exposure explainers)

Origin trial in Chrome 153–161 (not yet enabled by default): To enroll a production origin, register for the JSSelfProfilingMarkers origin trial (ID 2442639847895072769, desktop Chrome 153–161) at Chrome Origin Trials and deliver the token on the profiled document (alongside the mandatory Document-Policy: js-profiling response header required by new Profiler()). For local testing without a token, enable chrome://flags/#enable-experimental-web-platform-features or launch Chromium with --enable-blink-features=ExperimentalJSProfilerMarkers (defined with status: "experimental" and origin_trial_feature_name: "JSSelfProfilingMarkers" in runtime_enabled_features.json5). why it exists

A base ProfilerTrace records only a timestamp and optional stackId per sample. In field traces, long gaps between JavaScript stacks — or long durations spent inside a single DOM getter or allocation site — are ambiguous: a 30 ms stall inside a function could be pure script computation, forced synchronous layout, style recalculation, paint, or a garbage collection pause interrupting the stack. Attaching a coarse marker enum directly to each ProfilerSample attributes non-JavaScript main-thread work without duplicating stack entries or breaking parentId stack resolution.

Source: WICG JS Self-Profiling Markers explainer; ChromeStatus 5201297767792640.

Syntax

JS Self-Profiling Markers defines the ProfilerMarker enum and adds an optional marker member to the existing ProfilerSample dictionary returned inside trace.samples by await profiler.stop(). No new constructor options or methods are added to Profiler:

enum ProfilerMarker {
  "gc",
  "layout",
  "paint",
  "script",
  "style",
  "other"
};

dictionary ProfilerSample {
  required DOMHighResTimeStamp timestamp;
  unsigned long long stackId;
  ProfilerMarker marker;
};

This reference covers all three surfaces of the extension: the ProfilerMarker enum values, the optional ProfilerSample.marker dictionary member, and Blink’s conditional marker exposure algorithm (which gates sensitive markers on crossOriginIsolated). The pre-existing timestamp and stackId members of ProfilerSample (shipped in Chrome 94) are shown above for dictionary context.

Source: Blink profiler_sample.idl; WICG Markers explainer; WICG/js-self-profiling#89.

ProfilerMarker enum values

Inputs & Outputs. ProfilerMarker is a read-only output enum populated by the browser when serializing each sample in ProfilerTrace.samples; scripts never pass ProfilerMarker values as inputs. Each string value classifies the primary engine activity captured at that sample tick:

ProfilerSample.marker property

Inputs. Controlled indirectly by the existing new Profiler({ sampleInterval, maxBufferSize }) initialization options (no new option enables or filters markers). Markers are collected automatically whenever the runtime feature / origin trial is active.

Outputs. On every element of trace.samples returned by await profiler.stop(), sample.marker is either one of the six ProfilerMarker strings or absent ("marker" in sample === false, reading as undefined). A sample can carry both stackId and marker simultaneously — for example, a sample taken during forced synchronous layout inside a JS getter has stackId pointing to that JS stack and marker: "layout", and a GC pause interrupting a JS function has stackId plus marker: "gc". Conversely, a sample taken during a non-JS rendering phase can have marker: "style" or "paint" with no stackId.

Source: Blink profiler_sample.idl; Blink profiler_trace_builder.cc (AddSample); WICG Markers explainer.

Conditional marker exposure & Blink state-mapping algorithm

Inputs. For each V8 CPU profiler sample, Blink inspects three inputs in ProfilerTraceBuilder::GetMarker(): the Blink v8::EmbedderStateTag (embedder_state), the V8 VM v8::StateTag (fallback_state), and the profiling context’s CrossOriginIsolatedCapability (window.crossOriginIsolated).

Outputs. Blink evaluates the mapping in strict precedence order:

  1. Feature gate: If ExperimentalJSProfilerMarkers is disabled for the ExecutionContext, return empty (no marker property is set).
  2. Embedder state first (BlinkStateToMarker): If embedder_state is BlinkState::LAYOUT, BlinkState::STYLE, or BlinkState::PAINT, map to "layout", "style", or "paint" respectively.
  3. V8 VM state fallback (VMStateToMarker): Otherwise map v8::GC → "gc"; v8::JS / v8::ATOMICS_WAIT → "script"; v8::PARSER / v8::BYTECODE_COMPILER / v8::COMPILER / v8::OTHER / v8::EXTERNAL → "other"; and v8::IDLE / v8::IDLE_EXTERNAL / v8::LOGGING → empty.
  4. Cross-origin isolation filter (ProfileMarkerToPublicMarker): If !is_cross_origin_isolated_, retain only "style" and "layout"; strip "gc", "paint", "script", and "other" to empty so the sample object omits marker.
Source: Blink profiler_trace_builder.cc; Blink profiler_trace_builder.h; Conditional Markers Exposure explainer.

Errors, failure paths, and edge cases

  • Missing Document-Policy: js-profiling header: new Profiler(options) throws a SecurityError DOMException before any sampling begins.
  • Invalid constructor options: Inherited from the base Profiler constructor — negative sampleInterval or missing required sampleInterval throws RangeError or TypeError; buffer exhaustion stops recording and fires the samplebufferfull event.
  • No direct synchronous feature-detection property: Because marker is an optional dictionary output field (and idle samples also omit it), there is no static property to probe before sampling. Check typeof Profiler === "function" for base API support, check globalThis.crossOriginIsolated to know whether sensitive markers ("gc", "paint", "script", "other") can appear, and inspect whether any sample in a trace contains "marker" in sample.
  • Disambiguating omitted marker: In a non-COI context, a sample without marker can mean either idle time, a cross-origin rejected sample, or a filtered "script"/"gc"/"paint"/"other" sample. Avoid assuming !sample.marker means idle when !self.crossOriginIsolated; if sample.stackId !== undefined and sample.marker === undefined in a non-COI document, script or GC was running.
Source: WICG JS Self-Profiling API §The Profiler Interface; Blink profiler_trace_builder.cc; Conditional Markers Exposure explainer.

Context, exposure, and prerequisites

Profiler requires the HTTP response header Document-Policy: js-profiling on the profiled document. To receive all six ProfilerMarker values (including "script", "gc", "paint", and "other"), the document must also be cross-origin isolated (window.crossOriginIsolated === true, achieved via Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp or credentialless). Without cross-origin isolation, Blink still exposes "style" and "layout" markers when the feature is enabled. The origin trial (Chrome 153–161) targets desktop Chrome.

Source: Conditional Markers Exposure explainer; ChromeStatus 5201297767792640.

Lifecycle and sampling flow

  1. Start sampling: Calling new Profiler({ sampleInterval, maxBufferSize }) attaches a V8 CPU profiler session to the main thread’s isolate.
  2. Per-tick capture: On each sampling tick, V8 records the timestamp, JS call stack, V8 StateTag, and Blink’s active EmbedderStateTag (style, layout, or paint).
  3. Stop & trace construction: Calling await profiler.stop() halts sampling (marking profiler.stopped === true) and invokes ProfilerTraceBuilder::FromProfile() asynchronously, which clamps timestamps, filters non-CORS cross-origin stack frames, maps each sample’s embedder/VM state to a ProfilerMarker, applies the non-COI public-marker filter if needed, and resolves with the ProfilerTrace.
  4. One-shot session: A stopped Profiler cannot be restarted; create a new Profiler instance for the next sampling window.
Source: Blink profiler_trace_builder.cc; WICG JS Self-Profiling API.

Examples

Live showcase demo & summarizing marker breakdown

# Minimum header required for base Profiler API (exposes "style" and "layout" markers):
Document-Policy: js-profiling

# Add COOP + COEP for crossOriginIsolated === true (exposes all 6 markers including gc/paint/script/other):
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
async function profileWithMarkers(workFn) {
  if (typeof Profiler !== "function") {
    return { supported: false, counts: null };
  }

  let profiler;
  try {
    profiler = new Profiler({ sampleInterval: 10, maxBufferSize: 1000 });
  } catch (err) {
    // Throws SecurityError if Document-Policy: js-profiling header is missing.
    return { supported: true, error: err.name, counts: null };
  }

  try {
    await workFn();
  } finally {
    // Always stop in finally so the profiler buffer is released.
  }

  const trace = await profiler.stop();
  const counts = {
    script: 0,
    gc: 0,
    style: 0,
    layout: 0,
    paint: 0,
    other: 0,
    unmarked: 0,
  };

  for (const sample of trace.samples) {
    if (sample.marker && sample.marker in counts) {
      counts[sample.marker] += 1;
    } else {
      counts.unmarked += 1;
    }
  }

  return {
    supported: true,
    crossOriginIsolated: Boolean(globalThis.crossOriginIsolated),
    sampleCount: trace.samples.length,
    counts,
    trace,
  };
}

Security and privacy

  • Graduated disclosure by context isolation: In non-cross-origin-isolated documents, Blink filters out "gc", "paint", "script", and "other" via ProfileMarkerToPublicMarker() because GC timing can leak shared-process memory allocation patterns, paint timing can reveal cross-origin opaque resource costs that did not opt into Timing-Allow-Origin, and script states could reveal cross-origin timing. Only "style" and "layout" (already observable via DOM/CSSOM APIs) are exposed without COI.
  • Same-origin and CORS filtering: Stack frames from cross-origin scripts that do not pass CORS checks (or scripts without a parseable resource URL such as eval()) are omitted by ShouldIncludeStackFrame(), and V8 maps context-rejected samples to idle/logging states so no marker leaks from another origin’s work.
  • Timestamp coarsening & post-hoc delivery: Samples are delivered only after profiler.stop() resolves (never synchronously during GC), with timestamps clamped according to CrossOriginIsolatedCapability, preventing GC markers from acting as a real-time weak-reference oracle.
  • No persistent storage or PII: Traces are in-memory for the calling script and expose no persistent cross-session identifiers.
Source: Conditional Markers Exposure explainer (Security Analysis); WICG Markers explainer (Privacy and Security); Blink profiler_trace_builder.cc.
