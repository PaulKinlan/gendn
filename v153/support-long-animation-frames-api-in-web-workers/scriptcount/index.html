PerformanceLongAnimationFrameTiming.scriptCount

Limited availability — developer trial, behind a flag

  • Chrome · dev trial from 153, --enable-blink-features=LongAnimationFrameWorker
  • Edge · no signal
  • Firefox · no signal
  • Safari · no signal

Flag-gated Chrome prototype; not in the LoAF specification and not on MDN (MDN interface page checked 2026-09-13).

The number of JavaScript entry points (tasks that ran a script) within a long-animation-frame entry. Unlike scripts, which lists only entry points over the 5 ms per-script reporting threshold, scriptCount counts every entry point — making it the key signal for telling one long task (low count) from a flood of small tasks (high count, often with a near-empty scripts array).

Developer trial — the API surface may move

Gated on the LongAnimationFrameWorker runtime flag (status test; enable with --enable-blink-features=LongAnimationFrameWorker, no chrome://flags entry). The member appears on both main-thread and worker entries while the flag is on, and its WPT is explicitly .tentative — the contract is not standardized.

Source: Chromium IDL; runtime_enabled_features.json5.

Syntax

Verbatim from the Chromium IDL:

[RuntimeEnabled=LongAnimationFrameWorker] readonly attribute unsigned long scriptCount;

Read as entry.scriptCount on any PerformanceLongAnimationFrameTiming entry (window or dedicated worker) while the flag is enabled.

Source: performance_long_animation_frame_timing.idl.

Parameters

None — a read-only IDL attribute; there is nothing to pass. (The count is produced by the browser’s frame/congestion monitor, not by developer input.)

Source: Chromium IDL (readonly attribute).

Value

Typeunsigned long — a non-negative integer.
MeaningEvery top-level JS entry point that ran within the entry’s interval — a rendering frame on the main thread, a congested moment in a worker. Always ≥ scripts.length, because scripts additionally requires each entry point to have run ≥ 5 ms and to pass the same-origin attribution filter.
Diagnostic shapeLow scriptCount + long duration → a single long task. High scriptCount + near-empty scripts → tiny-task congestion, the case classic LoAF and Long Tasks cannot surface (the explainer’s worked example: scriptCount: 118 over a 214 ms moment with two listed scripts).
In toJSON()Included in the serialization only while the flag is enabled.
Source: explainer — the scriptCount property; performance_long_animation_frame_timing.cc (BuildJSONValue); WPT loaf-script-count.tentative.html.

Exceptions

None. Reading the attribute never throws. With the flag off (or in other browsers) the property is absent from the prototype — feature-detect rather than reading undefined:

const hasScriptCount =
  typeof PerformanceLongAnimationFrameTiming !== "undefined" &&
  "scriptCount" in PerformanceLongAnimationFrameTiming.prototype;
Source: detection pattern used verbatim by WPT loaf-script-count.tentative.html.

Lifecycle

  • Counted per entry: the monitor accumulates entry points task by task and snapshots the total into the entry when it is reported (frame end on the main thread; congested-moment close in a worker).
  • In a worker, a moment whose scriptCount would be 0 (backlog from native/internal tasks only) is not reported at all — so on worker entries the value is always ≥ 1.
  • The value is immutable once the entry is created.
Source: animation_frame_timing_monitor.cc (FinalizeCongestedMoment).

Examples

Classify congestion by shape, in a worker or on the main thread:

new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    const listed = entry.scripts.length;
    const total = entry.scriptCount ?? listed; // graceful when flag is off
    if (total > listed * 5 && listed <= 2) {
      console.warn(
        `Tiny-task flood: ${total} entry points over ${entry.duration}ms — ` +
        `no single script is slow; reduce task volume or batch messages.`);
    } else {
      console.warn(
        `Long-task congestion: inspect entry.scripts for the offender.`);
    }
  }
}).observe({ type: "long-animation-frame", buffered: true });
Source: pattern derived from the explainer’s flood-diagnosis example.

Security and privacy

An aggregate count of entry points on the observer’s own event loop. It carries no source identity (that lives in scripts, which is same-origin-gated) and, per the explainer, adds “no new cross-origin timing channel” beyond what LoAF already permits.
