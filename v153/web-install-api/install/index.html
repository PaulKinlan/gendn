navigator.install()

Requests installation of a web app: with no arguments, the currently loaded document; with an InstallParams dictionary, the app described by the manifest at params.manifest. Returns a promise that resolves with a WebInstallResult when installation completes and rejects otherwise. Requires a secure context, the primary top-level frame, and transient user activation. Identity: chromestatus.com/feature/5183481574850560.

Experimental — availability gating applies

This method only exists where the WebAppInstallation runtime feature is enabled — see the overview warn-block for the M153 flag state and the exact enable steps (chrome://flags/#web-app-installation-api or --enable-features=WebAppInstallation). The two install_url string overloads are the origin-trial-era shape and are marked for removal (crbug.com/520025525) — write new code against the no-argument and dictionary forms.

Web IDL, verbatim from Chromium trunk (navigator_web_install.idl, fetched 2026-08-09):

[
  RuntimeEnabled=WebAppInstallation,
  ImplementedAs=NavigatorWebInstall
] partial interface Navigator {
  [CallWith=ScriptState, RaisesException, MeasureAs="WebDXFeature::kNavigatorInstall"] Promise<WebInstallResult> install();
  [CallWith=ScriptState, RaisesException, MeasureAs="WebDXFeature::kNavigatorInstall"] Promise<WebInstallResult> install(USVString install_url);
  [CallWith=ScriptState, RaisesException, MeasureAs="WebDXFeature::kNavigatorInstall"] Promise<WebInstallResult> install(USVString install_url, USVString manifest_id);
  [CallWith=ScriptState, RaisesException, MeasureAs="WebDXFeature::kNavigatorInstall"] Promise<WebInstallResult> install(InstallParams params);
};

The draft specification (w3c/manifest#1175) currently defines only the zero-argument overload, with [SecureContext, NewObject] and a Promise<undefined> return.

parameters

ParameterTypeMeaning
(none)—Current-document install. Targets the currently loaded page's linked manifest. The manifest JSON must declare an id, or the promise rejects with DataError.
paramsInstallParamsBackground-document install. Dictionary described below.
install_url (deprecated shape)USVStringDocument URL to load in the background and install via its linked manifest. Empty or invalid URLs reject with TypeError. Retained from the 143–150 origin trial; marked for removal.
manifest_id (deprecated shape)USVStringExpected app id for the install_url form. May be absolute or relative; relative values resolve against the calling document's origin. Empty, "null", or "undefined" strings reject with TypeError (ValidateAndResolveManifestId).

the InstallParams dictionary

Verbatim from install_params.idl:

dictionary InstallParams {
  required USVString manifest;
  // If present, must be a valid absolute URL. Pass undefined, null, or omit
  // completely if the JSON at `manifest` contains an `id` field.
  USVString? manifestId;
};
  • manifest (required) — URL of the target app's manifest file. The browser fetches it with credentials mode "omit". An invalid URL rejects with TypeError (“Invalid manifest url”). Per the explainer's current decisions, the manifest URL must be same-origin with the app's start_url, and relative URLs inside the manifest resolve against the manifest URL itself. If relative, the manifest value resolves against the calling document.
  • manifestId (optional, nullable) — the expected app identity. May be omitted (or passed as undefined/null, which Chromium treats as not provided) if and only if the JSON at manifest declares an id. When provided it must be a valid absolute URL (invalid or empty values reject with TypeError, “Invalid manifest id”; relative support is tracked in crbug.com/397043069) and must equal the browser-computed manifest id, else the promise rejects with DataError. The computed id is visible in DevTools → Application → Manifest.
Source: install_params.idl; navigator_web_install.cc — InstallFromParamsImpl / InstallImpl; explainer — Proposed Approach, A note on manifest id, Open Questions.

return value

A Promise that fulfills with a WebInstallResult dictionary when the user accepts and installation completes (verbatim from web_install_result.idl):

dictionary WebInstallResult {
  USVString manifestId;
};
  • No-argument and install_url overloads: the result's manifestId is set to the installed app's computed manifest id (OnInstallResponse).
  • InstallParams overload: Chromium currently resolves with an empty WebInstallResult — manifestId is deliberately withheld while the team evaluates how much to disclose to callers (crbug.com/520052963). Do not rely on result.manifestId being present.
  • The explainer describes the resolved value as an empty dictionary “for future-proofing”; the draft spec resolves with undefined. Treat resolution itself — not the payload — as the success signal.
  • If the app is already installed, the browser may show launch UI instead: the promise resolves if the user accepts the launch and rejects with AbortError otherwise (explainer note).
Source: web_install_result.idl; navigator_web_install.cc; explainer — Proposed Approach.

exceptions and rejections

Chromium distinguishes synchronously thrown exceptions (precondition failures, before any promise exists — the IDL is RaisesException) from promise rejections. All names below are read directly from navigator_web_install.cc; the explainer specifies the same taxonomy as rejections.

ErrorThrown or rejectedWhen
SecurityErrorthrownPermissions policy disallows web-app-installation; or the document is in any sandboxed context
NotFoundErrorthrownThe navigator object is no longer associated with a document (detached)
InvalidStateErrorthrownNot the primary top-level frame: subframes, prerendering documents, fenced frames; or invalid script state. (The draft spec also rejects with this when the document is not fully active or another install() promise is pending.)
NotAllowedErrorthrownNo transient user activation (“This API can only be called shortly after a user activation.”). Activation is consumed on success, so back-to-back calls need a fresh gesture
TypeErrorrejectedInvalid manifest URL; invalid/empty manifestId; invalid or empty install_url (deprecated shape)
DataErrorrejectedManifest fetch failed, malformed manifest, no id in the manifest when manifestId was omitted, or a supplied manifestId not matching the computed id
AbortErrorrejectedUser dismissed the permission prompt or the install/launch confirmation, or installation failed in the browser

context and exposure

  • Exposure: Navigator (window only — no worker exposure), secure contexts. Gated on the WebAppInstallation runtime feature (runtime_enabled_features.json5); absent otherwise — feature-detect with 'install' in navigator.
  • Frame requirements: primary top-level browsing context only. Subframes (even same-origin), prerendering documents, and fenced frames throw InvalidStateError; sandboxed documents throw SecurityError.
  • Permissions policy: web-app-installation, default allowlist self — see the overview section.
  • User gesture: transient user activation is required and consumed by the call.
  • Permission: background-document installs from origins without the web-app-installation permission trigger a permission prompt first (except current-document installs, which never do) — see the overview section.
  • Platforms: desktop only at this milestone (Windows, macOS, Linux, ChromeOS) — the runtime feature carries no Android status and the flags entry is desktop-only.
  • Not available in private browsing (explainer: apps are not installable in off-the-record profiles).
Source: navigator_web_install.cc; runtime_enabled_features.json5; about_flags.cc; explainer.

lifecycle: the install algorithms

Step sequences as specified by the explainer (“Steps to install the app”), which is the normative source for every entry point while the spec PR covers only the no-argument form:

current document — install()

  1. Reject/throw NotAllowedError without transient user activation; consume the activation.
  2. Reject/throw InvalidStateError if sandboxed or not the top-level frame.
  3. Reject with DataError if the document links no manifest, or the manifest declares no id.
  4. Show install confirmation UI; user decline rejects with AbortError.
  5. Resolve. (If already installed, the browser may offer launch UI with the same resolve/AbortError contract.)

background document — install({ manifest [, manifestId] })

  1. Activation and frame checks as above; invalid manifest URL rejects with TypeError.
  2. If manifest is cross-origin to the calling document and the origin lacks the web-app-installation permission, prompt for it; denial rejects with AbortError.
  3. Fetch the manifest with credentials mode "omit"; failure rejects with DataError.
  4. Without manifestId: the fetched manifest must declare an id, else DataError. With manifestId: it must equal the computed id, else DataError.
  5. Show install confirmation UI naming the requesting site and the target app; decline rejects with AbortError; acceptance installs and resolves.

Concurrency and re-entry: the draft spec holds a single [[installPromise]] internal slot — a second call while one is pending rejects with InvalidStateError; the slot resets to null after settle, so the API is call-again-after-settle idempotent-safe. Because activation is consumed, retries always need a new user gesture. There is no cancellation surface (no AbortSignal parameter); the user closing the browser UI is the only way an in-flight call terminates early, surfacing as AbortError.

Source: explainer — Steps to install the app (all three signatures); w3c/manifest#1175 — install() algorithm and [[installPromise]]; navigator_web_install.cc.

examples

Feature-detected install button for the current site:

const btn = document.querySelector('#install-btn');
btn.hidden = !('install' in navigator);

btn.addEventListener('click', async () => {
  try {
    await navigator.install();
    btn.textContent = 'Installed';
  } catch (err) {
    if (err.name === 'AbortError') return;      // user changed their mind
    if (err.name === 'DataError') {
      console.warn('Add an `id` member to manifest.json to use install().');
    }
  }
});

App catalog installing a third-party app, with a permission pre-check (note the try/catch around permissions.query — it throws TypeError where the feature is disabled):

async function offerInstall(manifestUrl, expectedId) {
  if (!('install' in navigator)) return false;

  try {
    const { state } = await navigator.permissions.query({
      name: 'web-app-installation',
    });
    if (state === 'denied') return false;       // hide the install UI
  } catch {
    return false;                               // feature not enabled
  }

  try {
    await navigator.install({ manifest: manifestUrl, manifestId: expectedId });
    return true;
  } catch (err) {
    switch (err.name) {
      case 'AbortError':      return false;     // user declined
      case 'DataError':       throw new Error('manifest or id problem');
      case 'TypeError':       throw new Error('bad manifest/manifestId URL');
      case 'NotAllowedError': throw new Error('call from a click handler');
      default:                throw err;
    }
  }
}

security and privacy

  • Consent is unbypassable: every path ends in browser-rendered confirmation UI (which the explainer notes reuses existing accessible PWA install surfaces), and cross-origin targets additionally need the origin-scoped web-app-installation permission.
  • Anti-probing: the credentials-omitted manifest fetch, the coarse DataError, and the withheld manifestId on background installs (crbug.com/520052963) all limit what a catalog site can learn about the target app or user state. Focus/blur side channels remain and are documented in the explainer.
  • Use counters: calls are recorded under WebDXFeature::kNavigatorInstall (IDL MeasureAs) — usage is measurable but has no privacy payload.
  • No permission inheritance between installing origin and installed app; private-browsing behavior must not create a detection channel — full analysis in the overview security section and the explainer's considerations chapter.
Source: explainer — Accessibility, Privacy, and Security Considerations; navigator_web_install.idl.
