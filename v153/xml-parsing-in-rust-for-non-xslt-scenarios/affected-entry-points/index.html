Affected entry points — which XML parses go through Rust

Browser-internal parser selection — Chrome 153+

This page documents the concrete algorithm Chrome 153 uses to decide, per document, whether the Rust XML parser (XMLDocumentParserRs) or libxml2 (XMLDocumentParser) parses it — quoted from Chromium source, fetched 2026-09-13.

The rule is simpler than the four-scenario marketing list: any XML document that has no frame, and any SVG document, parses with the Rust parser when XMLRustForNonXslt is enabled (it is stable in Chrome 153). Frameless covers DOMParser.parseFromString() and XMLHttpRequest.responseXML; the SVG condition covers standalone SVG navigations and SVG loaded as an external image.

Selection algorithm

Verbatim from Document::CreateParser() in third_party/blink/renderer/core/dom/document.cc (fetched 2026-09-13; HTML-document branch and timing bookkeeping elided as marked):

DocumentParser* Document::CreateParser() {
  if (auto* html_document = DynamicTo<HTMLDocument>(this)) {
    /* … HTML documents use HTMLDocumentParser, not affected … */
  }

  data_->using_rust_xml_parser_ = false;

  // Use the Rust XML parser for situations non-XSLT situations: XMLHttpRequest,
  // JS DOMParser API, where no dom_window_ is available, or for SVG images.
  if (!GetFrame() || IsSVGDocument()) {
    /* … starts the parse-time measurement … */
    if (RuntimeEnabledFeatures::XMLRustForNonXsltEnabled()) {
      data_->using_rust_xml_parser_ = true;
      return MakeGarbageCollected<XMLDocumentParserRs>(*this, View());
    }
  }

  // FIXME: this should probably pass the frame instead
  if (RuntimeEnabledFeatures::XMLParsingRustEnabled()) {
    data_->using_rust_xml_parser_ = true;
    return MakeGarbageCollected<XMLDocumentParserRs>(*this, View());
  } else {
    return MakeGarbageCollected<XMLDocumentParser>(*this, View());
  }
}

Two independent flags appear here. XMLRustForNonXslt (status stable — this feature) gates the frameless/SVG branch. XMLParsingRust (no status — default off) would route every XML document to Rust and is documented under what still uses libxml2.

Source: document.cc — Document::CreateParser(); runtime_enabled_features.json5.

Inputs — the documents that take the Rust path

The condition !GetFrame() || IsSVGDocument() maps onto the four scenarios announced in the Intent to Ship:

Scenario (Intent wording)Why the condition matches
“DOMParser Web API”DOMParser.parseFromString(text, type) with an XML type (application/xml, text/xml, application/xhtml+xml, image/svg+xml) creates a document with no frame → !GetFrame()
“Accessing responseXML of XMLHttpRequest”The response document XHR builds for responseXML has no frame → !GetFrame()
“SVG standalone images (that is, accessing a image.svg document directly as a top level navigation)”The navigated document is an SVG document → IsSVGDocument()
“SVG external images (including a main document embedding an SVG as an external image resource)”SVG decoded for <img>, CSS images, favicons, etc. is parsed as an SVG document → IsSVGDocument(); the ChromeStatus record notes “Usage of SVG as external images remains high at about 60%… and will run through this code path”

The source comment generalizes the same set: “XMLHttpRequest, JS DOMParser API, where no dom_window_ is available, or for SVG images” — so any other frameless XML document construction that goes through Document::CreateParser() also takes the Rust path. What makes these “non-XSLT” is structural: XSLT applies during framed XML navigations via <?xml-stylesheet?>, which cannot happen for frameless documents, and inline XSLT producing SVG was removed in Chrome 147.

Source: Intent to Ship (scenario list); document.cc; ChromeStatus record (measurement section); ChromeStatus — remove inline XSLT for production of SVG.

Outputs — what the selected parser produces

Both backends produce the same observable output: a DOM Document built through Blink’s node-construction callbacks (StartElementNs, Characters, CData, Comment, DocType, ProcessingInstruction in xml_document_parser_rs.cc). The Intent to Ship’s compatibility claim: the Rust implementation is “expected and shown to be functionally equivalent to the C++ based implementation. No functional change.” For instrumentation, the selected backend is recorded per parse into the UMA histograms Blink.XMLParsing.NonXsltXmlParsingTime.Rust / .Libxml2 / .Combined (document.cc).

Source: xml_document_parser_rs.cc; Intent to Ship; document.cc (histograms).

Error surface

Parse failure surfaces exactly as before, per entry point: DOMParser returns an error document containing a <parsererror> element; XMLHttpRequest.responseXML is null when the response is not well-formed (the parser’s WellFormed() accessor is documented in xml_document_parser_rs.cc as “Used by the XMLHttpRequest to check if the responseXML was well formed”, matching the XHR Standard); a malformed standalone SVG navigation renders the error block; a malformed external SVG image fails to render. The wording of error messages differs between backends — detailed under observable compatibility differences.

Source: xml_document_parser_rs.cc; XMLHttpRequest Standard.

Examples — observing which parser ran

Sites cannot query the backend directly (no web-exposed switch), but each affected entry point can be exercised deterministically. In Chrome 153 all four snippets below take the Rust path; with --disable-blink-features=XMLRustForNonXslt they take libxml2. The DOM produced must be identical either way — any difference is reportable (see reporting regressions):

// 1. DOMParser — frameless document
const dp = new DOMParser().parseFromString("<a b='1'><c/></a>", "text/xml");
console.assert(dp.documentElement.getAttribute("b") === "1");

// 2. XMLHttpRequest.responseXML — frameless response document
const xhr = new XMLHttpRequest();
xhr.open("GET", "/sitemap.xml");
xhr.onload = () => console.log(xhr.responseXML instanceof XMLDocument);
xhr.send();

// 3. Standalone SVG — navigate a tab/iframe-less top-level load to image.svg
//    (the navigated document IsSVGDocument() → Rust parser)
location.assign("/logo.svg");

// 4. SVG as an external image resource
const img = new Image();
img.src = "/logo.svg";  // decoded via an SVG document → Rust parser
document.body.append(img);
Source: scenario mapping per document.cc and the Intent to Ship.

Security and privacy

These entry points all parse attacker-controllable input (cross-origin XML responses, user-supplied strings, remote SVG images), which is exactly why they were migrated first: “This change’s main intention is to improve security” (ChromeStatus security section). Selection happens in the renderer with no new process boundaries, permissions, or data flows; the only privacy-adjacent output is the aggregate UMA parse-time histogram named above.
