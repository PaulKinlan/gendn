Translator API on Android

Brings the on-device Translator Web API to Chrome for Android (including Chrome Custom Tabs) in Chrome 161, matching the desktop WebIDL surface shipped in Chrome 138 while introducing mobile-specific runtime guardrails — a per-origin isolated_app utility process, a 2-service concurrency cap, 1-minute idle model unloading, a 256 KiB per-call input limit, storage and metered-network availability gates, and Android support for the TranslatorAPIAllowed enterprise policy.

Limited availability — Chromium-only built-in AI API (not Baseline; Chrome for Android joins desktop Chrome 138 & Edge 148 in Chrome 161)

  • Chrome Desktop · 138
  • Chrome Android · 161 (including Custom Tabs)
  • Edge Desktop · 148
  • Firefox · No support (Mozilla position: Negative)
  • Safari · No support (WebKit position: No signal)

The translator web-feature is Limited availability on webstatus.dev (checked 2026-11-24). BCD api/Translator.json currently still records chrome_android: false (freshness gap vs. the Chrome 161 milestone listing), and MDN’s Translator reference does not yet document Android Custom Tabs, Android memory/storage/metered-network guardrails, or TranslatorAPIAllowed.

why it exists

Mobile web applications previously had to send user text to cloud translation endpoints or bundle heavy client-side ML weights, adding latency, data usage, and privacy exposure. Shipping Translator on Chrome for Android (including Chrome Custom Tabs) pairs with the Language Detector API on Android (M157) so mobile sites can detect and translate text locally with offline support once language packs are cached, while Chromium enforces strict mobile memory, storage, input-size, and metered-network guardrails so on-device translation does not destabilize phones.

Source: ChromeStatus summary & motivation (5106126157905920); Chrome case study.

In Blink’s translator.idl, Translator is exposed on Window via TranslationAPI (and on Worker only when the separate experimental TranslationAPIForWorkers flag is enabled). This reference documents all five parts of the Chrome 161 Android contract: Translator.availability(), Translator.create() & downloads, translate() & translateStreaming(), quota, metadata & destroy(), and Android runtime guardrails & enterprise policy.

Source: Translator API spec (fetched 2026-11-24); Writing Assistance APIs supporting types; Blink translator.idl.

Translator.availability(options)

Inputs. Requires a TranslatorCreateCoreOptions dictionary containing BCP 47 Unicode locale identifiers for sourceLanguage and targetLanguage (canonicalized in Blink via ValidateAndCanonicalizeUnicodeLocaleId).

Outputs. Returns a Promise<Availability> resolving to one of four enum values without triggering a model download:

Availability states returned by Translator.availability() on Chrome for Android
ValueMeaning on Android
"available"The bundled translation library and required language pack(s) are already on-device and ready for immediate Translator.create().
"downloadable"The language pair is supported, device storage and network checks pass, and calling Translator.create() (with user activation) will download the language pack(s) via Component Updater.
"downloading"Required language pack(s) are currently downloading in the background.
"unavailable"Returned when the language pair is unsupported, the translator permissions policy is blocked, TranslatorAPIAllowed enterprise policy disables the API, or Android storage, device-resource, or metered-network guardrails block downloading/running the model (without revealing whether packs are installed).
Source: Translator API spec; Blink translator.cc; ChromeStatus 5106126157905920.

Translator.create(options) & download monitoring

Inputs. Accepts TranslatorCreateOptions: required sourceLanguage and targetLanguage strings, optional signal (AbortSignal to cancel download/creation and bind session abort), and optional monitor callback receiving a CreateMonitor whose downloadprogress event reports download progress (e.loaded normalized from 0 to 1).

Outputs & behavior. Returns a Promise<Translator>. On Android, the translation library is bundled with Chrome while language packs download on demand via Chromium’s Component Updater (CRX3- and SHA-256-verified) after sticky user activation. Always check Translator.availability() first and invoke Translator.create() inside a user gesture when a download is required.

Source: Translator API spec; Blink create_translator_client.cc; ChromeStatus ergonomics & security notes.

translate(input, options) & translateStreaming(input, options)

Inputs. Both instance methods take a DOMString input (unmatched UTF-16 surrogates are replaced before IPC in Blink) and optional { signal } (TranslatorTranslateOptions).

Outputs. translate() returns a Promise<DOMString> resolving to the full translated string. translateStreaming() synchronously returns a ReadableStream of string chunks suitable for progressive UI rendering of longer passages. On Android, single-call inputs exceeding the 256 KiB engine budget (kTranslationAPIMaxInputSizeBytes) fail with a standard spec-defined error (QuotaExceededError), so callers should chunk large documents (for example by paragraph or sentence) before translating.

Source: Translator API spec; Blink translator.cc; Chromium features.cc.

Quota, metadata, destroy() & lifecycle

Attributes & methods.

  • sourceLanguage / targetLanguage (readonly DOMString): canonicalized BCP 47 tags for this instance.
  • inputQuota (readonly unrestricted double) & measureInputUsage(input, options) (Promise<double>): spec-defined quota inspection surface. Note that in Chromium’s current translator.cc, inputQuota returns Infinity while Android enforces its hard 256 KiB per-call byte budget in the translation service — do not rely solely on inputQuota to skip chunking or QuotaExceededError handling on Android.
  • destroy() (from DestroyableModel): releases the Mojo remote and aborts in-flight calls on that Translator instance. Calling destroy() promptly is especially valuable on Android where each loaded language pair consumes ~79–84 MiB and at most 2 per-origin service processes can run concurrently.

Lifecycle & idle unloading. On Android, Chromium automatically unloads idle translation models after 1 minute (kTranslationAPIModelIdleUnloadTimeout) and shuts down idle utility services after 1 minute (kTranslationAPIServiceIdleTimeout). Applications keeping a Translator reference across long pauses should expect transparent reload latency or recreate the translator if the service was reclaimed.

Source: Blink translator.cc; Chromium features.cc; ChromeStatus 5106126157905920.

Errors & failure modes

Standard spec-defined rejection errors surfaced on Chrome for Android
ErrorWhen it occursRecovery
TypeError / RangeErrorMissing required sourceLanguage / targetLanguage, or invalid BCP 47 language tag rejected by Unicode locale canonicalization.Validate and normalize BCP 47 language codes before calling.
NotAllowedError (DOMException)The translator permissions policy is disallowed (e.g., cross-origin iframe without allow="translator"), or Translator.create() requires a download without user activation.Add allow="translator" where appropriate and trigger Translator.create() inside a user gesture.
NotSupportedError (DOMException)Unsupported language pair, disabled by TranslatorAPIAllowed policy, or device/storage/metered-network checks prevent creation.Check Translator.availability() first and fall back to server/UI alternative.
QuotaExceededError (DOMException)Input exceeds Android’s 256 KiB per-call input budget (TranslationAPIMaxInputSizeBytes) or concurrency/resource quota is exceeded.Split text into smaller UTF-8 chunks (≤ 256 KiB, ideally a few KiB per call) and call destroy() on unused translators.

Context, exposure & permissions policy

Translator requires a SecureContext (HTTPS or localhost) and is exposed on Window (including top-level pages, Android Chrome Custom Tabs, and iframes granted the translator permissions policy — default allowlist 'self'). Cross-origin iframes must opt in via allow="translator" and an appropriate Permissions-Policy: translator=(...) response header. Exposure in Web Workers is not enabled by default (gated by TranslationAPIForWorkers). Android WebView does not expose the API.

Source: Translator API spec §3.5 Permissions policy; Blink translator.idl; ChromeStatus 5106126157905920.

Examples

Android-safe availability check, user-activated creation, chunked translation, and cleanup

// Stay well below Android's 256 KiB TranslationAPIMaxInputSizeBytes cap.
const MAX_ANDROID_CHUNK_BYTES = 16 * 1024;
const encoder = new TextEncoder();

async function translateSafely(text, sourceLanguage, targetLanguage, onProgress) {
  if (typeof Translator === "undefined") {
    throw new Error("Translator API is not supported in this browser");
  }

  const pair = { sourceLanguage, targetLanguage };
  const state = await Translator.availability(pair);
  if (state === "unavailable") {
    // Could be unsupported pair, low storage, metered network, or TranslatorAPIAllowed policy.
    throw new Error(`Translation unavailable for ${sourceLanguage} -> ${targetLanguage}`);
  }

  const controller = new AbortController();
  const translator = await Translator.create({
    ...pair,
    signal: controller.signal,
    monitor(m) {
      m.addEventListener("downloadprogress", (e) => {
        onProgress?.(Math.round(e.loaded * 100));
      });
    },
  });

  try {
    // Chunk input to avoid QuotaExceededError on Android's 256 KiB input budget.
    if (encoder.encode(text).byteLength <= MAX_ANDROID_CHUNK_BYTES) {
      return await translator.translate(text, { signal: controller.signal });
    }
    const paragraphs = text.split(/\n{2,}/);
    const out = [];
    for (const part of paragraphs) {
      out.push(await translator.translate(part, { signal: controller.signal }));
    }
    return out.join("\n\n");
  } finally {
    // Release the ~79-84 MiB language pair promptly under Android's TranslationAPIMaxServiceCount (2).
    translator.destroy();
  }
}
Source: Translator API spec; Chromium features.cc.

Streaming translation output with translateStreaming()

// Call inside a click/tap handler so downloads have sticky user activation.
async function streamTranslation(input, sourceLanguage, targetLanguage, targetEl) {
  const translator = await Translator.create({ sourceLanguage, targetLanguage });
  try {
    targetEl.textContent = "";
    const stream = translator.translateStreaming(input);
    for await (const chunk of stream) {
      targetEl.textContent += chunk;
    }
  } finally {
    translator.destroy();
  }
}
Source: Translator API spec; Chrome for Developers Translator API guide.

Security and privacy

  • Per-origin process isolation: On Android, translation inference runs inside a per-origin isolated_app utility process using the bundled on-device translation library, read-only language pack file descriptors, and browser-enforced 256 KiB input budgets so model execution is sandboxed away from the browser and other origins.
  • Verified model downloads: Language packs are downloaded on demand via Chromium’s Component Updater using CRX3- and SHA-256-verified packages, and require user activation before initiating downloads.
  • No pack-presence fingerprinting via guardrails: Device storage and metered-network checks report "unavailable" without revealing whether specific language packs are already installed on the device.
  • Local processing & enterprise governance: Page text never leaves the device during translation. Managed Android devices can disable the API and prevent model downloads entirely via the TranslatorAPIAllowed enterprise policy.
Source: ChromeStatus security & privacy notes (5106126157905920); Chrome Enterprise TranslatorAPIAllowed; Translator API spec.
