MediaSession: Return Promise<undefined> from setMicrophoneActive() and setCameraActive()

Updates navigator.mediaSession.setMicrophoneActive() and navigator.mediaSession.setCameraActive() to return a Promise<undefined> instead of synchronous undefined, matching the W3C Media Session specification. In a fully active document, the promise resolves with undefined; if the associated document is not fully active (such as a detached <iframe>), the promise rejects with an InvalidStateError DOMException.

Limited availability — supported in Chrome and Safari; not yet shipped in Firefox

  • Chrome · 159 (Promise<undefined>; base methods in 93)
  • Edge · Chromium-based (BCD mirror)
  • Firefox · Not supported in BCD (Positive position)
  • Safari · 18.4 (returns Promise<undefined>)

The base media-session web-feature is Limited availability per webstatus.dev, and BCD api/MediaSession.json lists setMicrophoneActive and setCameraActive as supported in Chrome 93+ and Safari 18.4+ but unsupported in Firefox (checked 2026-11-24). BCD does not yet have a separate subfeature for Chrome 159’s Promise<undefined> return type change.

why it exists

When Chrome 93 originally shipped setMicrophoneActive() and setCameraActive() for video-conferencing Picture-in-Picture and hardware media-key controls, both methods were specified as returning undefined (void). The W3C Media Session Working Group later updated the specification in w3c/mediasession#312 so both methods return Promise<undefined>, allowing user agents that enforce a capture-pause policy (such as Safari) to ask the user or perform asynchronous state transitions before settling. Updating Chromium in Chrome 159 aligns Chrome’s WebIDL contract with Safari 18.4+, fixes four failing subtests in WPT’s mediasession/idlharness.window.html, and lets conferencing apps await both methods uniformly.

Source: ChromeStatus motivation (5188639100370944); w3c/mediasession#312.

Syntax

Updated Blink WebIDL matching the W3C Media Session specification:

// third_party/blink/renderer/modules/mediasession/media_session.idl
[Exposed=Window, RuntimeEnabled=MediaSession]
interface MediaSession {
  // ...
  Promise<undefined> setMicrophoneActive(boolean active);
  Promise<undefined> setCameraActive(boolean active);
};

This reference covers three parts of the contract: MediaSession.setMicrophoneActive(), MediaSession.setCameraActive(), and the shared update capture state algorithm.

Source: W3C Media Session MediaSession interface; Blink media_session.idl.

MediaSession.setMicrophoneActive(active)

Inputs. Accepts a single required boolean active argument indicating whether the application considers the microphone active/unmuted (true) or muted/inactive (false). Standard JavaScript boolean coercion applies when a non-boolean argument is supplied; omitting the argument altogether causes WebIDL argument validation to return a rejected promise with TypeError.

Outputs. Returns a Promise<undefined>. In a fully active document in Chromium 159, notifies Chromium’s MediaSessionService with MicrophoneState::kUnmuted (when active is true) or MicrophoneState::kMuted (when active is false) and resolves to undefined. If the associated document is not fully active, returns a promise rejected with DOMException (name === "InvalidStateError").

Source: W3C Media Session setMicrophoneActive(); Blink media_session.cc.

MediaSession.setCameraActive(active)

Inputs. Accepts a single required boolean active argument indicating whether the application considers the camera active/on (true) or turned off/inactive (false). Omitting active returns a promise rejected with TypeError.

Outputs. Returns a Promise<undefined>. In a fully active document in Chromium 159, notifies Chromium’s MediaSessionService with CameraState::kTurnedOn (when active is true) or CameraState::kTurnedOff (when active is false) and resolves to undefined. If the associated document is not fully active, returns a promise rejected with DOMException (name === "InvalidStateError").

Source: W3C Media Session setCameraActive(); Blink media_session.cc.

Errors, behavioral changes, and caller migration

  • InvalidStateError (DOMException, rejected promise): occurs when calling either method on a MediaSession belonging to a document that is no longer fully active (such as a removed <iframe>). Always attach .catch() or try/await if calling across frame boundaries or during teardown.
  • TypeError (rejected promise instead of synchronous throw): prior to Chrome 159, calling navigator.mediaSession.setMicrophoneActive() or setCameraActive() with no arguments threw a synchronous TypeError. In Chrome 159+, because the WebIDL return type is Promise<undefined>, argument and receiver conversion failures produce a rejected promise.
  • Fire-and-forget callers stay safe in active documents: existing code that ignores the return value in an active document does not emit unhandled rejections because the returned promise resolves with undefined.
  • Cross-version await compatibility: await navigator.mediaSession.setMicrophoneActive(isActive) works seamlessly in both Chrome < 159 (where await undefined resolves immediately) and Chrome 159+ / Safari 18.4+ (which return a Promise<undefined>). Check "mediaSession" in navigator && typeof navigator.mediaSession.setMicrophoneActive === "function" before calling to guard Firefox.
Source: ChromeStatus interop & compatibility risks; WebIDL Operations (promise rejection conversion).

Context and exposure

MediaSession is exposed only on Window ([Exposed=Window]) via navigator.mediaSession; it is not exposed in Web Workers. Neither setMicrophoneActive() nor setCameraActive() is restricted to [SecureContext] in Blink IDL, though actual microphone/camera capture via navigator.mediaDevices.getUserMedia() requires a secure context and user permission.

Source: W3C Media Session; Blink media_session.idl.

Lifecycle and state transitions

Each call updates the document’s desired capture-active hint reported to browser UI surfaces (such as the Picture-in-Picture window mute/camera buttons) and immediately returns a settled Promise<undefined> in Chromium 159. Repeated calls with the same boolean value are idempotent. Once a document stops being fully active (e.g., an <iframe> is disconnected from its parent DOM or navigated away), subsequent calls on its retained MediaSession reference reject with InvalidStateError rather than silently succeeding.

Source: Blink media_session.cc; W3C Media Session.

Examples

Awaiting setMicrophoneActive() and setCameraActive() safely across browsers

async function syncCallCaptureIndicators({ micOn, camOn }) {
  const session = navigator.mediaSession;
  if (!session) return;

  try {
    // await works in Chrome 159+ & Safari 18.4+ (Promise<undefined>)
    // as well as Chrome 93-158 (undefined)
    if (typeof session.setMicrophoneActive === "function") {
      await session.setMicrophoneActive(micOn);
    }
    if (typeof session.setCameraActive === "function") {
      await session.setCameraActive(camOn);
    }
  } catch (err) {
    if (err instanceof DOMException && err.name === "InvalidStateError") {
      // Document was detached or (in Safari) hidden when re-activating capture
      console.warn("MediaSession state update skipped:", err.message);
      return;
    }
    throw err;
  }
}
Source: W3C Media Session; Blink media_session.cc.

Handling InvalidStateError on a detached document

const iframe = document.createElement("iframe");
document.body.append(iframe);
const detachedSession = iframe.contentWindow.navigator.mediaSession;
iframe.remove(); // Associated document is no longer fully active

// In Chrome 159+, returns a rejected Promise<undefined> (InvalidStateError)
const result = detachedSession.setMicrophoneActive(false);
if (result instanceof Promise) {
  await result.catch((err) => {
    console.log(err.name);    // "InvalidStateError"
    console.log(err.message); // "The document is not fully active."
  });
}
Source: Blink media_session.cc; Chrome Platform Showcase detached-document-rejection concept.

Security and privacy

Changing the return type from undefined to Promise<undefined> does not grant microphone or camera capture access, bypass permissions, or expose new user state. In Chromium 159, these methods only report the page’s self-declared mute/camera state to browser UI (such as Picture-in-Picture controls); rejecting with InvalidStateError when a document is not fully active prevents detached frames from modifying media-session state. In user agents that apply a capture-pause policy, returning a promise also allows user consent prompts before resuming capture. ChromeStatus records no security risks and lists security/privacy reviews as Pending (checked 2026-11-24).

Source: ChromeStatus record (5188639100370944); W3C Media Session Privacy Considerations.
