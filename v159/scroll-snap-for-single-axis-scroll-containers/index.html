Scroll snap for single-axis scroll containers

Extends CSS Scroll Snap Level 1 with per-axis scroll snap container resolution for single-axis scroll containers (elements pairing a scrollable overflow value with clip, such as overflow: auto clip or overflow: clip auto). A single-axis scroll container now captures descendant snap alignments only along its scrollable axis; snap alignment along its clipped axis propagates up the containing block chain to the nearest ancestor scroll container that scrolls in that direction.

Limited availability — single-axis scroll snap propagation is Chrome 159 only (base CSS scroll-snap is Baseline Widely available)

  • Chrome · 159 (desktop, Android, WebView)
  • Edge · Chromium-based (no BCD entry or separate announcement yet)
  • Firefox · No signal (standards-positions#1445)
  • Safari · No signal (standards-positions#712)

The base scroll-snap web-feature is Baseline Widely available since 2022-07-15 per webstatus.dev, and BCD css/properties/scroll-snap-type.json tracks base support from Chrome 69 / Edge 79 / Firefox 68 / Safari 11. Single-axis scroll snap propagation has no BCD subfeature yet (checked 2026-11-24) and depends on single-axis scroll containers (Chromium’s SingleAxisScrollContainers).

why it exists

Single-axis scroll containers allow an element to scroll in one axis while merely clipping the other (for example overflow: auto clip instead of coercing clip to hidden), enabling position: sticky elements to stick independently per axis. Previously, CSS Scroll Snap treated every scroll container as 2D: a single-axis horizontal carousel trapped descendant scroll-snap-align declarations on both axes, preventing the vertical alignment from reaching an outer vertical feed scroller. Extending CSS Scroll Snap to resolve the capturing scroll snap container independently per axis lets a single element snap horizontally inside a carousel while snapping vertically inside an outer page feed, matching the mental model of single-axis sticky positioning.

Source: single-axis-scroll-snap explainer; ChromeStatus summary & motivation (5086608215900160).

Syntax and per-axis snapping rules

No new CSS properties or keywords are introduced. Existing CSS Overflow 4 single-axis overflow combinations interact with CSS Scroll Snap 1’s scroll-snap-type and scroll-snap-align properties:

/* Single-axis scroll container (scrollable on one axis, purely clipped on the other) */
overflow: auto clip;    /* overflow-x: auto; overflow-y: clip; */
overflow: clip auto;    /* overflow-x: clip; overflow-y: auto; */
overflow: scroll clip;  /* overflow-x: scroll; overflow-y: clip; */
overflow: clip scroll;  /* overflow-x: clip; overflow-y: scroll; */

/* CSS Scroll Snap 1 — unchanged property grammars */
scroll-snap-type: none | [ x | y | block | inline | both ] [ mandatory | proximity ]?;
scroll-snap-align: [ none | start | end | center ]{1,2}; /* block-axis inline-axis */

“In each axis, a snap position is ‘captured’ by its nearest ancestor scroll container on its associated element’s containing block chain that is scrollable in that axis — its scroll snap container for that axis — and only affects the scroll position of that scroll container in that axis.”

This specification update defines four concrete behaviors: per-axis snap capture and propagation (including overflow: hidden vs overflow: clip, DOM order, and ::column pseudo-elements), scroll-snap-type on clipped axes, scroll-snap-align resolution across writing modes, and re-snapping and target preservation lifecycle.

Source: w3c/csswg-drafts#14354 (merged into CSS Scroll Snap 1 on 2026-09-28); w3c/csswg-drafts#14018.

Per-axis snap capture and propagation

Inputs. Any descendant element (or ::column pseudo-element in a multicolumn scroller) with a non-none scroll-snap-align inside one or more ancestor scroll containers on its containing block chain.

Outputs. For each physical axis independently, the browser walks the containing block chain to find the nearest ancestor scroll container that is scrollable in that axis:

Scroll snap capture and propagation by inner container overflow configuration (CSS Scroll Snap 1 & WPT single-axis-001–003, 007)
Inner container overflowHorizontal (X) snapVertical (Y) snapNotes
overflow: auto clip (or scroll clip)Captured by inner containerPropagates to nearest ancestor scrollable in YInner is scrollable in X only; Y is clipped, not scrollable
overflow: clip auto (or clip scroll)Propagates to nearest ancestor scrollable in XCaptured by inner containerInner is scrollable in Y only; X is clipped, not scrollable
overflow: auto hidden (or overflow: hidden)Captured by inner containerCaptured by inner container (does NOT propagate)overflow: hidden remains a 2D programmatic scroll container (WPT single-axis-002.html)
overflow: auto clip with scroll-snap-type: noneCaptured by inner container (no snapping in X)Propagates to nearest ancestor scrollable in YScrollable X still captures and stops X propagation even with scroll-snap-type: none

Two additional invariants verified by WPT apply when snap areas propagate across single-axis containers: ::column pseudo-elements inside a single-axis multicolumn scroller split snap axes identically (WPT single-axis-003.html), and ancestor scrollers preserve DOM order when breaking ties between co-located snap areas propagated from inner single-axis containers (WPT single-axis-007.html).

Source: w3c/csswg-drafts#14354; WPT single-axis-001.html; single-axis-002.html; single-axis-003.html; single-axis-007.html.

scroll-snap-type on a single-axis scroll container

Inputs & outputs. Per CSS Scroll Snap 1 (PR #14354): “A single-axis scroll container only establishes snap positions in its scrollable axis; specifying scroll-snap-type for an axis which is not one of the box’s scrollable axes has no effect.”

  • Setting scroll-snap-type: both mandatory on an overflow: auto clip container snaps only along X; the Y axis is ignored on that container and descendant Y snap positions still propagate to ancestor Y scrollers.
  • Setting scroll-snap-type: y mandatory on an overflow: auto clip container establishes no snapping on Y (not scrollable) and traps X snap positions without snapping (because X is scrollable with snapping disabled on X).
Source: w3c/csswg-drafts#14354 (#scroll-snap-type); single-axis-scroll-snap explainer.

scroll-snap-align resolution across writing modes

Inputs & outputs. Because scroll-snap-align: <block> <inline> uses logical axes while scroll containers scroll along physical axes (X and Y), inner and outer scrollers with differing writing-mode or direction values follow a two-step rule defined in CSS Scroll Snap 1 (PR #14354) and verified across WPT single-axis-004.html through single-axis-008.html:

  1. Logical-to-physical axis mapping: The two values of scroll-snap-align (block axis, then inline axis; if only one value is given, it applies to both) are mapped onto physical X and Y axes using the writing mode of the box’s nearest ancestor scroll container on its containing block chain — even if that container only scrolls in one of those two axes.
  2. start / end edge resolution: Once mapped to physical X and Y, any unconsumed physical axis propagates upward as a physical snap requirement. On each axis, start and end are resolved using the writing mode of the scroll snap container capturing that axis (unless the snap area is larger than the snapport, in which case the box’s own writing mode is used).
Source: w3c/csswg-drafts#14354 (#scroll-snap-align); WPT single-axis-005.html; single-axis-006.html; single-axis-008.html.

Re-snapping, dynamic updates, and lifecycle

Lifecycle & state transitions. When layout, DOM membership, or scroll-snap-align changes on a descendant inside a single-axis scroll container, each capturing ancestor scroll container re-evaluates its own axis independently. Per CSS Scroll Snap 1 §Re-snapping and WPT single-axis-009.html, an outer scroll container preserves a previously snapped target across layout updates only while that target’s contributing snap area remains present for the outer container’s axis; if the snap target is removed or its alignment on that axis becomes none, the outer container releases the stale target and re-snaps to remaining valid snap areas. Changing an inner container’s overflow between clip and hidden dynamically toggles whether the clipped axis propagates or is trapped locally.

Source: CSS Scroll Snap 1 #re-snap; WPT single-axis-009.html.

Errors, compatibility risks, and opt-outs

CSS Scroll Snap properties (scroll-snap-type and scroll-snap-align) never throw exceptions; invalid declarations are ignored at parse time, and declaring scroll-snap-type on a clipped axis silently has no effect rather than raising an error. However, the explainer and ChromeStatus identify one concrete behavioral change to guard against on pages already using overflow: auto clip (or clip auto):

  • Unexpected ancestor snapping on single-value scroll-snap-align: Writing scroll-snap-align: start sets start on both block and inline axes. Inside an overflow: auto clip carousel, the clipped vertical axis will now propagate to an outer vertical snap container instead of being silently trapped.
  • Opt-out 1 (recommended): Explicitly specify none on the non-snapping axis — for example scroll-snap-align: none start (horizontal-only in horizontal-tb writing mode) so the vertical axis never propagates to ancestors.
  • Opt-out 2 (preserve legacy 2D trapping): Use overflow: auto hidden instead of overflow: auto clip when you deliberately want the inner container to trap snap areas on both axes.
  • Fallback in browsers without single-axis scroll containers: In engines where overflow: auto clip still coerces clip to hidden (Firefox, Safari, Chrome < 156/159), inner carousels trap both axes; place vertical scroll-snap-align: start none on the carousel wrapper itself if outer vertical section snapping must work identically in older engines.
Source: single-axis-scroll-snap explainer #compatibility; ChromeStatus interop_compat_risks (5086608215900160).

Context and exposure

Pure CSS layout and scrolling behavior applying to all document and shadow DOM elements (including ::column pseudo-elements) in any browsing context when single-axis scroll containers are enabled. Requires no secure context, permission, user activation, or JavaScript. Not applicable to Web Workers.

Source: CSS Scroll Snap 1; WPT single-axis-003.html.

Examples

No interactive demo exists yet on the Chrome Platform Showcase for Chrome 159 (checked 2026-11-24). The feature author’s standalone multi-carousel feed demo is linked from the explainer at jsfiddle.net/lcdavid94/m4zvnxLo/.

Vertical snap feed with horizontal single-axis carousels

<div class="feed">
  <section class="carousel" aria-label="Trending Now">
    <article class="card">Item 1</article>
    <article class="card">Item 2</article>
    <article class="card">Item 3</article>
  </section>
  <section class="carousel" aria-label="Continue Watching">
    <article class="card">Item A</article>
    <article class="card">Item B</article>
  </section>
</div>

<style>
  .feed {
    block-size: 100svh;
    overflow-y: auto;
    scroll-snap-type: y mandatory;
  }

  .carousel {
    display: flex;
    gap: 1rem;
    /* Single-axis horizontal scroller: scrolls X, clips Y without trapping Y snap */
    overflow: auto clip;
    scroll-snap-type: x mandatory;
  }

  .card {
    flex: 0 0 80%;
    min-block-size: 14rem;
    /* Block-axis 'start' propagates up to .feed (snapping rows vertically);
       inline-axis 'start' is captured by .carousel (paginating cards horizontally). */
    scroll-snap-align: start start;
  }
</style>
Source: single-axis-scroll-snap explainer (Multi-Carousel Feed use case); WPT single-axis-001.html.

Opting out of ancestor propagation and preserving overflow: hidden trapping

/* Option 1: Keep overflow: auto clip, but set block-axis snap alignment to none
   so cards only snap horizontally inside the carousel and never snap the outer feed. */
.carousel-only-card {
  scroll-snap-align: none start; /* block: none, inline: start */
}

/* Option 2: Use overflow: auto hidden to form a 2D scroll container that traps
   both axes locally (matching pre-single-axis behavior across all browsers). */
.trapping-carousel {
  overflow: auto hidden;
  scroll-snap-type: x mandatory;
}
Source: single-axis-scroll-snap explainer #compatibility; WPT single-axis-002.html.

Mixed writing modes between inner single-axis scroller and outer scroller

.outer-scroller {
  inline-size: 200px;
  block-size: 200px;
  overflow: auto;
  scroll-snap-type: both mandatory;
}

.inner-vertical-lr {
  writing-mode: vertical-lr;
  /* Scrollable horizontally (block axis here), clipped vertically (inline axis here) */
  overflow: auto clip;
  scroll-snap-type: x mandatory;
}

.inner-vertical-lr .target {
  /* First value ('start') resolves to block axis of nearest scroll container (X in vertical-lr)
     -> captured by .inner-vertical-lr.
     Second value ('center') resolves to inline axis of nearest scroll container (Y in vertical-lr)
     -> propagates to .outer-scroller as a physical Y center alignment. */
  scroll-snap-align: start center;
}
Source: w3c/csswg-drafts#14354; WPT single-axis-008.html.

Security and privacy

Per-axis scroll snap propagation operates entirely within the document’s own CSS layout and scroll container hierarchy; it introduces no new network capability, permission, storage, cross-origin communication, or fingerprinting surface. Both the single-axis scroll containers explainer and ChromeStatus note no special security or privacy risks, with W3C TAG (#1266) and Chromium security/privacy reviews listed as Pending (checked 2026-11-24).

Source: ChromeStatus security_risks & review status (5086608215900160); W3C TAG review #1266.
