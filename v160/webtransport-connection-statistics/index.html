WebTransport connection statistics

Ships WebTransport.getStats(), returning an asynchronous WebTransportConnectionStats snapshot for an active or closed WebTransport session: QUIC round-trip time metrics (smoothedRtt, rttVariation, minRtt), congestion-estimated sending rate (estimatedSendRate), and datagrams counters (droppedIncoming, expiredIncoming, expiredOutgoing, lostOutgoing). Chromium 160 does not yet expose connection-level byte/packet totals or atSendCapacity.

Limited availability — WebTransport.getStats() fields vary across engines (base WebTransport is Baseline Newly available since 2026-03-24)

  • Chrome · 160 (RTT, send rate, datagram stats; no byte/packet totals)
  • Edge · Chromium-based (BCD mirror)
  • Firefox · 158 (full method; BCD still shows 114 not-implemented stub)
  • Safari · 26.4 / 27.2 (WebKit-7625.2.8 returns default-initialized stats)

The base webtransport web-feature is Baseline Newly available since 2026-03-24 per webstatus.dev, while WebTransport.getStats() has substantial cross-engine differences in populated dictionary fields (BCD api/WebTransport.json, Firefox 158 release notes, WebKit-7625.2.8 source, checked 2026-11-24). Always feature-check individual properties on the returned dictionary.

why it exists

Real-time WebTransport applications (live video, cloud gaming, collaborative editors, telemetry) need to separate network latency, congestion, and datagram drops from application-side queuing delays. Without connection-level stats, an application cannot tell whether incoming datagrams are overflowing the client receive buffer, whether outgoing datagrams are expiring before transmission or being lost on the wire, or how much bandwidth the QUIC congestion controller estimates is available. WebTransport.getStats() exposes a single asynchronous snapshot of underlying connection health without altering transmission behavior, complementing the per-stream and per-group byte counters added in Chrome 159 send groups.

Source: ChromeStatus motivation (5120203192139776); W3C WebTransport Explainer — Stats.

Syntax

Chromium 160 Blink WebIDL (web_transport.idl, web_transport_connection_stats.idl, web_transport_datagram_stats.idl):

  Promise<WebTransportConnectionStats> getStats();

dictionary WebTransportConnectionStats {
  DOMHighResTimeStamp smoothedRtt;
  DOMHighResTimeStamp rttVariation;
  DOMHighResTimeStamp minRtt;
  required WebTransportDatagramStats datagrams;
  unsigned long long? estimatedSendRate = null;

dictionary WebTransportDatagramStats {
  unsigned long long droppedIncoming;
  unsigned long long expiredIncoming;
  unsigned long long expiredOutgoing;
  unsigned long long lostOutgoing;
};

This reference covers all three parts of the Chrome 160 surface: WebTransport.getStats(), WebTransportConnectionStats (including the 9 W3C spec members omitted in Chrome 160), and WebTransportDatagramStats.

Source: Blink web_transport.idl; Blink web_transport_connection_stats.idl; Blink web_transport_datagram_stats.idl.

WebTransport.getStats()

Inputs. Takes no arguments (WebTransport.prototype.getStats.length === 0). Invoked on a WebTransport instance.

Outputs. Returns a fresh Promise<WebTransportConnectionStats> on every invocation (two concurrent calls return distinct Promise objects: wt.getStats() !== wt.getStats()). In Chromium’s web_transport.cc, concurrent calls while an IPC stats request is already in flight are coalesced into one network-service round trip and resolved with the resulting snapshot.

Source: W3C WebTransport — getStats(); Blink web_transport.cc; WPT stats.https.any.js.

WebTransportConnectionStats dictionary

Populated members in Chrome 160. All RTT and send-rate members are pooled connection stats under W3C WebTransport §6.13:

W3C spec members omitted in Chrome 160. The W3C WebTransport specification also defines eight connection byte/packet totals (bytesSent, bytesSentOverhead, bytesAcknowledged [at risk], packetsSent, bytesLost, packetsLost, bytesReceived, packetsReceived) and atSendCapacity (default false). Chromium 160 does not expose these nine members; they are absent (undefined) on returned dictionaries. Check "bytesSent" in stats before reading them.

Source: W3C WebTransport §6.13; Blink ConvertStatsFromMojom; ChromeStatus interop notes (5120203192139776).

Lifecycle and state transitions

  • Before connection establishment ([[State]] === "connecting"): calling wt.getStats() before await wt.ready does not throw; the returned promise waits until the connection transitions out of "connecting", then resolves with stats if it connects or rejects with InvalidStateError if the handshake fails.
  • While connected ([[State]] === "connected"): queries the network service asynchronously and updates Chromium’s cached latest_stats_ snapshot. Per W3C §6.13, whether a UA chooses to expose a member is fixed once per session (except estimatedSendRate, which can transition to or from null, and RTT fields before the first sample).
  • During and after normal closure ([[State]] === "closed"): calls issued immediately before wt.close() or after wt.close() resolve with the most recent cached stats snapshot (including updated incoming datagram drop/expiry counters flushed during cleanup).
  • Failed connection ([[State]] === "failed"): rejects with DOMException("InvalidStateError") on both initial and repeated getStats() calls.
Source: W3C WebTransport — getStats() steps; Blink WebTransport::getStats / Cleanup; WPT stats.https.any.js.

Errors and defensive handling

  • InvalidStateError (DOMException, code 11): wt.getStats() returns a rejected promise if the WebTransport connection is in the "failed" state (for example DNS/TLS/HTTP3 handshake failure or abrupt transport failure with no prior snapshot).
  • Missing optional members: smoothedRtt, rttVariation, and minRtt are absent until QUIC records a positive RTT sample; estimatedSendRate is null when no bandwidth estimate exists; non-pooled byte/packet counters and WebTransportDatagramStats fields may be omitted on pooled connections or in other engines. Always guard with "smoothedRtt" in stats, stats.estimatedSendRate !== null, and stats.datagrams?.lostOutgoing ?? 0.
  • Pre-160 Chrome / older Firefox: feature-detect typeof wt.getStats === "function" and catch rejections (Firefox 114–157 exposed getStats as a stub that rejected with a not-implemented error before Firefox 158 implemented it).
Source: W3C WebTransport — getStats(); WPT stats.https.any.js; BCD api/WebTransport.json.

Context and exposure

WebTransport.getStats(), WebTransportConnectionStats, and WebTransportDatagramStats are exposed in Window and Worker contexts (dedicated, shared, and service workers) and require a SecureContext (HTTPS or localhost). No user permission or user activation is required.

Source: Blink web_transport.idl; WPT stats.https.any.js (global=window,worker).

Examples

Polling RTT and estimated send rate safely across engines

async function inspectConnectionHealth(wt) {
  if (typeof wt.getStats !== "function") {
    return { supported: false };
  }

  try {
    const stats = await wt.getStats();
    return {
      supported: true,
      smoothedRttMs: "smoothedRtt" in stats ? stats.smoothedRtt : null,
      rttVariationMs: "rttVariation" in stats ? stats.rttVariation : null,
      minRttMs: "minRtt" in stats ? stats.minRtt : null,
      estimatedSendRateBps: stats.estimatedSendRate ?? null,
      // Optional in W3C spec; absent in Chrome 160
      bytesSent: "bytesSent" in stats ? stats.bytesSent : null,
    };
  } catch (err) {
    if (err.name === "InvalidStateError") {
      // Connection failed before establishing
      return { supported: true, failed: true };
    }
    throw err;
  }
}
Source: W3C WebTransport §6.13; WPT stats.https.any.js.

Monitoring WebTransportDatagramStats and post-close telemetry

const wt = new WebTransport("https://example.com:4433/wt", {
  congestionControl: "low-latency",
});
await wt.ready;

// Read final connection and datagram counters even after closing
wt.close({ closeCode: 0, reason: "session complete" });
const finalStats = await wt.getStats();

const {
  droppedIncoming = 0,
  expiredIncoming = 0,
  expiredOutgoing = 0,
  lostOutgoing = 0,
} = finalStats.datagrams;

console.log({
  droppedIncoming,
  expiredIncoming,
  expiredOutgoing,
  lostOutgoing,
});
Source: W3C WebTransport §6.14; WPT stats.https.any.js.

Security and privacy

WebTransport.getStats() returns only aggregate transport statistics for a WebTransport session the caller already owns; it reveals neither payloads nor peer credentials and creates no new network capability. However, RTT metrics and estimatedSendRate can reveal characteristics of a user’s network path or correlate concurrent activity.

Connection pooling boundary. Under W3C WebTransport §6.13, when a session shares a pooled underlying HTTP/3 connection (allowPooling: true, [[NewConnection]] === "no"), non-pooled connection and datagram counters MUST be withheld so one session cannot observe another pooled session’s traffic volume; only pooled connection stats (smoothedRtt, rttVariation, minRtt, estimatedSendRate) may be disclosed across pooled sessions sharing the same network partition key. User agents may also withhold additional members for privacy as long as that choice remains consistent across calls within a session.

Source: W3C WebTransport §6.13; ChromeStatus security_risks (5120203192139776).
