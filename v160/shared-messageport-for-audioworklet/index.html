Shared MessagePort for AudioWorklet

Chrome 160 exposes a shared, read-only MessagePort as AudioWorklet.prototype.port on the main thread and AudioWorkletGlobalScope.prototype.port inside the audio rendering thread. Applications can exchange global configuration, WebAssembly modules, or control messages directly with the worklet global scope without creating a dummy bootstrap AudioWorkletNode and AudioWorkletProcessor.

Limited availability — not Baseline

  • Chrome · 160 (desktop, Android, WebView)
  • Edge · Chromium-based (mirrors Chrome)
  • Firefox · 138 (shipped)
  • Safari · No (WebKit standards-positions#739)

The parent audio-worklet web-feature is Baseline Widely available (since 2023-10-26 per webstatus.dev), but the shared port properties are Limited availability (unsupported in Safari). Note that BCD api/AudioWorklet.json currently lists Chrome as preview while BCD api/AudioWorkletGlobalScope.json still reads false (checked 2026-11-24).

Chrome 160 details, WebIDL & lifecycle notes

In Web Audio API 1.1 (added by WebAudio/web-audio-api#2507 for issue #2456), both ends expose an entangled MessagePort gated in Chromium behind [RuntimeEnabled=AudioWorkletSharedPort] (now status: "stable"):

// Main thread (Window, SecureContext):
// context.audioWorklet.port exists BEFORE addModule() resolves.
const context = new AudioContext();
if ("port" in context.audioWorklet) {
  context.audioWorklet.port.addEventListener("message", (event) => {
    console.log("From AudioWorkletGlobalScope:", event.data);
  });
  context.audioWorklet.port.start(); // required when using addEventListener()
  await context.audioWorklet.addModule("worklet.js");
  context.audioWorklet.port.postMessage({ type: "init", gain: 0.5 });
}

// Inside worklet.js (AudioWorkletGlobalScope):
// `port` is already available during top-level module evaluation!
port.postMessage({ type: "module-evaluation" });
port.onmessage = (event) => {
  if (event.data?.type === "init") {
    // Store global state shared across processors without a dummy processor.
  }
};
  • Available before addModule() and during module evaluation: As verified by WPT audioworklet-messageport.https.html, context.audioWorklet.port is an instance of MessagePort immediately on context creation (before addModule() is called), and globalThis.port inside the worklet can call postMessage() during top-level module evaluation.
  • Resource collection note: Both AudioWorklet.port and AudioWorkletGlobalScope.port carry a normative note warning authors that if they register a "message" listener on this port, they should call port.close() on either end when done so the entangled MessageChannel and scope resources can be garbage-collected.
  • Ecosystem driver: Removes bootstrap-processor workarounds required by Emscripten audio worklets (see emscripten-core/emscripten#25354).
Source: Web Audio API 1.1 §1.32.1 AudioWorklet.port; §1.32.3.1 AudioWorkletGlobalScope.port; WPT audioworklet-messageport.https.html; ChromeStatus 5079784523694080.
