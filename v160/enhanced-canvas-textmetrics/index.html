Enhanced Canvas TextMetrics

Adds first-class Canvas 2D text shaping, selection geometry, caret hit-testing, and per-run/per-cluster glyph rendering via shapeText(), ShapedText, GlyphRun, and fillGlyphRun(s) / strokeGlyphRun(s) on both CanvasRenderingContext2D and OffscreenCanvasRenderingContext2D. Although the feature retains its historical “Enhanced Canvas TextMetrics” name from the Chrome 144–149 Origin Trial, Chrome 160 ships the redesigned shaping architecture aligned with WebKit’s CanvasTextShaping model, leaving TextMetrics itself unchanged and exposing per-run metrics via GlyphRun.textMetrics().

Limited availability — Canvas 2D text shaping is not Baseline (shipping in Chrome 160)

  • Chrome · 160 (desktop, Android, WebView)
  • Edge · Mirrors Chromium (160)
  • Firefox · No signal yet
  • Safari · Neutral (aligned with WebKit CanvasTextShaping sketch; no release)

No dedicated web-features entry exists on webstatus.dev for ShapedText or GlyphRun (checked 2026-11-24; parent canvas-2d is Baseline Widely available). BCD api/CanvasRenderingContext2D.json and BCD api/TextMetrics.json do not yet include shapeText(), ShapedText, or GlyphRun.

why it exists

ctx.measureText() only returns aggregate metrics for an entire string. Canvas-rendered editors, design tools, and frameworks (such as Flutter Web’s WebParagraph) previously had to approximate caret positions, selection highlight rectangles, and per-character animations by calling measureText() on substrings — which breaks ligatures, kerning, complex shaping, and bidirectional runs — or by synchronizing hidden DOM elements. Separating shaping into ctx.shapeText(text) creates an immutable ShapedText snapshot whose runs, grapheme clusters, bounding boxes, selection rectangles, and caret offsets can be queried accurately and rendered individually via fillGlyphRun(s) and strokeGlyphRun(s).

Design evolution note: Early Origin Trial builds (Chrome 144–149) added getSelectionRects(), getTextClusters(), and fillTextCluster() directly on TextMetrics/TextCluster. Following Origin Trial feedback and WebKit’s CanvasTextShaping explainer, Chromium redesigned the shipped Chrome 160 surface around shapeText(), ShapedText, and GlyphRun so TextMetrics remains untouched and future multi-style FormattedText overloads can layer cleanly on top. Legacy TextCluster declarations still present under Blink’s ExtendedTextMetrics flag during cleanup are not part of the Chrome 160 shipping contract.

Source: ChromeStatus motivation & interop notes (5075532483657728); WebKit/explainers#137; whatwg/html#10677.

Syntax

The Chrome 160 shaping surface adds five methods to the 2D rendering context (shared by CanvasRenderingContext2D and OffscreenCanvasRenderingContext2D) and introduces two new interfaces, ShapedText and GlyphRun:

partial interface mixin CanvasText {
  ShapedText shapeText(DOMString text);
  undefined fillGlyphRun(GlyphRun glyphRun, double x, double y);
  undefined strokeGlyphRun(GlyphRun glyphRun, double x, double y);
  undefined fillGlyphRuns(sequence<GlyphRun> glyphRuns, double x, double y);
  undefined strokeGlyphRuns(sequence<GlyphRun> glyphRuns, double x, double y);
};

[Exposed=(Window,Worker)]
interface ShapedText {
  readonly attribute double width;

  sequence<GlyphRun> glyphRuns();
  sequence<GlyphRun> glyphClusters();
  sequence<GlyphRun> glyphClusters([EnforceRange] unsigned long start, [EnforceRange] unsigned long end);

  sequence<DOMRectReadOnly> selectionRects([EnforceRange] unsigned long start, [EnforceRange] unsigned long end);
  DOMRectReadOnly actualBoundingBox([EnforceRange] unsigned long start, [EnforceRange] unsigned long end);
  unsigned long advanceToPosition(double advance);
  double positionToAdvance([EnforceRange] unsigned long position);
};

[Exposed=(Window,Worker)]
interface GlyphRun {
  readonly attribute unsigned long start;
  readonly attribute unsigned long end;
  readonly attribute double x;
  readonly attribute double y;
  readonly attribute double width;

  TextMetrics textMetrics();
};

All character offsets and ranges (start, end, position, and advanceToPosition() results) are 0-based UTF-16 code units, matching JavaScript String indexing, DOM Range/Selection, and Intl.Segmenter. Detailed contracts follow for shapeText(), ShapedText width, glyphRuns(), and glyphClusters(), selectionRects(), actualBoundingBox(), advanceToPosition(), and positionToAdvance(), GlyphRun, and fillGlyphRun(s) / strokeGlyphRun(s).

Source: Blink base_rendering_context_2d.idl; Blink shaped_text.idl; Blink glyph_run.idl.

ctx.shapeText(text)

Inputs. Accepts a single DOMString text (coerced per standard WebIDL string conversion). No optional arguments or max-width parameter are defined in Chrome 160.

Outputs. Resolves the canvas element’s style/layout tree (when attached to a document with a frame), snapshots the context’s current font, resolved writing direction (ltr or rtl), textAlign, and textBaseline, shapes the string into visual runs via Blink’s PlainTextPainter, and returns a new immutable ShapedText object. If called on an HTMLCanvasElement belonging to a frame-less document (for example created via document.implementation.createHTMLDocument()), Blink returns an empty ShapedText whose width is 0 and whose glyphRuns() / glyphClusters() are empty arrays.

Source: Blink base_rendering_context_2d.cc (BaseRenderingContext2D::shapeText); Blink shaped_text.cc.

ShapedText.width, glyphRuns(), and glyphClusters()

Inputs.

  • st.width: read-only double attribute representing the total advance width of the shaped string.
  • st.glyphRuns(): takes no parameters.
  • st.glyphClusters(): takes either no arguments (full string) or two [EnforceRange] unsigned long UTF-16 code unit indices (start, end) representing the half-open slice [start, end).

Outputs.

  • glyphRuns() returns a sequence<GlyphRun> in visual left-to-right order. Adjacent clusters sharing the same resolved font and bidi direction are merged into a single GlyphRun; mixed-script font fallbacks (such as emoji or Hebrew/Arabic mixed with Latin) or bidi level changes split into separate runs.
  • glyphClusters() returns minimal renderable grapheme clusters as GlyphRun instances so callers can style, transform, or animate individual characters/ligatures while preserving shaping context. Calling glyphClusters() with no arguments on an empty string returns []; passing (start, end) returns every cluster whose [cluster.start, cluster.end) range intersects [start, end).
  • Each returned GlyphRun has x already shifted by the snapshotted textAlign offset (for example, negative x when textAlign is "center" or "right") and y set to 0 relative to the draw origin.
Source: Blink shaped_text.cc (glyphRuns, glyphClusters); WPT 2d.text.shape.glyph-clusters-position.tentative.html; WPT 2d.text.shape.fillGlyphRuns-and-strokeGlyphRuns.tentative.html.

GlyphRun interface

Inputs & construction. GlyphRun has no public constructor; instances are produced exclusively by ShapedText.glyphRuns() and ShapedText.glyphClusters() and retain an internal reference to their originating ShapedText and resolved font face.

Outputs & members.

  • start / end (readonly unsigned long): inclusive start and exclusive end UTF-16 code unit indices into the original string passed to shapeText().
  • x / y (readonly double): shaped position offset of this run relative to the anchor point passed to fillGlyphRun() / strokeGlyphRun() (incorporating the snapshotted textAlign).
  • width (readonly double): advance width of this run/cluster.
  • textMetrics(): returns a TextMetrics object describing the exact ascent, descent, bounding box, and advance metrics for this GlyphRun’s slice and resolved font. Blink lazily constructs and caches the TextMetrics instance on first call.
Source: Blink glyph_run.idl; Blink glyph_run.cc; WPT 2d.text.shape.glyph-clusters-position.tentative.html.

fillGlyphRun(), strokeGlyphRun(), fillGlyphRuns(), and strokeGlyphRuns()

Inputs. Each method takes either a single GlyphRun (fillGlyphRun / strokeGlyphRun) or a sequence<GlyphRun> (fillGlyphRuns / strokeGlyphRuns) followed by destination anchor coordinates double x and double y.

Outputs & style precedence. Each run renders at (glyphRun.x + x, glyphRun.y + y) using the font, direction, textAlign, and textBaseline snapshotted when shapeText() ran — mutating those four properties on the context afterwards does not shift or re-shape previously created GlyphRuns. By contrast, active paint and compositing state (fillStyle, strokeStyle, lineWidth, shadow*, globalAlpha, transforms, and clipping regions) is applied at draw time, enabling per-cluster color gradients, transforms, and animations. fillGlyphRuns(runs, x, y) and strokeGlyphRuns(runs, x, y) iterate through runs in order and draw each run at the shared anchor (x, y).

Source: Blink base_rendering_context_2d.cc (lines 2132–2195); WPT 2d.text.shape.fillGlyphRun-range.tentative.html; WPT 2d.text.shape.fillGlyphRuns-and-strokeGlyphRuns.tentative.html.

Context, exposure, and lifecycle

Exposure & prerequisites. ShapedText, GlyphRun, shapeText(), fillGlyphRun(), strokeGlyphRun(), fillGlyphRuns(), and strokeGlyphRuns() are exposed in both Window and Worker (via OffscreenCanvasRenderingContext2D). No secure context, permission, or user activation is required. When using web fonts loaded via @font-face / FontFaceSet, await document.fonts.ready before calling shapeText() so shaping runs against the loaded typeface rather than a fallback font.

Lifecycle & immutability. A ShapedText instance is an immutable snapshot of the string and the context’s font, direction, textAlign, and textBaseline at the time shapeText() was called. GlyphRun objects retain a GC-traced reference to their parent ShapedText and resolved font data, and cache their textMetrics() result on first access. Re-shape whenever the string, font size/family, alignment, baseline, or writing direction changes; reuse the same ShapedText and GlyphRun arrays across animation frames when only colors, shadows, or transforms change.

Source: Blink shaped_text.idl; Blink glyph_run.cc; WPT offscreen 2d.text.shape.*.

Examples

No Chrome Platform Showcase demo exists yet for Chrome 160 enhanced-canvas-textmetrics (checked 2026-11-24).

Selection highlights, tight ink bounds, and pointer hit-testing with shapeText()

if ("shapeText" in CanvasRenderingContext2D.prototype) {
  const ctx = canvas.getContext("2d");
  ctx.font = "28px system-ui, sans-serif";
  ctx.textAlign = "left";
  ctx.textBaseline = "alphabetic";

  const originX = 24;
  const originY = 72;
  const text = "Hello 👋 עולם";
  const shaped = ctx.shapeText(text);

  // 1. Draw selection highlight rectangles for UTF-16 range [0, 8)
  ctx.fillStyle = "rgba(11, 87, 208, 0.25)";
  for (const rect of shaped.selectionRects(0, 8)) {
    ctx.fillRect(originX + rect.x, originY + rect.y, rect.width, rect.height);
  }

  // 2. Outline tight ink bounding box for the full shaped text
  const ink = shaped.actualBoundingBox(0, text.length);
  ctx.strokeStyle = "#b3261e";
  ctx.strokeRect(originX + ink.x, originY + ink.y, ink.width, ink.height);

  // 3. Render shaped text runs
  ctx.fillStyle = "#111";
  ctx.fillGlyphRuns(shaped.glyphRuns(), originX, originY);

  // 4. Convert a pointer X coordinate to a UTF-16 caret index and back
  canvas.addEventListener("pointerdown", (e) => {
    const localX = e.offsetX - originX;
    const caretIndex = shaped.advanceToPosition(localX);
    const caretAdvance = shaped.positionToAdvance(caretIndex);
    console.log({ caretIndex, caretAdvance, totalWidth: shaped.width });
  });
}
Source: WPT 2d.text.shape.position-to-advance.tentative.html; WPT 2d.text.shape.fillGlyphRuns-and-strokeGlyphRuns.tentative.html.

Per-cluster styling, animation, and GlyphRun.textMetrics() inspection

const ctx = canvas.getContext("2d");
ctx.font = "600 40px Georgia, serif";
ctx.textAlign = "center";
ctx.textBaseline = "middle";

const shaped = ctx.shapeText("Wave");
const clusters = shaped.glyphClusters(); // sequence<GlyphRun>

// Mutating ctx.font / ctx.textAlign after shapeText() does NOT alter these GlyphRuns.
const palette = ["#0b57d0", "#b3261e", "#146c2e", "#8f4e00"];

clusters.forEach((run, i) => {
  const metrics = run.textMetrics();
  const dy = Math.sin(i * 0.9) * 10;

  // Draw each cluster with its own fillStyle and strokeStyle while preserving kerning.
  ctx.fillStyle = palette[i % palette.length];
  ctx.strokeStyle = "#111";
  ctx.lineWidth = 1.5;
  ctx.fillGlyphRun(run, canvas.width / 2, canvas.height / 2 + dy);
  ctx.strokeGlyphRun(run, canvas.width / 2, canvas.height / 2 + dy);

  console.log({
    range: [run.start, run.end],
    pos: [run.x, run.y],
    width: run.width,
    ascent: metrics.actualBoundingBoxAscent,
  });
});

// Batch-draw a subset of clusters via strokeGlyphRuns()
ctx.strokeGlyphRuns(shaped.glyphClusters(1, 3), canvas.width / 2, canvas.height / 2 + 48);
Source: WPT 2d.text.shape.glyph-clusters-position.tentative.html; WPT 2d.text.shape.fillGlyphRun-range.tentative.html.

Security and privacy

Canvas 2D font metrics and rendered glyphs are already a well-known browser fingerprinting surface because installed system fonts and shaping engines vary across devices. ChromeStatus notes that shapeText(), ShapedText, GlyphRun, and fillGlyphRun(s) / strokeGlyphRun(s) expose finer-grained geometry of text already measurable via measureText() and drawable via fillText(), introducing no novel cross-origin leak, permission boundary change, or storage channel. Security and privacy reviews are listed as Pending in the ChromeStatus API record (checked 2026-11-24).

Source: ChromeStatus security_risks (5075532483657728); HTML Living Standard — Security with canvas elements.
